# Núcleo común de estudio

[←](README.md) · [Laboratorios avanzados](17-advanced-labs.md)

Mismos conceptos, casos y evidencias en ocho idiomas. Estudia estas doce unidades, desarrolla las veinte de certificación y comprueba los resultados de las prácticas. Las notas anteriores se conservan como ampliación; su extensión histórica varía.

<a id="core-cloud"></a>

## 1. Responsabilidad y escalado

Para una API, reparte OS, dependencias, datos y acceso entre proveedor y equipo. Añadir instancias no corrige estado local. Entrega una matriz y una prueba con peticiones a dos instancias.

<a id="core-resources"></a>

## 2. Ámbitos y ciclo de vida

Separa tenant, gestión, suscripción y grupo de recursos. Decide qué se elimina junto y qué red se comparte. Entrega un diagrama con propietarios y comprueba dependencias antes de mover o borrar.

<a id="core-compute"></a>

## 3. Ejecución y salud

Compara VM, PaaS, funciones y contenedores por control, duración y operación. Una app iniciada puede no escuchar donde se espera. Entrega una elección, una alternativa y comprobación de puerto, arranque y dependencia.

<a id="core-data"></a>

## 4. Datos y restauración

Distingue objetos, archivos y transacciones; JSON no impone un motor. Replica, versión y copia cubren riesgos distintos. Entrega mapa de documentos y metadatos y prueba coherencia después de recuperar.

<a id="core-network"></a>

## 5. Ruta y resolución

Sigue DNS, IP, ruta, filtros, listener y autenticación sin mezclarlos. El peering no es transitivo automáticamente. Entrega una tabla de saltos y explica por qué un endpoint privado aún puede fallar desde la universidad.

<a id="core-identity"></a>

## 6. Identidad y permisos

Diferencia autenticación, autorización, roles de directorio y roles Azure. Examina herencia y grupos antes de conceder más. Entrega la acción necesaria para estudiante, API y proceso, con ámbito mínimo y prueba del acceso.

<a id="core-governance"></a>

## 7. Reglas y excepciones

Distingue auditar, denegar y remediar. Describe identidad y permisos de remediación, recursos existentes y excepciones con revisión. Entrega una política piloto, impacto previsto y criterio para pasar de audit a deny.

<a id="core-monitor"></a>

## 8. Señales y evidencia

Selecciona éxito funcional, latencia y antigüedad de trabajo. Verifica recogida y destino antes de consultar. Entrega una alerta con ventana, volumen, umbral, responsable y acción; explica cómo una media puede ocultar un problema.

<a id="core-cost"></a>

## 9. Unidades y supuestos de coste

Compara bajo, esperado y alto consumo con horas, operaciones, transferencia y retención. Incluye capacidad ociosa y costes residuales. Entrega supuestos y sensibilidad; no una cifra fija ni presupuesto presentado como límite automático.

<a id="core-recovery"></a>

## 10. Recuperación completa

Define RTO/RPO por datos y servicio. Incluye identidad, DNS, permisos y configuración, no solo copias. Entrega orden de restauración, prueba aislada, validación funcional y retorno; distingue réplica, backup y recuperación de integraciones.

<a id="core-messaging"></a>

## 11. Mensajes y duplicados

Elige cola, eventos o ingesta de flujo según necesidad. Explica confirmación perdida, repetición, orden y mensajes fallidos. Entrega identificador estable, operación idempotente y estrategia de replay sin suponer entrega exactamente una vez.

<a id="core-delivery"></a>

## 12. Entrega y confianza

Promueve un artefacto probado e identificado. Separa código confiable, permisos y datos del PR. Entrega pruebas significativas, autorización, señal de promoción y rollback; demuestra por qué volver al código no siempre revierte datos.
