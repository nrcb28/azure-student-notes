# メッセージとイベント

[目次](README.md) · [認定試験](../certifications/ja/README.md)

キューは送信と処理を切り離します。Storage Queues は単純な仕事、Service Bus はキューとトピック、Event Grid はイベント配信、Event Hubs は大規模なイベントストリームに対応します。自動的に置き換え可能ではありません。

処理後に確認応答が失われると、同じメッセージが再び来ることがあります。安定した ID と整合的な更新で重複の影響を防ぎます。

**例：**サムネイル作成前に結果を確認し、生成と保存の後に完了を通知します。同時実行と原子的な操作も考えます。

件数だけでなく最古のメッセージの経過時間を監視します。DB が詰まっているなら、消費側を増やすだけでは解決しません。順序や失敗処理はサービスの条件を確認します。
