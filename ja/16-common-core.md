# 共通学習コア

[←](README.md) · [発展演習](17-advanced-labs.md)

八言語で同じ概念、ケース、証拠を学びます。基本十二単位、認定二十単位と演習に取り組みます。以前のノートは補足として残し、従来の長さには差があります。

<a id="core-cloud"></a>

## 1. 責任とスケール

API の OS、依存、データ、アクセスを提供者とチームに割り当てます。台数追加ではローカル状態は直りません。責任表と二インスタンスへの要求試験を提出します。

<a id="core-resources"></a>

## 2. 範囲とライフサイクル

テナント、管理、サブスクリプション、グループを区別し、何を一緒に消し、どのネットを共有するか決めます。担当図を作り、移動と削除前に依存を確認します。

<a id="core-compute"></a>

## 3. 実行と健全性

VM、PaaS、関数、コンテナーを制御、期間、運用で比較します。起動しただけでは正しいポートとは限りません。選択、代案、ポート・起動・依存の検査を提出します。

<a id="core-data"></a>

## 4. データと復元

オブジェクト、ファイル、取引を分け、JSON だけでエンジンを決めません。複製、版、コピーのリスク範囲は違います。文書とメタデータを対応させ復元後の整合性を確認します。

<a id="core-network"></a>

## 5. 経路と名前

DNS、IP、経路、フィルター、待受、認証を別に追います。Peering は自動推移しません。経路表と、大学から私設 endpoint に届かない理由を提出します。

<a id="core-identity"></a>

## 6. ID と権限

認証、認可、ディレクトリと Azure のロールを分けます。追加前に継承とグループを調べ、学生、API、処理の操作、最小範囲、検証を示します。

<a id="core-governance"></a>

## 7. 規則と例外

監査、拒否、修復を分け、修復 ID、権限、既存資源、見直す例外を説明します。試行方針、影響、audit から deny へ進む条件を提出します。

<a id="core-monitor"></a>

## 8. 信号と証拠

機能成功、遅延、処理の経過時間を選び、query 前に収集と出力を確認します。期間、件数、閾値、担当、対処を持つ警告と、平均の限界を説明します。

<a id="core-cost"></a>

## 9. 費用単位と仮定

低・通常・高利用を時間、操作、転送、保持で比較し、空き能力と残存費用も含めます。固定価格や予算自動停止ではなく、仮定と変動への影響を示します。

<a id="core-recovery"></a>

## 10. 全体復旧

データとサービスごとに RTO/RPO を定義し、ID、DNS、権限、設定を含めます。順番、隔離試験、機能確認、戻し方を示し、複製、コピー、統合復旧を分けます。

<a id="core-messaging"></a>

## 11. メッセージと重複

要件で queue、event、stream を選び、確認消失、反復、順序、失敗を説明します。安定 ID、冪等操作、再処理を示し、無条件の一回配送を仮定しません。

<a id="core-delivery"></a>

## 12. 公開と信頼

試験済みで識別できる成果物を昇格し、信頼コード、権限、PR 入力を分けます。試験、認可、昇格信号、rollback を示し、コードでデータが戻らない場合を説明します。
