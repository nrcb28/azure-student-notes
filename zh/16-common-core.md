# 共同学习核心

[←](README.md) · [进阶实验](17-advanced-labs.md)

八语版本具有相同概念、案例和证据。完成十二基础单元、二十认证单元并验证实验。旧笔记作为补充保留，历史篇幅仍有差异。

<a id="core-cloud"></a>

## 1. 责任与扩展

为 API 分配提供商与团队的操作系统、依赖、数据和访问责任。增加实例不能修复本地状态。提交责任矩阵及请求经过两个实例的测试。

<a id="core-resources"></a>

## 2. 作用域与生命周期

区分租户、管理、订阅和资源组。决定共同删除项及共享网络，提交负责人图，并在移动或删除前检查依赖。

<a id="core-compute"></a>

## 3. 执行与健康

按控制、时长和运维比较 VM、PaaS、函数及容器。启动成功可能仍监听错误端口。提交选择、备选和端口、启动、依赖检查。

<a id="core-data"></a>

## 4. 数据与恢复

区分对象、文件和事务，JSON 不决定引擎。副本、版本和备份覆盖不同风险。关联文档和元数据，恢复后检查一致性。

<a id="core-network"></a>

## 5. 路由与解析

分别跟踪 DNS、IP、路由、过滤、监听和验证。对等互连不自动传递。提交路径表，解释大学客户端仍无法访问私有 endpoint 的原因。

<a id="core-identity"></a>

## 6. 身份与权限

区分验证、授权、目录角色和 Azure 角色。加权前检查继承与组，定义学生、API、处理器的操作、最小范围及访问验证。

<a id="core-governance"></a>

## 7. 规则与例外

区分审计、拒绝和修正。说明修正身份、权限、现有资源和复查例外。提交试点策略、预期影响及从 audit 转为 deny 的条件。

<a id="core-monitor"></a>

## 8. 信号与证据

选择功能成功、延迟和任务年龄，查询前确认采集和目标。提交包含窗口、量、阈值、负责人和动作的告警，解释平均值可能隐藏的问题。

<a id="core-cost"></a>

## 9. 成本单位与假设

按小时、操作、传输和保留比较低、预期、高使用量，包含闲置容量和残余费用。提交假设及敏感性，不将固定价格或预算当成自动费用上限。

<a id="core-recovery"></a>

## 10. 完整恢复

按数据与服务定义 RTO/RPO，包含身份、DNS、权限和配置。提交恢复顺序、隔离测试、功能验证与返回方案，区分副本、备份和集成恢复。

<a id="core-messaging"></a>

## 11. 消息与重复

按需求选队列、事件或流，解释确认丢失、重复、顺序和失败。提交稳定标识、幂等操作和重放策略，不假设恰好一次交付。

<a id="core-delivery"></a>

## 12. 交付与信任

推广已测试且可识别制品，分开可信代码、权限和 PR 数据。提交有效测试、授权、晋级信号及回滚，说明代码回滚为何不总能恢复数据。
