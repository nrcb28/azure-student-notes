# SC-300 · Identity and Access Administrator

[Certifications](README.md) · [Ten cases](SC-300-cases.md) · [Workbook](SC-300-workbook.md)

SC-300 studies how Microsoft Entra identities receive, use, and lose access. For our university notes app, I start with a concrete request: which student, guest, administrator, or background worker needs which operation, and for how long?

Reference checked **2026-11-01**: [official study guide](https://learn.microsoft.com/en-us/credentials/certifications/resources/study-guides/sc-300), objectives effective **2026-10-28**. Credential: [Identity and Access Administrator Associate](https://learn.microsoft.com/en-us/credentials/certifications/identity-and-access-administrator/).

The guide lists user identities, workload identities, and identity governance at **20–25% each**. There is a source discrepancy for authentication and access management: its summary says **25–30%**, but its detailed heading says **20–25%**. These notes preserve that discrepancy; check the current official guide rather than assuming a corrected weight. Localised exam updates can follow a different schedule.

These are original study notes and hypothetical exercises, not official questions, complete objective coverage, or evidence of tenant execution.

## 1. Establish the tenant and permission boundary

A tenant is an identity boundary; an Azure subscription is a resource-management boundary. Entra directory roles manage directory capabilities, while Azure RBAC roles apply to Azure resources at a specified scope. Neither automatically makes someone a course editor inside our application.

Evaluate effective access through direct assignments, groups, inherited resource assignments, active privileged assignments, and application roles. Removing one path can leave another. Administrative units can scope supported directory administration to selected objects; they do not isolate all data belonging to a department. Record group type, membership source, owner, and who can change membership. Compare the boundaries with the [identity notes](../../en/06-identity.md).

## 2. Separate collaboration from hybrid synchronisation

A visiting lecturer can use a guest identity without becoming an unrestricted university member. Cross-tenant settings distinguish inbound access, outbound access, and whether specified MFA or device claims from another organisation are trusted. Trusting a claim does not assign permission to a document. Check the home tenant, resource tenant, targeted application, invitation restrictions, and guest lifecycle. [Cross-tenant access](https://learn.microsoft.com/en-us/entra/external-id/cross-tenant-access-overview).

Hybrid identity concerns connecting on-premises identity infrastructure with Entra. Connect Sync and Cloud Sync require a deliberate source-of-authority and supported-feature choice. Password hash synchronisation, pass-through authentication, and federation concern authentication architecture; synchronising an account does not itself establish appropriate access. Plan matching, deletion handling, dependencies, and health monitoring before proposing migration.

## 3. Plan registration, strong authentication, and recovery

MFA methods provide different protections. For sensitive administration, assess phishing-resistant options such as supported passkeys, Windows Hello for Business, or certificate-based authentication, together with device and deployment constraints. Registration alone does not prove a policy requires the method. SSPR also needs suitable registration and recovery design.

A Temporary Access Pass is a time-limited bootstrap or recovery credential for registering other methods. Its permitted users, lifetime, usage settings, identity verification, and secure delivery matter. Our notebook records a proposed process, never a real passcode or password export. Recovery must remain usable when the normal method is lost. [Authentication overview](https://learn.microsoft.com/en-us/entra/identity/authentication/overview-authentication) · [Temporary Access Pass](https://learn.microsoft.com/en-us/entra/identity/authentication/howto-authentication-temporary-access-pass).

## 4. Describe Conditional Access as a scoped decision

Write the targeted identities, resources, conditions, grant controls, session controls, and exclusions before saying “require MFA”. A rule for editors accessing the notes API does not establish protection for every university application. Multiple applicable policies must be considered together, and application authorisation still decides which note the editor may change.

For an offline rollout plan, specify a pilot, expected allowed and denied requests, report-only analysis, administrator recovery, and rollback ownership. Report-only policies record evaluation without enforcing their controls. Exclusions need explicit reasons and review; a large exclusion group can defeat the design. Check applicable licensing and dependencies. [Conditional Access overview](https://learn.microsoft.com/en-us/entra/identity/conditional-access/overview).

## 5. Distinguish user risk from sign-in risk

User risk concerns the likelihood that an identity is compromised; sign-in risk concerns a particular authentication request. A suspicious sign-in and a long-standing compromised account therefore need related but distinct investigation. Neither score answers whether a lecturer still needs access to last semester's course.

Record detections, timestamps, affected identities, authentication details, and the investigator's conclusion. A risk-based policy can require an appropriate remediation, subject to its configuration and prerequisites. Do not dismiss a signal merely to clear a dashboard, or assume every unusual location proves compromise. Workload-risk capabilities have separate scope and licensing considerations. [ID Protection](https://learn.microsoft.com/en-us/entra/id-protection/overview-identity-protection).

## 6. Identify the application object and its permissions

An app registration defines application identity configuration in its home tenant. A service principal represents its local use in a tenant; Enterprise applications exposes that local management context. Managed identities also have service principals, with credentials managed by the platform. They still need deliberately scoped permissions.

Delegated permissions act on behalf of a signed-in user, with access constrained by the relevant permission model. Application permissions let a workload act without that user context and require administrator consent. Review API, permission type, consent grant, owner, and business purpose. Adding a requested permission and granting consent are separate steps. A background indexer should not inherit a human administrator's account. [Application objects and service principals](https://learn.microsoft.com/en-us/entra/identity-platform/app-objects-and-service-principals).

## 7. Keep federation, provisioning, and authorisation distinct

Workload identity federation can exchange an external provider's token for an Entra token without maintaining a stored client secret. The configured issuer, subject, and audience must match the incoming assertion, including case. Token acceptance authenticates the workload; the resulting identity still needs minimum resource permissions. Review a fictional build environment's claims without copying live tokens into notes. [Federation concepts](https://learn.microsoft.com/en-us/entra/workload-id/workload-identity-federation).

For a connected learning platform, SAML or OpenID Connect SSO concerns sign-in. SCIM provisioning concerns creating, updating, or removing accounts and attributes. Successful SSO does not prove deprovisioning works. Document mappings, assignment scope, provisioning failures, and what happens when an entitlement expires.

## 8. Govern privilege and ordinary entitlements

PIM eligibility allows activation under configured conditions; an active assignment makes privilege available. Eligible and active assignments can be time bound. Check role, scope, approval, authentication, and duration: a brief excessively broad role remains excessive.

Access reviews ask whether existing access remains justified. Entitlement management packages resources with request, approval, expiration, and review policies. Lifecycle workflows automate supported joiner, mover, and leaver tasks using defined triggers. These mechanisms complement each other; a completed review does not activate an administrator. Record resource owners, failed automation handling, and evidence that approved removals take effect. Check the specific feature's licence and beneficiary requirements rather than assuming one subscription unlocks every governance capability. [Identity Governance](https://learn.microsoft.com/en-us/entra/id-governance/identity-governance-overview).

## 9. Diagnose with the right evidence

Sign-in logs explain authentication attempts and policy evaluation; audit logs support investigation of directory changes; provisioning logs support account-lifecycle diagnosis. Routing through diagnostic settings, retention, access permissions, and ingestion determine what analysis is available. An empty result does not prove that no event occurred. [Monitoring and health](https://learn.microsoft.com/en-us/entra/identity/monitoring-health/overview-monitoring-health).

This hypothetical KQL sketch groups ingested sign-ins; it was not run:

```kusto
SigninLogs
| where TimeGenerated > ago(1d)
| summarize Attempts = count()
    by AppDisplayName, ConditionalAccessStatus, ResultType
```

Check table availability and schema before use. Aggregate status alone cannot explain every policy, especially report-only evaluation; inspect the relevant event details and correlation identifiers. Document missing telemetry and competing explanations.

## 10. Connect network access to the access lifecycle

Global Secure Access brings together Entra Private Access for private resources and Entra Internet Access for internet and SaaS traffic; the Microsoft traffic profile serves supported Microsoft services. Clients, connectors, traffic forwarding, policies, and licensing affect coverage. A private network path still needs identity and application permission checks. [Global Secure Access](https://learn.microsoft.com/en-us/entra/global-secure-access/overview-what-is-global-secure-access).
