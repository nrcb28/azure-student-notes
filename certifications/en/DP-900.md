## 1. Start with the question the data must answer

For our university notes app, a file download, an enrolment transaction, and a report of monthly activity are different workloads. I would write down the operation before choosing a product. Which records must change together? How old may a result be? Who can read the data? Keeping a PDF does not automatically require a database, and having JSON does not automatically rule one out.

## 2. Representation and workload are separate decisions

Structured data follows an explicit arrangement, such as an enrolment table with typed columns. Semi-structured data carries organisation without requiring every record to have identical fields: a JSON document can include optional metadata. A scanned worksheet is unstructured for the purposes of searching its contents, even if its filename follows a convention.

CSV is convenient for small tabular exchanges but needs an agreed encoding, delimiter, and treatment of missing values. JSON handles nested structures. Parquet is column-oriented and often suits analytical scans. A format alone does not provide permissions, business rules, or data quality.

Transactional work usually involves many focused operations: reserve a seat and update the remaining capacity consistently. Analytical work aggregates history: compare enrolment by course and term. A database can participate in both, but heavy reporting can compete with the live application. Decide acceptable freshness rather than demanding “real time” without a reason.

## 3. Relational design makes relationships explicit

Imagine Students, Courses, and Enrolments. A primary key identifies a row; a foreign key expresses a relationship when the database enforces that constraint. An Enrolments table connects students and courses without copying the course title into every student record. Normalisation reduces particular duplication and update anomalies; it is not a rule that every useful report must use the most fragmented possible schema.

A table stores rows. A view presents a saved query; it is not necessarily a separate stored copy. An index supports access paths and adds storage and write work. A stored procedure groups database-side operations. Transactions help keep related changes consistent under the database's concurrency and isolation behaviour. They do not fix a business rule that was never encoded.

Learn the purpose of SELECT, INSERT, UPDATE, DELETE, CREATE, and GRANT. Before any UPDATE or DELETE, predict the affected rows and test the condition on sample data. A successful statement can still change the wrong records.

## 4. Choose the Azure SQL operating model

Azure SQL Database is a managed database service. Azure SQL Managed Instance offers instance-oriented compatibility for many existing SQL Server applications. SQL Server on an Azure VM provides operating-system access and leaves more administration with the team. Similar query syntax does not make their deployment, compatibility, or maintenance responsibilities identical.

For a new notes app, I would compare required features, connections, recovery needs, operational effort, and workload shape. For a migration, inventory dependencies first: instance-level features and external components can change the choice. “Managed” does not remove responsibility for access, schema, application queries, or recovery requirements. PostgreSQL and MySQL also have managed Azure offerings; matching an existing engine can matter more than adopting SQL Server terminology. Verify the specific product and supported version rather than assuming all engines are interchangeable.

[Source: Azure SQL choices](https://learn.microsoft.com/en-us/azure/azure-sql/azure-sql-iaas-vs-paas-what-is-overview).

## 5. Objects, shares, and entities solve different needs

Blob Storage stores objects such as PDFs and images. Azure Files provides managed file shares for compatible file-access requirements. Table Storage stores entities in a nonrelational model; it is not a relational SQL table service. A managed disk belongs to a different storage abstraction again.

For the notes app, one plausible design keeps file contents in Blob and ownership metadata in a database. Record how those two parts stay consistent when an upload fails halfway. Storing the file and its metadata separately is a design decision, not automatic transaction coordination. Access to create the storage account is also different from permission to read its blobs. Treat a download token as a credential and keep it out of shared notes.

[Source: Storage services](https://learn.microsoft.com/en-us/azure/storage/common/storage-introduction).

## 6. Understand where a document database fits

Azure Cosmos DB supports nonrelational application scenarios through supported APIs and data models. A document-style record may fit flexible course metadata without representing each optional attribute as a separate relational column. That does not establish that every workload belongs there.

Start with the application's reads, updates, relationships, consistency requirements, and operating constraints. A SQL-like query language does not by itself imply relational behaviour or unrestricted relational joins. For fundamentals, be able to compare a document, a key-value entity, an object, and a relational row. Detailed application implementation and performance tuning are beyond this unit.

[Source: Cosmos DB overview](https://learn.microsoft.com/en-us/azure/cosmos-db/overview).

## 7. Follow data through the pipeline

Batch processing handles a bounded collection, such as yesterday's downloads. Streaming processes arriving events with bounded delay, but must still deal with duplicates, late events, and failures. A dashboard updated every second is not evidence that every source event has already arrived.

ETL transforms data before loading the intended target. ELT loads it and transforms using the target's processing capabilities. Neither acronym guarantees clean data. Define record identifiers, types, rejected-record handling, and reconciliation checks. Count source events, accepted events, and rejected events; explain differences instead of hiding them. Orchestration coordinates the steps, their dependencies, and recovery after failure; it is distinct from the transformation itself.

[Source: ETL and ELT](https://learn.microsoft.com/en-us/azure/architecture/data-guide/relational-data/etl).

## 8. Turn stored data into useful analysis

A data lake can hold varied data for later processing. A warehouse organises analytical data for consistent queries and reporting; a lakehouse combines approaches. A pile of files becomes useful only when ownership, formats, quality, and discovery are defined. In a star model, a fact table records measurable events and dimension tables supply descriptive context; choose the grain before adding totals.

Azure Synapse Analytics provides analytical capabilities and integration options. Microsoft Fabric brings multiple data and analytics workloads together in a SaaS platform. Power BI supports semantic models, reports, and dashboards. These are related roles, not interchangeable labels. Define a measure such as completed downloads, its time zone, and its refresh boundary before building a chart. Otherwise two correct-looking reports may count different things.

[Source: Fabric overview](https://learn.microsoft.com/en-us/fabric/fundamentals/microsoft-fabric-overview).

## 9. Design exercise and evidence

Without creating cloud resources, draw a design for PDFs, enrolments, and monthly download reports. Produce six synthetic records, including a duplicate event and a missing course identifier. Choose a store for each dataset, state an acceptable reporting delay, and describe how the duplicate and invalid record are handled. Write one sample SQL query or explain its expected result on paper. Distinguish a design prediction from an observed execution result.

A DBA focuses on database operation, a data engineer on moving and shaping data, and an analyst on answering questions with models and reports. Responsibilities overlap; assign an owner for each quality check. Compare your design with the [general data chapter](../../en/04-storage.md), then solve the [ten cases](DP-900-cases.md) before opening their answers.
