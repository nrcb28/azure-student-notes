# AZ-802 · Administering Windows Server

[Certifications](README.md) · [10 reasoned cases](AZ-802-cases.md) · [Five-unit workbook](AZ-802-workbook.md) · [Español](../es/AZ-802.md)

I would study this route as the student responsible for a small university Windows lab. The useful question is rarely “which console has this setting?” It is “which layer is failing, what evidence supports that conclusion, and how can I change it without losing access or data?” The examples below use an invented environment, not a university network we have inspected.

## 1. Start with the current route and a clear lab boundary

Use isolated VMs with a disposable AD forest `lab.example.test`, two domain controllers, a member file server, and a client. Add a Hyper-V host only where nested virtualization, memory, storage, and licensing permit it. An Azure extension is optional and requires an authorized subscription, cost owner, and supported networking. Never attach the lab domain to a production trust just to make an exercise work.

PowerShell examples below inspect state; they are not an installation script. They need Windows and the named roles/modules, suitable permissions, and substituted lab names. The Linux documentation environment has not executed them. Keep credentials, recovery keys, personal identifiers, and raw production logs outside published evidence. ## 2. Explain identity before creating accounts

AD DS is a directory with domain controllers, replication, DNS dependencies, and authentication responsibilities. Microsoft Entra ID is a different identity system. Joining a Windows machine to an AD domain, registering it in Entra, and connecting it to Azure Arc solve different problems. A diagram should show which system authenticates a user, which identity administers Azure, and which account reaches a file share.

Start an identity inventory with forest/domain names, DNS namespace, domain controllers, functional compatibility, sites, subnets, time sources, and application dependencies. Separate ordinary student accounts from privileged administration. Distinguish security groups used in authorization from organizational units used for organization and policy targeting. Moving a user into an OU does not grant file access by itself.

For a university research service, consider a supported group managed service account rather than a student-owned password that expires after graduation. A gMSA has prerequisites and a defined set of hosts allowed to retrieve its managed password; it is not a universal login account. Document the service's required rights and network targets, and verify support in the particular application. See [gMSA overview](https://learn.microsoft.com/en-us/windows-server/identity/ad-ds/manage/group-managed-service-accounts/group-managed-service-accounts/group-managed-service-accounts-overview).

On a Windows administration machine with the ActiveDirectory module and directory-read rights:

```powershell
Get-ADDomainController -Filter * |
    Select-Object HostName, Site, IsReadOnly, OperationMasterRoles
Get-ADDomain | Select-Object DNSRoot, PDCEmulator, RIDMaster, InfrastructureMaster
```

The output is an inventory, not proof that every controller is healthy. Compare it with the intended topology. A missing site assignment, an inaccessible controller, or a service running under a privileged human account becomes a question to investigate, not an excuse to recreate the domain.

## 3. Connect DNS, time, sites, and replication

A domain client needs suitable DNS to discover AD services. “The internet works” is weak evidence: public name resolution can succeed while the domain's SRV lookup fails. In the lab, resolve the domain and service records using the client's actual resolver. Then test the named controller and required protocol, rather than beginning with a password reset.

```powershell
Get-DnsClientServerAddress -AddressFamily IPv4
Resolve-DnsName -Name '_ldap._tcp.dc._msdcs.lab.example.test' -Type SRV
w32tm /query /status
```

These queries require appropriate network access; `w32tm` is a Windows tool. A successful SRV answer does not prove that the advertised server is reachable or that authentication succeeds. Record the resolver, returned targets, timestamps, and errors. Kerberos also depends on an acceptable time relationship. Diagnose the time hierarchy and synchronization status instead of changing every clock independently.

AD sites and subnet mappings describe network location and influence service location and replication. Creating a site without assigning the relevant IP subnet does not make clients use it. When a campus account change appears late at a remote building, compare controller selection, replication health, topology, schedules, and connectivity. Do not immediately lower all intervals or force replication without understanding the failure.

With the AD tools and relevant permissions, query the selected lab controller:

```powershell
Get-ADReplicationFailure -Target 'LAB-DC1.lab.example.test' -Scope Server
repadmin /replsummary
```

Treat errors as a timeline. A replication symptom may originate in DNS, authentication, time, network filtering, or a directory problem. Fixing transport does not automatically establish that every required change has converged. Validate the particular object or policy afterward. Use [AD replication concepts](https://learn.microsoft.com/en-us/windows-server/identity/ad-ds/get-started/replication/active-directory-replication-concepts) to explain why local success and forest-wide convergence are different claims.

## 4. Choose controller and policy operations deliberately

An RODC is useful where physical or administrative trust is weaker, but “read-only” does not mean “stores no credentials.” Its password replication policy determines which credentials may be cached. Plan allowed and denied accounts, delegated administration, access to writable controllers, and the response to losing the device. A privileged account cached at an untrusted branch defeats much of the intended boundary. See [RODC password replication groups](https://learn.microsoft.com/en-us/windows-server/identity/ad-ds/manage/understand-security-groups).

FSMO roles are distinct responsibilities, not a load-balancing group. A role transfer is a controlled move while the existing holder is available. Seizure is a recovery action for an unavailable holder and needs a supported plan for that former holder before it returns. A failed user logon alone does not justify seizing every role. First identify the failing operation, role dependency, controller health, and recovery owner.

For Group Policy, separate policy existence, scope, processing, and resulting settings. Check the relevant user/computer OU, links, inheritance, security filtering, WMI filtering where used, and client evidence. A user policy is not automatically applied to every computer in the same classroom. Loopback changes how user policy is selected on particular computers and needs a deliberate use case.

On the affected Windows lab client, `gpresult /r` summarizes the applied context. Explain the difference between “the GPO is linked,” “this client processed it,” and “the effective setting matches our requirement.” Group Policy preferences are not a place to publish reusable privileged passwords. Keep the rollback of a policy setting explicit; unlinking a policy is not a universal promise to restore every previous value. Review [Group Policy overview](https://learn.microsoft.com/en-us/windows-server/identity/ad-ds/manage/group-policy/group-policy-overview).

## 5. Make remote and hybrid administration a permission design

Draw the operator, administration workstation, gateway or endpoint, target server, and any second resource. Windows Admin Center, Server Manager, PowerShell remoting, SSH, and RDP have different prerequisites and session behaviours. Opening a port does not grant a user administrative authority, and broad administrator membership is a poor substitute for identifying the operation required.

The second-hop problem appears when a session on server B must access resource C using an appropriate identity. Do not solve it by copying an administrator password into a script. [PowerShell second-hop guidance](https://learn.microsoft.com/en-us/powershell/scripting/security/remoting/ps-remoting-second-hop) compares methods and limitations. CredSSP delegates credentials with additional exposure; constrained-delegation approaches have protocol limitations, including WinRM second-hop restrictions. Select the actual supported path and authentication mechanism rather than treating “enable delegation” as one setting.

[JEA session configuration](https://learn.microsoft.com/en-us/powershell/scripting/security/remoting/jea/session-configurations) can expose a restricted administrative endpoint. Review role capabilities, visible commands and parameters, execution identity, authorized users, and transcripts together. By default a JEA virtual account is a local Administrators member on a member server and a Domain Admins member on a domain controller. Configure restricted execution groups where supported and inspect command escape routes. A small command list does not establish least privilege if a permitted command can launch arbitrary code.

Azure Arc makes a non-Azure server manageable through Azure services; it does not join AD, create a forest trust, or remove local security responsibilities. The [Arc security overview](https://learn.microsoft.com/en-us/azure/azure-arc/servers/security-overview) describes sensitive agent and extension boundaries. Decide who may install extensions and execute scripts, especially on domain controllers. For updates, separate assessment from installation, maintenance scope from reboot handling, and a runbook's schedule from successful completion. Pilot a representative member server before widening a change.

## 6. Treat Hyper-V capacity, networks, and recovery separately

For each VM, record its role, guest compatibility, memory, CPU, storage path, virtual network, startup dependencies, and acceptable interruption. Dynamic Memory is a policy with workload compatibility and host headroom requirements, not free capacity. Nested virtualization and GPU partitioning need support for the exact hardware, OS, guest, and configuration. Avoid promising a feature because it appears in a screenshot from another edition.

Inspect a lab Hyper-V host with its module and suitable host permissions:

```powershell
Get-VM -Name 'LAB-APP' | Select-Object Name, State, Generation, MemoryAssigned, CheckpointType
Get-VMMemory -VMName 'LAB-APP'
Get-VMSwitch | Select-Object Name, SwitchType
Get-VMSnapshot -VMName 'LAB-APP' | Select-Object Name, SnapshotType, CreationTime
```

The inventory above does not prove production consistency. `SnapshotType` is the checkpoint classification exposed by [Get-VMSnapshot](https://learn.microsoft.com/en-us/powershell/module/hyper-v/get-vmsnapshot), while the VM's `CheckpointType` is its configured policy. Check creation results and the relevant guest consistency or VSS evidence; do not infer successful production processing from the word Standard or the requested policy alone.

Map an external, internal, or private virtual switch to the intended communication boundary. An isolated switch can explain why two lab guests communicate but cannot reach the campus; changing the guest firewall alone will not create an uplink. Distinguish a host adapter problem, VM adapter attachment, guest IP configuration, DNS, and application access.

[Checkpoints](https://learn.microsoft.com/en-us/windows-server/virtualization/hyper-v/checkpoints) are especially easy to misunderstand. Standard checkpoints capture VM state, including memory; production checkpoints use guest-aware consistency mechanisms where supported. A production configuration can allow fallback to standard, while ProductionOnly refuses that fallback. Neither setting turns the VM's checkpoint chain into an independent protected backup. Do not manually delete AVHDX files to clear space; use supported management and merging procedures.

Hyper-V Replica supports asynchronous replication and planned/test/unplanned failover workflows. It is different from clustered VM high availability and from historical backup. A replica may contain a bad application change. In a design review, identify the failure addressed, the possible lag, the authoritative writer, network mapping, test isolation, and failback process. See [Hyper-V Replica overview](https://learn.microsoft.com/en-us/windows-server/virtualization/hyper-v/replication-overview).

| Mechanism | Useful for | Does not establish by itself |
|---|---|---|
| Checkpoint | A controlled VM-state return during a supported lab change | An independent copy surviving loss of its storage chain |
| Hyper-V Replica | Recovering a replicated VM after a primary failure | An uncorrupted historical recovery point or zero data loss |
| Clustered VM | Restarting/moving a supported VM after host failure | Application-level correctness or protection against deletion |
| Protected backup with tested restore | Historical recovery under the selected retention and consistency policy | Automatic failover or a recovery time never measured |

## 7. Diagnose an Azure VM as a complete Windows workload

An Azure VM can be running while its guest service is unusable. Separate platform status, boot, guest networking, Windows authentication, service health, and application dependencies. Resizing changes available resources and may require a restart or introduce placement/capacity constraints; check both VM and disk limits before calling it a performance repair.

Availability sets and zones concern placement. A second VM does not automatically provide application failover, duplicate writable directories, or a consistent file service. For an AD domain controller in Azure, follow supported directory virtualization and backup guidance, arrange suitable DNS and network paths, and avoid treating a copied operating-system disk as a new independent controller.

Azure Bastion provides a managed access path; JIT controls restrict exposure under their supported requirements. Neither replaces Windows credentials, guest authorization, or required application permissions. Investigate why the approved path fails before opening permanent public RDP. The exercise deliverable is a path diagram and a least-privilege access explanation, not a public endpoint created for convenience.

## 8. Troubleshoot DNS and DHCP with the actual client path

Build a name-resolution chain: client resolver, local zone, conditional forwarder, upstream target, and authoritative answer. A conditional forwarder sends queries for a specific namespace to selected DNS servers; it does not create a network route to them. DNSSEC adds validation of DNS data, not transport encryption or automatic access to a private application. Specify what a lookup must return and from which side of the hybrid boundary.

On a DNS administration host with the DnsServer module and appropriate read access:

```powershell
Get-DnsServerZone -ComputerName 'LAB-DC1'
Get-DnsServerForwarder -ComputerName 'LAB-DC1'
```

For DHCP, inspect the scope range, exclusions, leases, reservations, options, relay path, and authorized server. A reservation is tied to a client identifier; it does not make the address static inside the guest. A full scope can fail new clients while existing leases continue, so test both cases. A relay or VLAN issue can look like a DHCP service failure when the server never receives the request.

With the DHCP Server module and relevant rights:

```powershell
Get-DhcpServerv4Scope -ComputerName 'LAB-DHCP1'
Get-DhcpServerv4Failover -ComputerName 'LAB-DHCP1'
```

DHCP failover protects the configured relationship and scopes under its supported behaviour; merely deploying a second server does not coordinate allocations. Record the mode, partner state, supported lease behaviour, and a recovery procedure. See [DHCP failover](https://learn.microsoft.com/en-us/windows-server/networking/technologies/dhcp/dhcp-failover).

## 9. Trace every file-access boundary

A student who can sign in is not necessarily entitled to a share. For a Windows SMB server, inspect share permissions and NTFS permissions for the actual identity, including group membership and inheritance. An explicit deny and a stale group token can change the result. Document the intended collaboration group and isolation boundary rather than granting Everyone full control until the symptom disappears.

On the lab file server, with the SMBShare module and access to the selected folder:

```powershell
Get-SmbShareAccess -Name 'LabNotes'
Get-Acl -LiteralPath 'D:\LabShares\Notes' | Format-List Owner, AccessToString
```

These outputs describe configured entries; they are not a complete effective-access proof. Test a permitted user and a denied user against the intended path. Azure Files has its own supported identity setup and share-level authorization, plus directory/file permissions where applicable. [Azure Files authorization](https://learn.microsoft.com/en-us/azure/storage/files/storage-files-authorization-overview) makes that layering explicit. A resource-management Contributor role is not automatically SMB data permission.

Azure File Sync connects a cloud endpoint with server endpoints and can tier files. Synchronization and availability do not provide an independent historical recovery boundary by themselves. Plan retention, protected backups, restore dependencies, endpoint health, cache capacity, and how a deleted or corrupted file will be recovered. A placeholder is not proof that the required contents are immediately local. See [Azure File Sync planning](https://learn.microsoft.com/en-us/azure/storage/file-sync/file-sync-planning).

Recovery of a registered File Sync server has additional restrictions: restoring its operating-system image, cloning it, or reverting its VM checkpoint is not a generic supported recovery path. Follow the [File Sync disaster-recovery guidance](https://learn.microsoft.com/en-us/azure/storage/file-sync/file-sync-disaster-recovery-best-practices), identifying the full cloud copy, retained protection and supported server re-registration/recovery process as applicable. Do not make an ordinary Hyper-V rollback the workbook's File Sync restore procedure.

[SMB over QUIC](https://learn.microsoft.com/en-us/windows-server/storage/file-server/smb-over-quic) needs supported OS editions/versions, clients, connectivity, and a suitable certificate. At this review, the guide lists Windows Server 2022 Datacenter: Azure Edition or Windows Server 2025 editions, with Windows 11 clients. Check the default UDP 443 path and a trusted Server Authentication certificate with the required DNS subject alternative names and usable private key. The current Windows Server 2025 setup uses PowerShell; do not substitute an older Windows Admin Center recipe without checking the version-specific procedure. QUIC does not bypass file authorization, and enabling it is not permission to expose unrelated services.

## 10. Separate storage capacity, resilience, and recoverability

Disk size is only one dimension. Map physical devices, pools, virtual disks, volumes, filesystems, workloads, and protection. Storage Spaces, Storage Spaces Direct, Storage Replica, DFS namespaces, and DFS Replication have different purposes. A namespace gives a logical path; it does not guarantee that the referred content is synchronized or that an application can safely accept concurrent writes.

Read-only inventory on a compatible Windows storage host:

```powershell
Get-PhysicalDisk | Select-Object FriendlyName, HealthStatus, OperationalStatus
Get-VirtualDisk | Select-Object FriendlyName, ResiliencySettingName, HealthStatus
Get-Volume | Select-Object DriveLetter, FileSystem, HealthStatus, SizeRemaining, Size
```

Correlate latency, throughput, queues, capacity, and workload timing. A healthy pool can still have insufficient performance. Resilience to a device failure does not protect against an administrator deleting a folder. [Storage Replica](https://learn.microsoft.com/en-us/windows-server/storage/storage-replica/storage-replica-overview) also needs a supported topology, suitable log/data arrangements, and an explicit recovery design; replication is not a universal replacement for backup.

Choose NTFS or ReFS for supported workload requirements, not a slogan that one is always faster. Deduplication, SMB Direct/RDMA, storage QoS, iSCSI, and BitLocker each bring compatibility and operational requirements. For encryption, protect recovery material separately and verify that an authorized recovery path exists. Do not publish a recovery key as a workbook screenshot. Retain an independent copy of essential recovery instructions where an outage cannot make it inaccessible.

## 11. Harden according to role and preserve recovery access

A file server, Hyper-V host, and domain controller should not receive an unexplained identical settings bundle. Begin with asset roles, privileged identities, exposed services, permitted administration paths, and recovery access. Stage firewall and authentication changes with a tested way back in. A security setting that silently disables the only management channel can turn a small problem into a recovery exercise.

[OSConfig security baselines](https://learn.microsoft.com/en-us/windows-server/security/osconfig/osconfig-how-to-configure-security-baselines) currently target Windows Server 2025. Verify the installed module and supported scenario before applying one; do not copy those commands to an older server. Inspect the planned settings, pilot the right server role, review compliance and drift, and document the prior state. Applying or removing a baseline requires a restart. Removing configuration management is not a promise that every prior value will be restored.

[Windows LAPS](https://learn.microsoft.com/en-us/windows-server/identity/laps/laps-overview) reduces reuse of local administrator passwords through managed rotation and controlled retrieval. Decide the supported backup destination, account policy, retrieval roles, auditing, and recovery procedure. This does not grant permission to retrieve passwords for a student report. On controllers, DSRM recovery has its own supported LAPS conditions; do not confuse a domain account with a machine's local recovery credential.

Credential Guard, application control, exploit protection, Defender for Servers, and account protections address different threats. Verify hardware/OS prerequisites and observe actual enforcement, rather than treating an installed feature as protection proved. For AD delegation, grant the narrow directory operation needed on the appropriate scope. A helpdesk password-reset task does not require Domain Admin membership. Keep privileged sessions off ordinary browsing and email machines where possible.

## 12. Build useful monitoring before troubleshooting by dashboard

Pick a question first: failed sign-ins, disk latency, replication failure, update health, or a missing agent extension. Specify the source, collection method, destination, time window, owner, and alert action. Performance Monitor counters and data collector sets help establish a baseline; a single high sample does not identify the cause. Correlate the application symptom with the same interval and compare against normal workload behaviour.

Azure Arc connection status, Azure Monitor Agent health, a data collection rule (DCR), the DCR association, and destination permissions are separate checks. [AMA troubleshooting for Windows Arc servers](https://learn.microsoft.com/en-us/azure/azure-monitor/agents/azure-monitor-agent-troubleshoot-windows-arc) distinguishes agent/configuration and ingestion paths. Heartbeat data can show an agent is reporting while the requested event logs remain uncollected. An empty query can mean the wrong time range, table, source selection, association, or workspace, not necessarily “no incidents.”

On the relevant Windows lab server, a local event query can help establish whether source events exist:

```powershell
Get-WinEvent -FilterHashtable @{LogName='System'; StartTime=(Get-Date).AddHours(-2)} -MaxEvents 20 |
    Select-Object TimeCreated, Id, ProviderName, LevelDisplayName
```

Reading some logs requires elevated or delegated permissions. Record the query time and timezone, keep useful event identifiers, and redact sensitive values. Explain separately whether the event happened locally and whether the configured collection delivered it. Alerts need a useful threshold, recipient, response owner, and validation case; a rule that nobody receives is an incomplete operating procedure.

## 13. Use a diagnosis order and a supported recovery method

For a logon incident, my first worksheet would ask: what changed, which identities and devices fail, what is the exact error, and when did it start? Then follow IP configuration, resolver/SRV results, controller reachability, time, authentication and secure-channel evidence, replication, and authorization. This is a hypothesis order, not an instruction to disable firewalls or reset every account. On a member server, `Test-ComputerSecureChannel` can inspect trust; do not add `-Repair` without a separately justified change, and do not treat that member-server test as a DC-health check.

For a missing file, identify the namespace and authoritative location, intended identity, share/NTFS or Azure authorization, synchronization state, deletion timeline, and usable historical copy. For a slow VM, compare the guest workload with host contention, memory pressure, disk limits, queues, and network dependencies. Preserve evidence before rebooting away the symptom.

AD recovery needs special care. A Recycle Bin object restoration has prerequisites and does not equal a whole-domain recovery. DSRM is a recovery boot context with protected credentials, not a normal administrative session. SYSVOL recovery and authoritative/non-authoritative directory restoration depend on the actual failure and supported procedure. Use [AD forest recovery guidance](https://learn.microsoft.com/en-us/windows-server/identity/ad-ds/manage/forest-recovery-guide/ad-forest-recovery-guide) to plan owners, clean recovery, backups, dependencies, and validation. Never practice a controller rollback or FSMO seizure against a real directory from these notes.

## 14. Turn lab work into evidence rather than screenshots

The [workbook](AZ-802-workbook.md) combines these topics into five investigations. Before each investigation, write the expected result, a competing explanation, commands that distinguish them, the state that may change, and an exit condition. A screenshot of Server Manager is weaker evidence than an identity-specific test with timestamp, target, command, sanitized result, and explanation.

Use a change ledger: baseline, proposed action, approval owner in a real environment, observation, interpretation, and rollback gate. If no Windows lab is available, produce a topology and predicted observations clearly labelled as predictions. Do not invent output or describe a planned restore as completed. Prefer small reversible changes in a disposable lab, one variable at a time, with a known recovery path.

| Example family | Prerequisites to record before querying |
|---|---|
| AD inventory/replication | ActiveDirectory/RSAT tools, reachable lab controllers, relevant directory-read rights |
| DNS client, time, policy | Windows client, correct user/computer context, access to the queried service |
| DNS/DHCP server | DnsServer/DhcpServer modules and delegated or administrative read rights on the selected server |
| Hyper-V | Supported Windows host, Hyper-V PowerShell module, authorized host access |
| Share and filesystem | SMBShare support, actual share/path, rights to inspect its ACL |
| Storage inventory | Supported Storage module/provider and authorized host context |
| Local event logs | Existing log and time range, permission to read that log, redaction plan |
