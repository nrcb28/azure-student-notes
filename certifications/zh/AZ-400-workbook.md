# AZ-400 · 八语共同进阶练习册

[←](README.md) · [共同学习核心](../../zh/16-common-core.md) · [进阶实验](../../zh/17-advanced-labs.md)

八种语言具有对应的目标、案例和交付物。按学习单元及验证证据检查等价性，而不是比较字数。原有指南仍作为补充说明保留。

<a id="az-400-unit-1"></a>

## 1. 追踪与 Git

关联需求、issue、PR、commit、build、制品和部署。统一指标边界，不按代码行或提交评价个人。按发布频率和维护版本选择分支。

**案例：**撤销共享发布。**证据：**解释 revert 与重写历史及数据影响。泄漏秘密先撤销或轮换，不只删除文件。

<a id="az-400-unit-2"></a>

## 2. 测试与制品

构建一次，推广同一已标识结果，记录版本、适用的 digest 和来源。按风险组合测试，覆盖率不保证断言有价值。

**案例：**代码没变，昨天成功今天失败。**证据：**检查未固定工具、依赖和基础镜像。调查不稳定测试，不只是重复到绿色。区分缓存与制品。

<a id="az-400-unit-3"></a>

## 3. Runner 身份与边界

区分可信代码、PR 输入、workflow 权限和云作用域。自托管 runner 需要隔离、更新和清理。OIDC 仍要求精确信任与授权。

**案例：**外部 PR 修改内部脚本。**证据：**无生产权限的执行路径、身份限制和资源控制。Pipeline 代码并非天然无害。

<a id="az-400-unit-4"></a>

## 4. 部署与恢复

比较 rolling、blue-green、canary、rings 和 flags。明确人群、功能信号、观察期和停止条件。Swap 不隔离所有依赖，适用时设计向后兼容迁移。

**案例：**canary CPU 正常但结果错误。**证据：**业务信号和回滚标准，解释旧镜像为何不能恢复删列。

<a id="az-400-unit-5"></a>

## 5. 闭合运维循环

传播上下文，在遥测中标明版本并保护日志。指定告警负责人和窗口。资源审批不只是作者能改的 YAML 条件。

**交付：**完整 pipeline、有意义测试、固定制品和晋级策略。运行本地模拟器，换重试政策再试。复盘措施包含动作、负责人和验证。
