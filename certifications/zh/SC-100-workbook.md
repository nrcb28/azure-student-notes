# SC-100 · 安全架构练习册

[指南](SC-100.md) · [十个案例](SC-100-cases.md) · [目录](README.md) · [Español](../es/SC-100-workbook.md)

面向虚构大学笔记服务的五个原创离线单元。使用虚构资产、身份、事故和证据。产出架构提案与桌面演练结果；不修改租户、不运行攻击、不部署资源、不连接实时遥测。不宣称云操作已执行或控制已有效。

<a id="sc-100-unit-1"></a>

## 1. 确定关键性与控制覆盖

**场景：**大学在原本只保存公开笔记的应用中加入未公开考核答案。确定关键操作、数据负责人、可能威胁和业务影响。区分 MCRA 能力映射、MCSB 控制要求、CAF 平台责任与 Well-Architected 工作负载审查。明确假设，不编造完整资产清单。

**证据：**假设资产图、三项优先风险、当前控制边界和缺失信息。加入一项不能仅凭 Azure Policy 结果评估的要求。

**交付物：**覆盖表，包含要求、控制、范围、负责人、证据、缺口和验收标准。附简短 ADR 比较两个选项，并指定有权接受残余风险的负责人。

<a id="sc-100-unit-2"></a>

## 2. 限定身份、网络与特权边界

**场景：**校园用户、访问教师、管理员、部署管道和 AI 智能体访问笔记服务的不同部分。跨校园与云绘出身份、应用、网络和管理边界。规定最小权限、特权激活、恢复访问、凭据或联合身份归属。检查拟议智能体控制的功能与许可假设。

**证据：**六项预期允许或拒绝决定、专用 DNS 依赖、公共访问假设，以及网络可达时授权如何继续成立的说明。

**交付物：**信任边界图和访问矩阵，包含负责人、范围、生命周期、日志和失败行为。加入被拒绝的智能体工具操作及恢复管理员路径。所有身份和请求均保持虚构。

<a id="sc-100-unit-3"></a>

## 3. 连接检测与获授权响应

**场景：**可疑校园身份活动与异常文档下载同时出现。定义跨身份、终端、应用、云和 SaaS 所需 SOC 能力。将两条优先威胁路径映射到相关 MITRE ATT&CK 技术、预期遥测、关联、分诊和遏制。说明 Sentinel 与 Defender XDR 责任，不假设完整可见性。

**证据：**合成时间线，显示事件来源、摄取延迟、保留假设、缺失信号和竞争解释。确定谁能禁用身份或中断考试服务器。

**交付物：**检测覆盖矩阵与响应权限表，包含升级处理、批准、回退和证据保全。将每项检测与响应标为提案，并注明投入运维前所需验收证据。

<a id="sc-100-unit-4"></a>

## 4. 保护数据以及软件和 AI 生命周期

**场景：**新 AI 助手检索课程文档，构建管道部署其 API。分类信息并映射标签、加密、DLP、保留和应用访问边界。说明控制缺少支持之处。对依赖、构建身份、制品提升、文档提示注入和工具访问进行威胁建模。

**证据：**一个合成正常检索、一份带不可信指令的文档和一次虚构未批准构建。记录预期检索与工具拒绝，不生成利用指令或运行测试。

**交付物：**数据控制矩阵和生命周期审查，显示负责人、范围、溯源、权限、批准和验收证据。解释检测、加密和基准映射为何各自留下需独立评估的风险。

<a id="sc-100-unit-5"></a>

## 5. 演练恢复并安排计划顺序

**场景：**勒索软件影响主要文档存储和一个特权账户。使用练习要求：应用 RTO 两小时、RPO 十五分钟。跟踪身份、控制平面访问、DNS、密钥、配置、元数据、文件和部署依赖。比较受保护恢复点与复制，考虑损坏和备份管理失陷。

**证据：**桌面恢复顺序、假设恢复时间戳、一致性检查，以及即使文件恢复仍阻止获授权读取的一项依赖。将测量标为假设。

**交付物：**恢复验收计划和受一学期经费限制的三阶段路线图。包含负责人、工作量估计、前置依赖、回退标准、到期例外，以及业务对剩余风险的批准。没有验证实际恢复或恢复目标。
