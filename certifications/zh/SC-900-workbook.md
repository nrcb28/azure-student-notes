# SC-900 · 决策与证据练习册

[指南](SC-900.md) · [十个案例](SC-900-cases.md) · [目录](README.md)

五个原创单元，在各语言中应用相同学习目标。使用虚构大学与合成数据。这是离线设计练习，不部署策略、不修改租户，也不声称完成 Azure 执行。

<a id="sc-900-unit-1"></a>

## 1. 画出责任与信任边界

画出浏览器、身份提供商、应用和文档存储。在每个边界说明验证什么，以及相关控制由谁运行。把提供商的平台职责与组织关于用户、共享、配置和数据的决定分开。解释为什么校园网络不足以证明请求可信。

**场景：**来宾必须能读已发布笔记，但不能读取未发布解答。**证据：**图示，以及包含两个允许和两个拒绝操作、负责人和所需观察的表格。**交付物：**一页文档，区分预期结果与实际观察。本练习不要对真实租户进行测试。

<a id="sc-900-unit-2"></a>

## 2. 设计一次访问决定

明确身份类型、目标应用、所请求动作和最小权限。提出身份验证要求，解释因素类别和抗钓鱼特性。描述哪些条件访问信号重要，以及仍需哪些应用检查。记录范围、排除项、恢复和许可证依赖，而不是只写“给所有人启用 MFA”。

**场景：**访问教师用个人设备读取课程材料。**证据：**分别说明合法请求、身份验证方法不足、请求超出教师权限三种情况的预期决定。**交付物：**带理由的访问矩阵。保持假设性质，不修改租户控制，也不把仅报告观察当作已执行的决定。

<a id="sc-900-unit-3"></a>

## 3. 区分特权、现有权限与风险

写出三个问题：谁可激活特权角色、谁应保留项目权限、哪种身份行为值得调查？分别对应 PIM、访问复核和身份风险概念。定义角色范围和持续时间，不能假设短期广权限就自动是最小权限。

**场景：**前项目成员仍在组中，而管理员需要临时维护权限。**证据：**授权路径、资源所有者决定、拟议激活流程，以及存在可疑行为时单独保存的记录。**交付物：**简短操作手册，说明谁批准每项决定、怎样确认完成。本练习不创建特权分配。

<a id="sc-900-unit-4"></a>

## 4. 规划检测与有边界的响应

选择包含邮件、身份和工作负载的假设攻击链。列出支持或推翻假设所需的事件。解释 Defender XDR 关联在哪些位置有用，以及 Sentinel 连接器、分析和响应编排可能用在哪里。标出缺失数据；空结果不证明事件从未发生。

**场景：**钓鱼邮件之后出现可疑登录。**证据：**事件时间线、来源覆盖、负责分析师，以及在破坏性动作之前发出通知的方案。**交付物：**检测响应表，包含误报考虑和恢复步骤。本练习不引入遥测、不开启付费服务、不自动封锁账户。

<a id="sc-900-unit-5"></a>

## 5. 追踪敏感数据生命周期

跟踪一份合成文档，从创建到内部使用、共享、调查和最终处置。区分分类、配置的保护、DLP 处理、内容保留、审核证据和电子数据展示。记录每种能力依赖的工作负载与许可证假设。合规分数不能替代对组织实际义务的认定。

**场景：**虚构解答表在发布前必须保持私密，相关消息需为调查保留。**证据：**预期处理决定、所需活动记录、保留假设和具名负责人。**交付物：**生命周期表，解释为什么单个标签、日志或备份不能满足所有要求。法律义务应由有权负责人提供，作为设计输入。
