# DP-700 · 离线数据工程练习册

[指南](DP-700.md) · [十个案例](DP-700-cases.md) · [目录](README.md) · [Español](../es/DP-700-workbook.md)

五个单元使用合成大学数据，无需账户、付费容量或执行 Fabric。各语言版本保持相同交付物。推理输出标为 **EXPECTED**，本地观察标为 **OBSERVED**，未执行平台检查标为 **NOT EXECUTED**。来源范围与核验限制见[指南](DP-700.md)。

<a id="dp-700-unit-1"></a>

## 1. 绘出平台与归属关系图

解释租户、容量、工作区、项、OneLake 位置和执行引擎的区别。绘出大学选课来源、原始下载文件、整理表、图书馆目录快捷方式和分析使用者。决定湖屋与仓库可以放在哪里，分别给出一个具体理由。说明各表的粒度。

**场景：**图书馆控制快捷方式目标并改变访问策略。**证据：**记录目标归属、内部或外部认证假设、所需权限、架构约定和目标删除的影响。**交付物：**依赖图与访问矩阵。另列历史保留要求；快捷方式本身不能满足备份或恢复需求。

<a id="dp-700-unit-2"></a>

## 2. 对账增量变更日志

使用下面完整合成日志；`version` 是权威源顺序，`key` 标识选课。初始目标为空。为删除保留带版本的墓碑记录。每个键归并到最大版本，折叠完全相同的重复，再仅合并新版本。同版本载荷冲突必须隔离。

| key | version | operation | module |
|---|---:|---|---|
| E1 | 1 | upsert | CS101 |
| E2 | 1 | upsert | DB201 |
| E1 | 2 | upsert | AI301 |
| E1 | 2 | upsert | AI301 |
| E2 | 2 | delete | DB201 |
| E2 | 1 | upsert | DB201 |

**场景：**成功响应丢失后重放日志。**预期证据：**E1 在版本 2 仍活跃于 AI301；E2 在版本 2 已删除。两次运行后活跃数均为 1。**交付物：**中间状态与进度提交规则；解释迟到的 E2 版本 1 为何不能使其复活。

<a id="dp-700-unit-3"></a>

## 3. 规定质量与事件时间规则

设计下载记录，包含事件标识符、课程、事件时间、到达时间和架构版本。定义空值、类型、允许值和重复规则。解释批准可选新字段与接受无效记录的区别。隔离区要保留可修复标识符与原因，同时限制敏感内容访问。

**场景：**事件发生于 UTC 23:59，次日 UTC 00:07 到达；声明允许迟到十分钟。**预期证据：**它的事件时间日期是前一天。是否接受还需要知道到达时引擎的水印；仅凭八分钟实际到达延迟不能证明会被接受。**交付物：**接受和修正规则、对账、窗口边界、检查点用途，以及超过允许范围时的行为。

<a id="dp-700-unit-4"></a>

## 4. 设计受控部署

描述管道：复制有界选课区间，调用验证与转换，仅发布通过验收的结果。为相关转换选择 SQL、PySpark 或 KQL，并论证引擎选择。区分 Git 对受支持定义的版本管理、受支持内容的部署与数据移动。

**场景：**测试笔记本仍指向生产湖屋。**证据：**执行前检查项引用、连接绑定、运行身份、参数、环境依赖和计划。**交付物：**开发/测试/生产配置表，覆盖报表与文件路径的允许和拒绝读者测试，以及回退步骤。解释敏感度标签为何不能单独实现完整权限设计。

<a id="dp-700-unit-5"></a>

## 5. 诊断虚构的缓慢运行

建立运行耗时、输入输出计数、拒绝数、新鲜度和容量使用率基线。加入相同输入量耗时翻倍的事故。提出三种竞争解释：Spark 连接倾斜、大量小文件和并发容量需求。说明什么证据支持或否定各解释；适当检查分区裁剪与查询行为。

**场景：**部分写入后发生重试。**证据：**用单元 2 的版本规则展示业务状态是否改变。**交付物：**一项可逆调优实验，包含验收阈值和正确性对账。所有 Fabric 时间标为 NOT EXECUTED；合成推理不能证明实际吞吐量、恢复耗时或云部署成功。
