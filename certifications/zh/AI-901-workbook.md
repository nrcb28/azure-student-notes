# AI-901 · 共同进阶练习册

[指南](AI-901.md) · [十个案例](AI-901-cases.md) · [目录](README.md)

各学习语言均包含对应的五个单元。使用虚构的大学笔记、提示词、转写和候选回答离线练习。把每个候选输出标为**合成内容**，把每个预期结果标为**预测**。不要上传真实学生资料。本练习册不部署任何资源，也不代表已覆盖完整考试范围。资料核对日期：**2026 年 11 月 1 日**；[目标自 2026 年 4 月 15 日起生效](https://learn.microsoft.com/en-us/credentials/certifications/resources/study-guides/ai-901)。

<a id="ai-901-unit-1"></a>

## 1. 定义五项 AI 约定

分别为回答课程问题、提取作业截止日期、分析反馈文本、接收口述问题和描述图表编写一项约定。规定输入模态、获准数据、输出形式、不可接受的错误及后备处理。根据产出比较生成式回答、文本分析、语音、视觉和 Content Understanding。加入一项图像生成请求，以区分创建与解释。

**场景：**队友建议所有功能都使用同一个图像模型。**证据：**一份五行决策矩阵，每行给出有理由的能力选择和被排除的替代方案。补充有关模态、部署选项、语言及支持参数的模型选择问题。把未知的服务细节标为需要在当前文档中核实的事项，不要编造限制。

<a id="ai-901-unit-2"></a>

## 2. 编写有来源依据的提示词和访问规则

虚构三个短段落：获准使用的课程笔记、私人笔记本，以及含有导出文档指令的获准页面。为其分配稳定的来源标识符，并设定两名访问列表不同的学生。编写系统提示词和用户提示词，要求回答有来源支持、保持来源边界，并允许证据不足时不作答。检索必须在构造上下文前按调用者的权限过滤；提示词不能提供这道安全边界。

**场景：**获准段落中没有问题的答案。**证据：**一次预期的不作答、一次对禁止访问的拒绝，以及一个抵抗注入的合成回答。标注每个来源支持哪些论断。解释为什么仅有引用或攻击检测器都不能证明真实性、隐私或权限正确。

<a id="ai-901-unit-3"></a>

## 3. 在不调用云服务的情况下追踪轻量客户端

画出 Python 客户端向预期 Foundry 终结点和已配置部署发送请求，并收到响应或错误的过程。区分身份、授权、目的地和部署选择。用伪代码描绘读取受保护配置、取得适当凭据、发送获准输入、检查错误与输出，以及呈现安全结果的过程。明确将草图标为**伪代码**，而不是可执行的 SDK 代码。解释字典、迭代、异常和异步调用可能出现在哪里。

**场景：**身份验证成功，但所选资源拒绝操作。**证据：**一份脱敏的故障排查清单，以及访问被拒、超时、空输出和配置无效时的预期客户端行为。比较 REST、SDK 和 CLI 如何表达同一任务。指出后续云端实践中会遵循的当前 [SDK 快速入门](https://learn.microsoft.com/en-us/azure/foundry/quickstarts/get-started-code)。

<a id="ai-901-unit-4"></a>

## 4. 验证多模态提取

虚构一张包含最终截止日期的作业单、另一张没有日期的作业单、一张单位无法辨认的图表，以及一个嘈杂的口述问题。定义截止日期架构，包括字段类型、缺失值规则和来源引用。生成刻意有缺陷的合成输出：猜测的日期、错误的单位和听错的技术术语。定位失败发生在提取、视觉解释、识别还是下游推理。描述语音转文本流水线，以及一种受支持的直接多模态替代方案。

**场景：**输出是有效 JSON，但与作业单矛盾。**证据：**分别记录架构验证和来源验证的结果、处理歧义的审核规则，以及文本无障碍后备方式。说明 [Content Understanding](https://learn.microsoft.com/en-us/azure/ai-services/content-understanding/overview) 如何处理文档、图像、音频和视频输入。不要用置信度代替证据。

<a id="ai-901-unit-5"></a>

## 5. 评估工具有限的单个智能体

设计一个笔记搜索智能体，指定指令、模型选择、按调用者范围检索，且不提供修改工具。定义搜索工具的请求与结果，以及客户端如何标识智能体并维护对话上下文。创建至少六行的失败矩阵：有依据的回答、证据缺失、文档访问被拒、注入、截止日期冲突和工具超时。先补充预期结果，再为每行编写两个互相竞争的合成回答。

**最终证据：**提交约定、提示词、访问列表、客户端草图、提取检查和已评分矩阵。分别评估事实支持、引用、不作答或拒绝、隐私、架构有效性和工具权限。解释一次提示词修改及其取舍。列出尚需动手完成的工作：模型部署和门户交互、真正的 SDK 聊天客户端、在门户中测试的单个智能体及其客户端。离线评分是这些工作的准备。
