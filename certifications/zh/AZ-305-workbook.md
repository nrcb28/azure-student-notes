# AZ-305 · 八语共同进阶练习册

[←](README.md) · [共同学习核心](../../zh/16-common-core.md) · [进阶实验](../../zh/17-advanced-labs.md)

八种语言具有对应的目标、案例和交付物。按学习单元及验证证据检查等价性，而不是比较字数。原有指南仍作为补充说明保留。

<a id="az-305-unit-1"></a>

## 1. 需求变为约束

定义用户、增长、驻留、隐私、性能、RTO/RPO、预算和技能。区分已验证需求与假设。始终可用需要明确操作和测量窗口。

**案例：**五学院共享网络，但各有私有数据。**证据：**管理与数据边界、所有者，以及要求隔离的具体条件。不因架构庞大而选择它。

<a id="az-305-unit-2"></a>

## 2. 设计数据与状态

比较查询、事务、兼容、一致性和恢复。JSON 不决定引擎，读取扩展不必然增加写入。区分应用、会话和文档状态。

**案例：**快速缓存返回旧权限。**证据：**失效、过期、缓存故障行为，以及不能依赖过期副本的信息。

<a id="az-305-unit-3"></a>

## 3. 设计完整恢复

为服务和数据分别设置 RTO/RPO，包含容量、凭据、授权、DNS 和配置。复制可能传播逻辑破坏。按费用和复杂度比较主动主动与主动被动。

**案例：**Key Vault 恢复但缺少集成。**证据：**顺序、授权消费者测试、不会自动恢复的依赖及隔离演练。

<a id="az-305-unit-4"></a>

## 4. 选择执行与通信

按控制、时长和运维比较 VM、PaaS、容器和 batch。队列增加状态及重复，扩消费者前先设计超时、有界重试和幂等。

**案例：**保存响应丢失且消息重复。**证据：**稳定 ID、尝试上限和部分处理策略，解释为何需要集群或简单平台。

<a id="az-305-unit-5"></a>

## 5. 记录迁移决定

盘点依赖和使用量，验证兼容，规划试点、初次传输、增量、切换和回退。定义完整性证据及源系统退出条件。缺少必要文件的 VM 迁移并未完成。

**交付：**两个 ADR、网络与恢复设计和风险表。每项决定包含合理备选、后果、测试和复查条件；改变预算或驻留后重新评估。
