# DP-900 · 共同进阶练习册

[指南](DP-900.md) · [十个案例](DP-900-cases.md) · [目录](README.md)

八种语言包含对应的五个单元。使用合成数据，把预测和观察分开记录。这些练习不部署 Azure，也不证明覆盖完整考试范围。

<a id="dp-900-unit-1"></a>

## 1. 选存储之前先描述数据

清点一个 PDF、一条选课行、一份有可选元数据的 JSON 文档和一个下载事件。分别描述结构、标识、生产者、消费者、保留时间和敏感字段。再写出重要操作：取文件、记录选课或聚合事件。区分格式选择和工作负载要求。

**场景：**有人因为四类数据属于同一个应用，就提议只用一个数据库。**证据：**提交四行决策矩阵，为每行排除一个替代方案，并说明什么新要求会改变选择。不要编造服务限制，也不要假设所有 JSON 文档都必须放在 Cosmos DB。

<a id="dp-900-unit-2"></a>

## 2. 让关系完整性看得见

画出带稳定标识的 Students、Courses 和 Enrolments。创建六条合成记录，解释主键、引用和防止重复选课的规则，预测一个连接结果。随后修改课程名称，与把名称复制到每条选课行的设计比较修改次数。目标是暴露具体更新异常，不是背诵规范化口号。

**场景：**学生选入不存在的课程。**证据：**写出应拒绝或发现它的规则、无效样本和预期结果。如果执行本地 SQL 示例，注明引擎；本地 SQLite 行为不等于测试了 Azure SQL。

<a id="dp-900-unit-3"></a>

## 3. 决定谁来运维数据库

针对新应用和迁移，比较 Azure SQL Database、Managed Instance 与 VM 上的 SQL Server。列出兼容依赖、网络与身份要求、维护责任和恢复期望。应用需要原有开源引擎时，把该选项也加入比较。推荐必须有依据，不能声称某产品永远最好。

**场景：**迁移清单包含需要访问来宾操作系统的组件。**证据：**提交兼容问题清单、运维责任表和带成功标准的概念验证计划。不要求部署；说明接受目标前仍需测试的假设。

<a id="dp-900-unit-4"></a>

## 4. 核对一条小型数据管道

制作六个合成下载事件，包含一个重复标识和一个缺少课程的记录。定义有效输入、唯一事件与完成条件。分别画 ETL 和 ELT 路线，标出验证和拒绝记录保存位置。解释何时批处理满足延迟要求，何时可能需要流处理。

**场景：**仪表板总数与源行数不一致。**证据：**提供源、重复、拒绝和接受数量，以及可复现的差异解释。为运行失败指定负责人和响应方式。管道状态成功，不证明业务总数正确。

<a id="dp-900-unit-5"></a>

## 5. 定义一个可信的分析度量

选择报告粒度，例如一次完成的下载事件，并定义带课程与日期背景的事实。规定时区、迟到事件处理和新鲜度。说明哪部分保存数据、哪部分转换、哪部分提供语义模型、哪部分显示报告。按需要完成的工作比较数据湖、仓库和湖仓，而不是按产品名称判断。

**最终证据：**提交存储矩阵、关系草图、管道核对结果和带度量定义的月报样稿。解释 Fabric、Synapse 与 Power BI 的相关作用。找出一个仍需查阅官方指南的问题；好看的样稿不证明云端操作能力或考试准备程度。
