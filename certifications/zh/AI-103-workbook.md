# AI-103 · 高级开发练习册

[指南](AI-103.md) · [十个案例](AI-103-cases.md) · [目录](README.md)

五个跨语言对应单元使用虚构大学笔记和离线请求/响应样例。把候选输出标为**合成**，预期行为标为**预测**。无需云资源、凭据、真实学生记录或服务测量。这些练习训练部分实现技能，不宣称完整覆盖。核验日期为 **2026 年 11 月 1 日**，依据[自 2026 年 4 月 16 日生效的目标](https://learn.microsoft.com/en-us/credentials/certifications/resources/study-guides/ai-103)。

<a id="ai-103-unit-1"></a>

## 1. 固定客户端约定和部署决策

**场景：**笔记应用的 Python 后端必须在复习高峰返回有据答案。定义请求和响应样例，包含身份上下文、请求 ID、课程、状态、答案、引用和错误类别。加入无效 JSON、访问拒绝、超时和不完整输出。依据当前 [SDK 指南](https://learn.microsoft.com/en-us/azure/foundry/how-to/develop/sdk-overview)，建立兼容性清单，记录资源/项目、终结点类型、部署名称、API 代际、包版本和凭据方式。

**证据：**比较两个假设模型的质量、功能支持、容量、延迟和资源使用，把未知项留待验证。**交付物：**带类型的约定草图、四个失败样例，以及有理由的部署决策，不编造限制或价格。

<a id="ai-103-unit-2"></a>

## 2. 设计能够处理访问撤销的检索

**场景：**两名学生共享笔记本，之后撤销其中一人的访问权。虚构六个片段，包括被拟议分块边界拆开的作业限定条件。定义文档和分块 ID、版本、来源位置、ACL 元数据以及索引/嵌入版本。比较关键词、向量和混合检索的预测。按实际顺序绘出调用者认证、权限筛选、检索、缓存查询和模型上下文。

**证据：**撤销前后的访问表，覆盖索引传播、缓存分块和对话记忆，另加一个无支持引用和一个证据不足响应。**交付物：**带权限新鲜度策略、失效规则和四个回归案例的检索设计。解释 [Search 访问模式](https://learn.microsoft.com/en-us/azure/search/search-document-level-access-overview) 如何影响实现选择。

<a id="ai-103-unit-3"></a>

## 3. 跟踪结果不确定的已批准工具操作

**场景：**笔记智能体提出把一份获准文档共享给学习小组。定义工具架构、调用者范围、精确批准载荷、操作键、状态存储、超时预算和对话归属。编写“验证 → 授权 → 批准 → 执行 → 核对 → 报告”的**伪代码**；这是应用设计，不是可执行 SDK 代码。加入保留同样权限的规划器/检索器交接。

**证据：**拒绝、成功执行、重复投递、批准过期以及后端成功后响应丢失的轨迹。**交付物：**状态转换表和脱敏轨迹，说明重试为何不会重复共享。把设计与当前[函数调用边界](https://learn.microsoft.com/en-us/azure/foundry/agents/how-to/tools/function-calling) 联系起来。

<a id="ai-103-unit-4"></a>

## 4. 验证多模态字段和语义

**场景：**作业单包含草稿与最终截止日期，图表有无法辨认的轴，语音问题包含“mutex”。分别定义文本、语音、视觉理解、媒体生成和提取约定。为 Content Understanding 编写字段架构，精确说明描述、类型、空值处理和来源引用。构造有缺陷的合成输出：交换日期、编造单位和误听技术术语。

**证据：**独立的架构、来源、语义和无障碍检查，包含高置信度错误字段及文本纠正后备路径。**交付物：**五个注释样例和用标注样例校准的复核策略。检查[分析器设计](https://learn.microsoft.com/en-us/azure/ai-services/content-understanding/concepts/best-practices)与[文档依据定位可用性](https://learn.microsoft.com/en-us/azure/ai-services/content-understanding/document/analyzer-improvement)，明确模态和 API 限制。

<a id="ai-103-unit-5"></a>

## 5. 评估并演练回退

**场景：**候选版本修改提示词、工具架构和嵌入模型。评分八个固定案例：有支持的答案、来源缺失、访问撤销、注入、错误引用、模糊截止日期、工具超时和重复操作。分别记录检索质量、主张支持、安全、权限合规和延迟预测。说明有界推广及触发恢复的指标。

**证据：**对照表、兼容发布清单、脱敏遥测架构，以及共同恢复客户端、索引、提示词和工具的回退顺序。**交付物：**可审核发布资料包和仍需获授权云实验的测量清单。利用[评估指南](https://learn.microsoft.com/en-us/azure/foundry/how-to/develop/cloud-evaluation) 区分离线预测与实际部署证据；不能把合成评分当作 Azure 实测结果。
