# AZ-900 · 八语共同进阶练习册

[←](README.md) · [共同学习核心](../../zh/16-common-core.md) · [进阶实验](../../zh/17-advanced-labs.md)

八种语言具有对应的目标、案例和交付物。按学习单元及验证证据检查等价性，而不是比较字数。原有指南仍作为补充说明保留。

<a id="az-900-unit-1"></a>

## 1. 分配责任

为同一需求比较 VM、托管平台和已有订阅软件。列出操作系统、依赖、数据、访问与恢复责任。没有完全免责任的方案，关键是所需控制与团队运维能力。

**案例：**库要求安装系统驱动，哪个方案不再合适，为什么？**证据：**责任矩阵，以及因具体要求被排除的备选方案。

<a id="az-900-unit-2"></a>

## 2. 可用性与边界

区分进程、实例、可用区和区域故障。多个实例仍可能共享关键依赖。说明切换实例时会话和文件如何处理。组件 SLA 不等于整个应用的可用性。

**案例：**四个 API 依赖没有恢复方案的单一数据库。**证据：**完整请求路径、薄弱依赖和验证测试。

<a id="az-900-unit-3"></a>

## 3. 选择数据和连接

区分对象、关系元数据与共享文件，定义读、写、授权和恢复。公共不等于匿名，私有 DNS 不授予权限。

**案例：**教师能打开文档，另一用户收到403。**证据：**分别针对网络、身份和授权提出假设，并说明能证实每项的观察结果。

<a id="az-900-unit-4"></a>

## 4. 治理与估算

RBAC 管操作，Policy 管资源条件，标签分类。预算告警不等于停止所有费用。用明确假设估算容量、操作、传输、日志和备份。

**案例：**只允许批准区域，并按学院归集成本。**证据：**治理规则、最小角色，以及不虚构价格的计费单位表。

<a id="az-900-unit-5"></a>

## 5. 解释与验证

区分部署、功能和恢复。资源创建不证明能下载，备份任务不证明及时恢复。使用业务信号而不只看 CPU。

**交付：**架构图、五项理由、容忍故障、剩余责任和清理计划。改变要求后重新回答；如果答案始终不变，需要检查是否真正分析。
