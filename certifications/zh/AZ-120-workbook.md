# AZ-120 · 通用高级练习册

[指南](AZ-120.md) · [10 个案例](AZ-120-cases.md) · [目录](README.md)

五个跨语言对应单元。围绕虚构大学的采购、财务 SAP 环境与研究门户集成离线工作。不提供或宣称许可证、Azure 部署、SAP 执行或生产就绪。区分假设、预测结果与观测证据。

<a id="az-120-unit-1"></a>

## 1. 清点责任与受支持容量

绘出生产与非生产 SID、应用服务器、ASCS/ERS 或 SCS、HANA、共享文件、身份、DNS 和接口。指定基础设施、操作系统、Basis、数据库、安全和业务验证负责人。解释应用服务器冗余为何仍留下其他单点故障。规模表应包含相关 SAPS、内存、增长、吞吐量、延迟和故障余量；SKU 选择仍以认证和兼容检查为条件。

**场景：**较便宜 VM 核数相同，却没有 HANA 支持证据。**证据：**依赖图、受支持 VM/操作系统/数据库/存储组合、区域配额假设和许可审查负责人。**交付物：**说明验收条件和未解决测量的架构决定。复习[计算基础](../../zh/03-compute.md)。

<a id="az-120-unit-2"></a>

## 2. 设计放置、网络与 HANA 存储

绘出受支持应用到数据库路径，以及管理、复制、备份、校园连接和 DNS 转发。区分专用 ExpressRoute 与选定加密控制。用明确延迟假设比较可用区隔离与 PPG 共址约束。规划 `/hana/data`、`/hana/log`、`/hana/shared`、受支持文件系统、磁盘及 VM I/O 上限，以及配置特定的缓存或 Write Accelerator 决策。

**场景：**保存点与采购变慢同时发生，有人建议在 SAP 应用与数据库间放置检查设备。**证据：**流量路径、放置图、预计延迟预算、卷角色表和所需 I/O 观察。**交付物：**含容量与故障域权衡的受支持替代方案。复习[网络基础](../../zh/05-networking.md)。

<a id="az-120-unit-3"></a>

## 3. 区分安全故障转移与历史恢复

解释 HANA System Replication、受支持集群控制、ASCS/SCS 保护、ERS、仲裁、fencing、虚拟名称和负载均衡器探测。绘出网络分区后唯一允许写入者。定义业务 RPO、RTO、工作负载一致备份、可用日志、保留和恢复依赖。说明复制为何会复制错误，以及未协调快照为何不能证明应用一致性。

**场景：**对端无法被隔离，而财务错误已经复制。**证据：**预计集群决策、隔离依赖、权威副本规则、备份/日志可用性和恢复验证条件。**交付物：**独立 HA 与恢复运行手册，明确拒绝通过禁用 fencing 修复，并加入历史恢复后的业务对账。

<a id="az-120-unit-4"></a>

## 4. 编写迁移与集成运行手册

评估源支持、版本、接口、变化速率、传输耗时、停机和目标兼容性。选择并解释受支持迁移方式。定义演练、写入冻结、最终同步、源隔离、DNS/接口变更、技术检查、业务验收和重新开放写入。对 RISE，依据合同分配客户集成与 SAP 管理责任，不能假设订阅访问权。

**场景：**切换后用户创建采购订单，随后研究门户失败。**证据：**写入归属时间线、队列状态、接口交接点、验证关口和决策负责人。**交付物：**新写入前的回退，以及写入后的独立对账或反向迁移决策；如果失败边界属于 RISE，包含 SAP 升级处理。

<a id="az-120-unit-5"></a>

## 5. 审查运维并演练区域恢复

审查虚构 IaC 变更的映像支持、放置、存储、秘密引用、依赖和破坏性差异。按集群顺序分阶段更新，并设置回退条件。规定 Azure Monitor 采集、SAP 监控提供程序、数据库与集群证据、警报负责人和保留。恢复备用区域完整服务，涵盖身份、网络、中央服务、应用、数据、集成和返回主区域同步。

**场景：**采购期间区域中断，同时存在待批准的大小调整建议。**证据：**依赖顺序、预计 RPO/RTO、故障容量、复制状态、业务流程检查，以及持续计算/存储/网络/监控成本负责人。**交付物：**事故桌面演练与变更审查记录，区分计划检查和已执行测试。

用[指南](AZ-120.md)中的六项技术参考质疑假设。这些原创练习选择有用概念，不覆盖全部官方目标，也不保证考试结果。
