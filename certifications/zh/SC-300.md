# SC-300 · 身份和访问管理员

[认证](README.md) · [十个案例](SC-300-cases.md) · [练习册](SC-300-workbook.md)

SC-300 研究 Microsoft Entra 身份如何获得、使用和失去访问权限。对于我们的大学笔记应用，我会从一个具体请求开始：哪位学生、来宾、管理员或后台工作进程，需要执行什么操作，以及需要多久？

参考资料核对日期为 **2026-11-01**：[官方学习指南](https://learn.microsoft.com/en-us/credentials/certifications/resources/study-guides/sc-300)，目标自 **2026-10-28**起生效。对应证书：[Identity and Access Administrator Associate](https://learn.microsoft.com/en-us/credentials/certifications/identity-and-access-administrator/)。

指南列出的用户身份、工作负载身份和身份治理三个领域，**各占 20–25%**。来源中关于身份验证和访问管理的比重存在差异：摘要写的是 **25–30%**，但详细标题写的是 **20–25%**。这些笔记保留该差异；请查看当前官方指南，不要自行假定已修正的比重。本地化考试更新可能遵循不同时间表。

这些是原创学习笔记和假设练习，不是官方试题，不代表完整覆盖全部目标，也不是执行过租户操作的证据。

## 1. 明确租户和权限边界

租户是身份边界；Azure 订阅是资源管理边界。Entra 目录角色管理目录功能，而 Azure RBAC 角色在指定范围内应用于 Azure 资源。两者都不会自动使某人成为我们应用中的课程编辑者。

评估直接分配、组、继承的资源分配、已激活的特权分配和应用角色共同形成的有效访问权限。移除一条路径后，另一条可能仍然存在。管理单元可以将支持的目录管理限定在选定对象上；它们不会隔离某个院系的所有数据。记录组类型、成员资格来源、所有者，以及谁可以更改成员资格。结合[身份笔记](../../zh/06-identity.md)比较这些边界。

## 2. 区分协作与混合身份同步

访问学者可以使用来宾身份，而不必成为不受限制的大学成员。跨租户设置区分入站访问、出站访问，以及是否信任另一组织指定的 MFA 或设备声明。信任声明并不等于赋予文档权限。检查主租户、资源租户、目标应用、邀请限制和来宾生命周期。[跨租户访问](https://learn.microsoft.com/en-us/entra/external-id/cross-tenant-access-overview)。

混合身份关注将本地身份基础结构与 Entra 连接。Connect Sync 和 Cloud Sync 需要有意识地选择权威来源及所支持的功能。密码哈希同步、直通身份验证和联合涉及身份验证架构；同步账户本身并不能建立合适的访问权限。在提出迁移方案前，规划匹配、删除处理、依赖关系和运行状况监测。

## 3. 规划注册、强身份验证和恢复

MFA 方法提供不同保护。对于敏感管理操作，应评估支持的通行密钥、Windows Hello for Business 或基于证书的身份验证等抗钓鱼选项，同时考虑设备和部署约束。完成注册本身不能证明策略要求使用该方法。SSPR 也需要合适的注册和恢复设计。

临时访问密码是一种有时间限制的初始引导或恢复凭据，用于注册其他方法。允许的用户、有效期、使用设置、身份核验和安全交付都很重要。我们的笔记本只记录拟议流程，绝不保存真实密码或导出的密码。正常方法丢失后，恢复机制仍必须可用。[身份验证概述](https://learn.microsoft.com/en-us/entra/identity/authentication/overview-authentication) · [临时访问密码](https://learn.microsoft.com/en-us/entra/identity/authentication/howto-authentication-temporary-access-pass)。

## 4. 将条件访问描述为有明确范围的决策

在说“要求 MFA”之前，先写清目标身份、资源、条件、授予控制、会话控制和排除项。针对访问笔记 API 的编辑者制定规则，不能证明大学所有应用都受保护。必须一并考虑多项适用策略，而应用授权仍决定编辑者可以修改哪份笔记。

为离线上线计划规定试点、预期允许和拒绝的请求、仅报告分析、管理员恢复及回滚负责人。仅报告策略记录评估结果，但不强制执行其控制。排除项需要明确理由和复核；一个很大的排除组可能使设计失效。检查适用的许可和依赖关系。[条件访问概述](https://learn.microsoft.com/en-us/entra/identity/conditional-access/overview)。

## 5. 区分用户风险和登录风险

用户风险关注身份已遭入侵的可能性；登录风险关注某一次身份验证请求。因此，可疑登录和长期遭入侵的账户需要相关但不同的调查。任何一个分数都不能回答某位讲师是否仍需要访问上学期的课程。

记录检测、时间戳、受影响身份、身份验证详情及调查人员结论。基于风险的策略可以在其配置和前提条件允许的情况下要求适当补救。不要只是为了清空仪表板而忽略信号，也不要假定每个异常位置都证明入侵。工作负载风险能力另有范围和许可方面的考虑。[ID Protection](https://learn.microsoft.com/en-us/entra/id-protection/overview-identity-protection)。

## 6. 识别应用对象及其权限

应用注册在其主租户中定义应用身份配置。服务主体代表该应用在某个租户中的本地使用；“企业应用程序”呈现这种本地管理上下文。托管身份也有服务主体，其凭据由平台管理。它们仍然需要刻意限定范围的权限。

委托权限代表已登录用户操作，访问受相关权限模型约束。应用程序权限允许工作负载脱离该用户上下文操作，并需要管理员同意。审核 API、权限类型、同意授予、所有者和业务目的。添加请求的权限与授予同意是两个步骤。后台索引器不应继承某位人类管理员的账户。[应用对象和服务主体](https://learn.microsoft.com/en-us/entra/identity-platform/app-objects-and-service-principals)。

## 7. 区分联合、预配与授权

工作负载身份联合可以将外部提供程序的令牌换为 Entra 令牌，而无需维护存储的客户端机密。配置的颁发者、主体和受众必须与传入断言匹配，包括大小写。接受令牌验证了工作负载的身份；由此得到的身份仍需要最小资源权限。审核虚构构建环境的声明，不要把真实令牌复制进笔记。[联合概念](https://learn.microsoft.com/en-us/entra/workload-id/workload-identity-federation)。

对于连接的学习平台，SAML 或 OpenID Connect SSO 负责登录。SCIM 预配负责创建、更新或移除账户及属性。SSO 成功不代表取消预配正常工作。记录映射、分配范围、预配失败，以及访问授权到期时会发生什么。

## 8. 治理特权与普通访问授权

PIM 资格允许在配置的条件下激活；有效分配才使特权可用。符合资格的分配和有效分配都可以有时间限制。检查角色、范围、审批、身份验证和持续时间：即使持续时间很短，范围过大的角色仍然过度授权。

访问评审询问现有访问是否仍有正当理由。权利管理通过请求、审批、到期和评审策略打包资源。生命周期工作流通过定义的触发器自动执行受支持的入职、调岗和离职任务。这些机制互为补充；完成评审不会激活管理员。记录资源所有者、自动化失败处理，以及已批准的移除确实生效的证据。检查具体功能的许可证和受益人要求，不要假定一个订阅就能解锁全部治理能力。[身份治理](https://learn.microsoft.com/en-us/entra/id-governance/identity-governance-overview)。

## 9. 用正确证据进行诊断

登录日志解释身份验证尝试和策略评估；审核日志帮助调查目录更改；预配日志帮助诊断账户生命周期。通过诊断设置进行路由、保留、访问权限和摄取，共同决定可开展哪些分析。空结果不能证明没有事件发生。[监测与运行状况](https://learn.microsoft.com/en-us/entra/identity/monitoring-health/overview-monitoring-health)。

下面的假设 KQL 草图对已摄取的登录分组；它没有被运行过：

```kusto
SigninLogs
| where TimeGenerated > ago(1d)
| summarize Attempts = count()
    by AppDisplayName, ConditionalAccessStatus, ResultType
```

使用前检查表是否可用及其架构。仅靠汇总状态无法解释每一项策略，尤其是仅报告评估；应检查相关事件详情和关联标识符。记录缺失的遥测及其他可能解释。

## 10. 把网络访问与访问生命周期联系起来

Global Secure Access 将面向私有资源的 Entra Private Access 与面向互联网和 SaaS 流量的 Entra Internet Access 结合起来；Microsoft 流量配置文件服务于受支持的 Microsoft 服务。客户端、连接器、流量转发、策略和许可会影响覆盖范围。私有网络路径仍需要身份和应用权限检查。[Global Secure Access](https://learn.microsoft.com/en-us/entra/global-secure-access/overview-what-is-global-secure-access)。

最后离线完成：为学生、来宾、编辑者、管理员和索引工作进程制作访问决策矩阵。添加治理表，包含所有者、授予路径、到期、评审和所需日志。使用[案例](SC-300-cases.md)和[五个练习单元](SC-300-workbook.md)论证每项决策，再对照官方指南找出剩余学习缺口。
