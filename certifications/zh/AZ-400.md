# AZ-400 · 认证考试

[目录](README.md) · [English](../en/AZ-400.md)

考试领域和权重依据2026年10月27日核查的官方英语指南。不同考试语言和日期可能有更新，请在报考前确认。这是独立学习材料，不保证覆盖全部考题或通过考试。

## 学习目标

交付小、可验证、可恢复的变更。流程10–15%，源代码管理10–15%，构建和发布50–55%，安全10–15%，检测策略5–10%。目标自2026年7月27日起适用。

核查的 DevOps Engineer Expert 要求包括 AZ-400，以及 Administrator Associate 或 Developer Associate 之一。请再次确认最新路线。

## 工作与代码

关联 issue、PR、执行记录、制品和发布。统一 lead time、cycle time、失败率、频率和恢复时间的定义。不用提交数量衡量个人价值。

使用短分支和频繁集成，理解 merge、rebase、revert，不擅自重写共享历史。秘密泄漏后先撤销或轮换，再清理文件与历史。

## 构建与发布

推广同一个经过测试的制品。单元、集成、端到端和负载测试覆盖不同风险，高覆盖率不证明断言有价值。

不通过反复执行直到绿色来掩盖不稳定测试。区分缓存与制品。自托管 runner 要维护和隔离。

比较 rolling、blue-green、canary 和 rings，理解 feature flag 与 A/B 的目标不同。数据库变更要考虑新旧版本兼容，旧镜像无法复原被删除的数据。

## 安全与观测

保护 Terraform 状态、连接和秘密。OIDC 仍需信任和权限。资源 checks 不等于作者可改的 YAML 条件。SBOM 是组件清单，不是安全证明。

**交付：**定义有意义的测试、固定制品、审批、发布条件、回滚和发布后的业务信号。Postmortem 的改进要有负责人、期限与验证，而不是只写以后小心。
