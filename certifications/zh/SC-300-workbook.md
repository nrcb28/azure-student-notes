# SC-300 · 访问决策与治理练习册

[指南](SC-300.md) · [十个案例](SC-300-cases.md) · [目录](README.md)

针对虚构大学笔记应用的五个原创离线单元。使用合成身份和文档。不要更改租户策略、创建凭据、激活角色或连接真实遥测。交付物描述预期决策；不声称执行过云端操作。

<a id="sc-300-unit-1"></a>

## 1. 追踪有效访问和身份来源

映射租户、订阅、应用和文档存储。区分目录角色、管理单元范围、Azure 资源与数据角色，以及应用访问授权。包含直接授予和基于组的授予路径，并确定谁控制成员资格。对于混合身份，记录权威来源，以及所选同步和身份验证假设；不要把同步视为授予访问。

**场景：**学生失去直接分配后，仍可以读取课程文件夹。**证据：**一张指出两条可能授予路径的图，以及区分两者所需的记录。**交付物：**一份六行访问决策矩阵，涵盖学生、来宾、编辑者、管理员、索引器和已离开成员，逐项写明最小范围和一次预期拒绝。

<a id="sc-300-unit-2"></a>

## 2. 设计身份验证与条件访问

规定受支持的身份验证方法、注册路径和恢复负责人。解释抗钓鱼性，以及临时访问密码如何在不存储真实密码的情况下引导符合条件的用户。描述策略目标、条件、授予和会话控制、排除项、许可假设和紧急恢复。把仅报告评估与强制执行结果分开。

**场景：**访问学者使用个人设备，而编辑者处理尚未发布的答案。**证据：**三个身份、方法、设备或资源不同的预期请求；分别解释跨租户声明信任与应用授权。**交付物：**拟议策略矩阵及上线说明，包含试点、评审、恢复和回滚标准。不会在真实租户中启用任何内容。

<a id="sc-300-unit-3"></a>

## 3. 选择并约束工作负载身份

比较索引器的应用注册、相应服务主体和托管身份。解释委托权限与应用程序权限、同意及资源范围。针对虚构外部构建，使用编造的声明值记录预期联合颁发者、主体和受众。说明为什么令牌签发成功并不能证明有权部署。

**场景：**索引器只读取已发布笔记，而构建只更新自身的测试应用。**证据：**每项工作负载各一项允许和一项拒绝的操作，以及权限负责人和评审日期。**交付物：**身份选择表和联合信任草图，不包含密码、客户端机密、真实令牌或部署命令。把未经支持的假设记录为向负责人提出的问题。

<a id="sc-300-unit-4"></a>

## 4. 构建访问授权与特权生命周期

把 PIM 资格、激活和有效持续时间与定期访问评审区分开。为访问学者提出访问包，并为入职、调岗和离职人员提出受支持的生命周期自动化。区分 SSO 联合与 SCIM 预配，并解释如何确认下游移除。列出各功能的许可假设及自动化失败负责人。

**场景：**讲师的学期结束，同时管理员需要临时维护访问。**证据：**一次到期决策、一次资源所有者评审、一份范围明确的激活提议，以及一条下游预配完成记录。**交付物：**治理表，列出触发器、审批者、访问授权、持续时间、评审、预期移除、证据和例外处理。完成评审并不是角色已激活的证据。

<a id="sc-300-unit-5"></a>

## 5. 依据有边界的证据解释失败

区分用户风险、登录风险、策略评估、目录更改和预配失败。选择相关日志，并描述诊断路由、保留、访问和架构假设。为指南中的假设 KQL 查询添加注释，说明其聚合能够和不能证明什么。只有在资源路径确实需要相应用途时，才加入 Private Access、Internet Access 或 Microsoft 流量配置文件。

**场景：**来宾无法打开课程，但仪表板没有匹配的失败记录。**证据：**假设时间线、覆盖缺口、关联字段，以及两种相互竞争的解释。**交付物：**一页诊断和证据清单，连接身份、网络路径、策略、应用访问授权和预配。将每项结果标为预期；不执行查询或租户测试。
