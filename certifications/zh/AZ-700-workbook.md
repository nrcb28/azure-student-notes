# AZ-700 · 共同进阶练习册

[指南](AZ-700.md) · [十个案例](AZ-700-cases.md) · [目录](README.md) · [网络实验](network-lab.md)

五个单元在八种语言中对应相同目标、场景与交付物。这是设计和诊断练习。预测不是 Azure 观察，也没有声称完成新部署。

<a id="az-700-unit-1"></a>

## 1. 制定地址与依赖规划

为笔记应用设计校园、中心、Web 和数据网络。选择新 CIDR 前清点已有范围，为增长和服务专属子网预留空间。解释普通 /24 在 Azure 可分配的 IPv4 地址为什么少于原始总数。不要假设任何空子网都适合委派服务。

**场景：**合作方使用的范围与拟建中心网络重叠。**证据：**包含所有者、前缀、用途、限制和增长空间的表。**交付物：**修订后的非重叠设计，指出已移除的冲突，以及仍需在当前服务文档核对的一项限制。

<a id="az-700-unit-2"></a>

## 2. 追踪请求与响应

画出 API 调用从 Web 辐射网络经过检查设备到另一网络目标的路径。逐步写出目标前缀、下一跳和相关转发设置。单独画回程；有状态检查与地址转换可能使表面合理的不对称路线失败。只有对等互连，不能让中心网络变成中转路由器。

**场景：**UDR 修改后，源端发出请求却收不到响应。**证据：**竞争路由与两个方向的有效下一跳。**交付物：**一个可验证假设、确认观察，以及拟议修改的回滚条件。

<a id="az-700-unit-3"></a>

## 3. 分层诊断专用访问

描述校园客户端怎样通过选定 DNS 与转发设计解析存储主机名。标出专用终结点的服务子资源、专用地址、批准状态和预期网络限制。将名称解析、可达性、TLS 与数据权限分开；证明一层不代表证明其余各层。

**场景：**公共访问关闭，但调用者仍解析到公共地址。**证据：**主机名、解析器路径、返回地址和预期专用目标。**交付物：**DNS 纠正方案，以及随后验证路由和带身份验证数据访问的检查。解释为什么永久覆盖成公共 IP 不合适。

<a id="az-700-unit-4"></a>

## 4. 选择交付与保护控制

比较 TCP 服务、区域 Web 应用与全球 Web 应用。按协议、范围、路由要求和故障行为选择候选，而不是按记住的产品标签。包括探测行为和证书处理。区分 DNS 选择与请求代理，以及 WAF 检查、网络过滤和 DDoS 可用性防护。

**场景：**后端通过健康探测，文档下载却错误。**证据：**探测测试什么，真实操作又验证什么。**交付物：**简短决策记录，排除一个替代方案，并定义能停止错误版本继续发布的功能信号。

<a id="az-700-unit-5"></a>

## 5. 设计并验证混合恢复

规划校园主连接与备份连接。列出相关故障、路由变化、加密要求、容量和应用依赖。ExpressRoute 的专用性不代表默认加密。明确保护边界和兼容加密设计，不要假设所有线路类型支持相同选项。

**场景：**大量学生下载笔记时主连接失败。**证据：**预期去程与回程、备用容量假设，以及可度量的应用恢复标准。**交付物：**隔离测试计划、恢复正常步骤和预期与观察两列。如果没有获授权环境，提交设计，并明确把观察项标为未测试。
