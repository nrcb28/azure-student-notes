# SC-900 · 安全、合规与身份基础

[认证路线](README.md) · [案例](SC-900-cases.md) · [练习册](SC-900-workbook.md)

SC-900 把安全理念与 Microsoft Entra、Azure、Microsoft 365、Defender、Sentinel 和 Purview 联系起来。我会围绕三个问题学习：控制措施解决什么问题、产生什么证据、又做不到什么。认识产品名称只是起点。

## 1. 责任与边界防护的局限

假设大学笔记应用运行在托管基础设施上。Microsoft 负责底层平台，但谁能查看尚未发布的考试解答，仍由我们决定。责任会随服务模式变化；外包基础设施，不等于把身份、数据、配置和使用方式的所有决策一起外包。

纵深防御组合权限、设备控制、网络边界、应用检查、加密、监控与响应。一层成功，不证明所有层都有效。零信任提供一个有用习惯：验证请求、限制权限，并按可能已被入侵来准备。接入校园 Wi-Fi 不应获得无限访问。[零信任参考](https://learn.microsoft.com/en-us/security/zero-trust/zero-trust-overview)。

## 2. 谁在连接，可以做什么？

身份验证确认身份，授权决定该身份能否执行动作。因此登录成功后仍可能访问被拒。修改权限前，应记录身份、资源、动作和范围。

Entra ID 表示人员和工作负载。员工、来宾、应用、服务主体与托管身份有不同用途和生命周期。托管身份让支持的工作负载获取令牌，而不用在应用中保存客户端机密，但仍需要相应权限。Entra 目录角色和 Azure 资源角色管理不同对象。用户管理员不会自动成为所有学生文档的读者。可回看[身份笔记](../../zh/06-identity.md)理解这些边界。

## 3. 凭据、MFA、哈希与加密

两个密码仍是同一类因素。MFA 组合不同因素类别，但各种方式抵抗钓鱼的能力并不一样。对特权访问，应评估支持的抗钓鱼方法和恢复流程，而不是认为多一个提示框就有相同保护。用户注册、设备支持和实际策略执行都重要。

加密通过密钥保护数据，获授权后可以恢复原文。密码学哈希产生用于比较的摘要，不是可逆加密。文件摘要相同，可在选定假设下支持内容一致的判断，却不能证明作者。密码存储需要合适的密码哈希设计，包括盐和工作因子；本笔记不是自行搭建身份验证系统的配方。

## 4. 条件访问是一套决策策略

条件访问将信号与访问控制组合起来。例如财务应用可以要求适当的身份验证强度和合规设备。要描述目标身份、应用、条件、授予控制和排除项。一条只针对某应用的策略，不能证明所有应用都受到保护。

它不能替代应用权限或拒绝服务防护。提出上线方案时，应采用假设的小范围试点和仅报告分析，评估应允许、应阻止的情况、管理员恢复和依赖。本指南不要求开启覆盖整个租户的规则。[条件访问参考](https://learn.microsoft.com/en-us/entra/identity/conditional-access/overview)。

## 5. 特权、访问复核与身份风险

PIM 处理应以符合条件或限时方式提供、而不是永久激活的特权访问。激活可以要求审批、理由和身份验证。符合条件不等于角色已经激活，时间短也不代表范围过大的角色合理。

访问复核询问已有权限是否仍然必要。ID Protection 识别身份风险信号；风险检测是调查线索，不是每个事件的完整解释。它们能协同，但回答的问题不同：谁可以激活、谁应保留访问、哪些身份行为可疑？[PIM 参考](https://learn.microsoft.com/en-us/entra/id-governance/privileged-identity-management/pim-configure)。

## 6. Azure 安全需要多层配合

网络安全组过滤适用的网络流量。Azure Firewall、Web 应用防火墙和 DDoS 防护用途不同，任何一项都不会自动赋予正确的应用授权。专用终结点改变网络路径，但 DNS 与身份控制仍需分别配置。

Defender for Cloud 帮助评估云安全态势，并通过适用计划提供工作负载保护。建议项表示某种状态值得评估；点击开启产品，不证明问题已修复。对于笔记应用，应区分暴露管理端口、身份权限过大、应用返回另一位学生文件三类问题。它们需要不同证据和负责人。

## 7. 跨产品检测与响应

Defender XDR 关联已接入且受支持的 Microsoft 安全产品信号，帮助调查有关活动。例如邮件、身份事件和终端告警可能是同一次攻击的不同部分。但从未发送必要数据的传感器，无法凭空参与关联。[Defender XDR 参考](https://learn.microsoft.com/en-us/defender-xdr/microsoft-365-defender)。

Sentinel 提供 SIEM 能力，跨来源收集、分析安全数据，并提供响应自动化与编排选项。SIEM 关注信息与事件管理，SOAR 关注协调响应工作流。要定义连接器、规则、保留期、权限和响应负责人。自动禁用账户比通知分析师需要更谨慎地设计。[Sentinel 参考](https://learn.microsoft.com/en-us/azure/sentinel/overview)。

## 8. Purview：区分保护措施与调查证据

敏感度标签分类内容，并可在支持的位置应用已配置的保护。DLP 检查敏感数据的处理方式，对匹配活动发出警告或实施限制。标签名叫 Confidential，不代表它单凭名称就阻止所有外部共享。

保留策略按适用规则保存或删除内容。审核记录活动，电子数据展示帮助为调查查找、保留和复核信息。它们都不等于备份策略。Compliance Manager 可以组织改进事项和评估，但仪表板分数不构成法律上的合规认定。应从具体数据义务、负责人、范围和证据开始。[Purview 概述](https://learn.microsoft.com/en-us/purview/purview)。

## 9. 不修改租户的实践练习

画一个虚构流程：来宾下载课程笔记，编辑者上传解答，管理员管理访问。使用合成文档名，不包含个人信息。标出信任边界，并在每一步找一个威胁。

为每个威胁写出预防控制、检测信号、负责人和恢复动作。增加一个预期失败：来宾不应下载尚未发布的解答。解释拒绝请求、审核事件或告警中的哪一种证据能支持判断。这些是预期结果，不是观察到的 Azure 结果。提交图示和六行证据表；本练习不启用策略，也不部署服务。

## 10. 实践前核对覆盖范围与前提

许可证、服务计划、支持的工作负载、角色和接入情况，决定实际能使用什么。熟悉的门户截图不能证明已获得使用权益。提出部署或估算运维投入前，核对具体能力；这里不假设任何价格。
