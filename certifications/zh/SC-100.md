# SC-100 · Microsoft 网络安全架构师

[认证](README.md) · [十个案例](SC-100-cases.md) · [练习册](SC-100-workbook.md) · [Español](../es/SC-100.md)

SC-100 要求我把安全决策与业务结果联系起来。虚构的大学笔记应用现已横跨校园基础设施、Azure、另一朵云、Microsoft 365 和 AI 学习助手。购买控制措施容易，说明每项风险由谁负责，以及整个服务如何保持安全和可恢复更难。

参考资料核验于 **2026-11-01**：[官方学习指南](https://learn.microsoft.com/en-us/credentials/certifications/resources/study-guides/sc-100)，目标自 **2026-10-21** 起生效。

| 官方领域 | 权重 |
|---|---|
| 安全最佳实践与优先级 | 20–25% |
| 安全运营、身份与合规能力 | 25–30% |
| 基础设施安全 | 25–30% |
| 应用与数据安全 | 20–25% |

[Cybersecurity Architect Expert 认证](https://learn.microsoft.com/en-us/credentials/certifications/cybersecurity-architect-expert/) 要求通过 SC-100，并取得 Identity and Access Administrator Associate、Security Operations Analyst Associate 或 Cloud and AI Security Engineer Associate 中的**至少一项**。并非三项都需要。规划路线前请重新核对认证页面。

这些原创笔记和离线练习用于辅助学习，不是官方试题、完整目标覆盖、已执行云变更或通过承诺。本地化考试更新可能采用不同日程。

## 1. 从关键服务和责任人开始

我会先确定大学必须保护什么：已发布笔记、未公开考核答案、学生记录，以及事故期间继续教学的能力。业务关键性与技术资源大小应分开分类。一个很小的身份依赖也可能中断全部课程。

针对每个威胁，记录受影响业务、影响、可能性假设、现有控制、残余风险和具体风险负责人。安全团队可以推荐控制；授权业务负责人决定是否接受剩余风险。定义可测量验收标准，例如在约定时间内恢复获授权文档读取。在[架构决策记录](ADR-template.md)中保留决策和被否决选项。产品名称或仪表板分数不能代替这套论证。

## 2. 用参考框架解决不同决策

[MCRA](https://learn.microsoft.com/en-us/security/adoption/mcra) 帮助映射整个环境的安全能力与集成关系。[MCSB](https://learn.microsoft.com/en-us/security/benchmark/azure/overview) 帮助把能力转化为控制要求和实施指导。两者都不会自动决定大学的优先级。

用 [CAF 登陆区域](https://learn.microsoft.com/en-us/azure/cloud-adoption-framework/ready/landing-zone/)分配平台护栏和工作负载责任；用 [Well-Architected 安全指南](https://learn.microsoft.com/en-us/azure/well-architected/security/)审查工作负载决策及其权衡。建立覆盖表：要求、控制、范围、负责人、证据和缺口。继承策略可能管辖生产订阅，却不覆盖院系 SaaS。应记录边界，不能凭一次成功评估宣称全校覆盖。

## 3. 让零信任跨越每个边界

连接校园网不代表可信。评估身份、设备、资源、请求上下文和应用授权，遵循最小权限并假设已遭入侵。网络分段减少可达路径，却不决定学生是否能读取另一学院的受限资料。

在浏览器、API、文档存储、管理平面、外部协作者和 AI 检索服务周围画出信任边界。区分身份验证与授权、数据平面访问与资源管理。说明条件访问、应用权限、终端状态和网络控制分别在哪里发挥作用。为重要请求描述预期允许与拒绝、所需证据及一种失败方式。访问设计还应包含可用性与管理员恢复。

## 4. 保护人员、工作负载和智能体权限

区分普通用户、外部研究者、管理员、部署管道、索引器和智能体。提出限定范围角色、限时特权激活、受保护管理设备、访问评审和带监控的紧急访问。校园目录遭入侵可能影响云恢复，因此要涵盖混合身份依赖和加固要求。

适用时优先使用平台管理的凭据或联合身份，并明确资源权限与生命周期负责人。智能体身份，包括适用的 Microsoft Entra Agent ID 能力，需要受限工具、访问策略和责任归属；给智能体命名不代表授权所有操作。记录许可证和功能假设。这里保留设计层权限要求，详细身份管理决策可学习 [SC-300](SC-300.md)。

## 5. 设计具有响应权限的 SOC 能力

Microsoft Defender XDR 与 Microsoft Sentinel 可提供检测、关联、调查和响应。架构必须定义哪些校园、云、身份、终端和 SaaS 信号真正送达，以及延迟、保留、访问限制和运营成本。纸面配置连接器不证明遥测可用。

把优先威胁映射到相关 MITRE ATT&CK 技术、预期信号、检测逻辑、分诊与响应。指出未覆盖路径。明确谁能隔离教学服务器、禁用账户或批准自动遏制，尤其在考试期间。加入升级处理、回退和证据保全。[SC-200](SC-200.md)训练分析员工作流；架构任务是在明确覆盖与权限边界内，让这些工作流可行。

## 6. 把数据义务转为独立控制

选择保护方式前，先发现并分类公开笔记、未发布解答、个人记录和研究资料。[Microsoft Purview Information Protection](https://learn.microsoft.com/en-us/purview/information-protection) 支持发现、分类、敏感度标签和保护能力。核对支持的位置、应用和许可证。

区分分类结果与已应用标签、标签与其配置的加密，以及 DLP 与全面阻止泄露。静态加密无法阻止获授权应用导出明文。保留策略管理保存和删除，法律保全与调查另有要求。将每项义务映射到控制范围、责任人、证据和复核。基准映射、合规分数和已部署产品辅助评估，但不能保证法律合规。法律和隐私负责人必须解释大学的义务。

## 7. 覆盖混合基础设施和网络依赖

清点服务器、学生设备、容器、SaaS、实验室 IoT 或 OT，包括未纳管和不受支持资产。按资产风险和受支持范围选择态势与工作负载保护。Defender for Cloud、Azure Arc、终端管理和专用 IoT 保护作用不同；纳管某类资产不能证明处处受保护。

为笔记 API 画出入口、出口、分段、专用终结点、DNS 解析、远程管理和跨云路径。专用终结点不会自动禁用公共访问或配置校园 DNS。包括证书和密钥归属、轮换、访问与中断行为。优先处理通向关键资产的可利用路径，而非只美化分数，并记录遗留系统的补偿控制。

## 8. 纳入软件供应链和 AI 边界

对源代码变化、依赖、构建运行器、制品库、部署身份、API 和生产发布进行威胁建模。提出评审、依赖与秘密扫描、来源验证、制品保护和限定部署权限。指定例外与修复负责人；没有负责人的扫描仍有流程缺口。

AI 助手新增检索文档、模型输入、工具响应和工具执行等边界。将检索文本视为不可信数据。[Prompt Shields](https://learn.microsoft.com/en-us/azure/foundry/openai/concepts/content-filter-prompt-shields) 可以检测提示词和文档攻击模式，但检测不是授权边界，也不保证事实正确。检索仅限获准课程，最小化工具权限，重要操作需批准，并用合成内容设计评估。检查具体集成支持的控制。

## 9. 恢复应用及其控制平面

练习为获授权文档读取设置两小时恢复时间目标（RTO）和十五分钟恢复点目标（RPO）。这些是待验证要求，不是产品承诺。优先梳理恢复该操作所需的身份、DNS、密钥、配置、数据库、文件和部署制品。

设计受保护备份，包含适当隔离、受支持的不可变性、独立管理、监控和可恢复密钥依赖。仅有复制可能传播损坏或恶意删除。描述干净恢复环境，以及特权账户被入侵时管理员如何重获可信控制。文件恢复成功不能证明应用恢复。桌面演练应明确恢复顺序、完整性检查、凭据恢复、批准，以及如何测量耗时和恢复数据。

## 10. 用证据论证分阶段实施

大学无法在下学期前更换所有遗留系统。按风险降低、成本、许可、人员能力、用户影响和恢复复杂度比较方案。初期可能先保护特权访问和备份，再扩大检测覆盖、现代化院系应用。依赖关系决定顺序。

每阶段都应明确试点边界、负责人、验收证据、回退条件，以及经风险负责人批准且有到期日的例外。比较迁移前后预期控制覆盖，避免把采购等同于有效。最终用 ADR 说明选择路径和剩余风险，再通过[案例](SC-100-cases.md)和[练习册](SC-100-workbook.md)检验。重读官方指南，识别其余学习缺口。
