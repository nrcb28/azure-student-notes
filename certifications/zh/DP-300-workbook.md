# DP-300 · 共同运维练习册

[指南](DP-300.md) · [十个案例](DP-300-cases.md) · [目录](README.md)

五个单元在八种语言中具有对应目标和证据要求。必要时可以不使用 Azure 完成设计练习。将预期行为与实际观察分开。不声称已执行 Azure，也不保证覆盖全部考试范围。

<a id="dp-300-unit-1"></a>

## 1. 为平台与迁移选择提供理由

为笔记应用建立要求表：必要数据库功能、操作系统访问、实例依赖、可接受写入中断、维护负责人和恢复目标。按这些要求比较 SQL Database、Managed Instance 和 VM 上的 SQL Server，不因熟悉名字就加分。

**案例：**既有计划任务依赖操作系统工具。**证据：**判断依赖是否仍必要，提出受支持目标或重新设计，并确定兼容检查。**交付物：**迁移步骤，包含初始传输、停止写入、验证、切换、回滚负责人，以及切换后新增写入的处理。复制完成不等于验收通过。

<a id="dp-300-unit-2"></a>

## 2. 区分访问与保密边界

画出应用身份到表上获准操作的路径。标明名称解析、网络访问、身份验证、数据库主体和对象权限。分开应用、部署和紧急管理职责。说明查询、日志、导出和备份中允许出现什么数据。

**案例：**专用连接正常，但应用读不了自己的表。**证据：**实际身份、数据库、对象和被拒操作；不能靠扩大公共网络代替诊断。**交付物：**最小权限设计，并针对具体保密要求比较传输加密、TDE、Always Encrypted 和掩码。包括密钥恢复与归属。

<a id="dp-300-unit-3"></a>

## 3. 诊断可测量的性能回退

为文档权限查询虚构两个可比较负载窗口，包含耗时、读取量、CPU、并发和计划标识。写出把变化与证据关联的假设，再写一项能推翻它的观察。除可用 Query Store 历史外，还应包含阻塞和事务时长；平台指标正常或某计划算子看似昂贵，都不能单独确定原因。

**案例：**新索引改善读取，却拖慢导入。**证据：**代表性负载下两种操作的前后结果。**交付物：**一个可逆调优实验、验收阈值、回滚步骤和证据限制。不要把收缩或终止所有会话作为日常维护方案。

<a id="dp-300-unit-4"></a>

## 4. 让自动化可观察、可重复

按任务内容和目标平台分类夜间工作。比较适用于受支持 SQL Server 或 Managed Instance 负载的 SQL Agent，与适用于 SQL Database T-SQL 工作的 Elastic Jobs。规定身份、目标集合、调度、超时、重试预算和失败通知。外部依赖可能需要更广的编排器。

**案例：**任务已提交输出，但丢失成功响应。**证据：**解释重跑如何避免重复业务结果，以及运维人员如何确认完成。**交付物：**待处理、运行、完成和不确定工作的状态表，加上合成数据测试计划。调度器调用成功，不能与业务结果已验证混为一谈。

<a id="dp-300-unit-5"></a>

## 5. 同时恢复数据与完整服务

分别定义误删除和区域故障。按各自解决的问题选择历史恢复状态与可用性机制。以笔记应用定义 RPO 和 RTO，再列出恢复所需权限、目标容量、终结点、DNS、身份验证与依赖。复制可以传播不希望发生的已提交修改。

**案例：**新主库健康，用户仍不能下载笔记。**证据：**功能检查和包含重连的计时步骤。**交付物：**隔离还原验证计划、故障回复前的权威副本决定，以及保留数据清理负责人。适当环境中实际观察前，将拟议耗时标为 EXPECTED（预期）；桌面推演不能测量 Azure 恢复。
