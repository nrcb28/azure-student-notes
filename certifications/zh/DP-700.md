## 1. 绘出 Fabric 的边界

Microsoft Fabric 是 SaaS 分析平台，不是 Azure Synapse Analytics 的另一个名字。概念相似不能证明运行时、权限或部署行为相同。OneLake 提供公共逻辑数据湖，各工作负载提供不同的数据处理与消费方式。

工作区组织湖屋、笔记本、仓库和管道等项。容量提供共享计算资源，并非保存文件的文件夹。区分租户设置、工作区配置、项定义、已存数据和运行中的作业。为应用画出选课来源、原始落地区、整理表和报表使用者。选择工具前，标注每个边界的负责人及新鲜度要求。[Fabric 概述](https://learn.microsoft.com/en-us/fabric/fundamentals/microsoft-fabric-overview)。

## 2. 选择存储和表语义

湖屋适合文件摄取、Spark 工程处理与 SQL 消费相结合的工作流。仓库适合以 T-SQL 为中心的关系分析。比较支持的操作和团队要求；名称本身不保证性能。湖屋 SQL 分析终结点是查询界面，不能当作可互换的仓库写入引擎。

Delta 表将列式数据文件与事务日志结合。任意 Parquet 文件目录不具备这种表的事务语义。有重放和审计需求时保留原始记录，再生成经过验证的表并明确分析粒度。定义每一行代表一次下载、一条选课还是一天的课程总数。混合粒度会悄悄破坏汇总。[湖屋与 Delta 表](https://learn.microsoft.com/en-us/fabric/data-engineering/lakehouse-and-delta-tables)。

## 3. 把快捷方式视为依赖

OneLake 快捷方式引用目标位置，并不建立独立备份。来源删除、权限变化或目标移动都可能影响读者。删除快捷方式本身不会删除目标。因此，共享路径需要负责人、访问约定和持续可用计划。

对于图书馆管理的课程目录，快捷方式可以避免维护副本。检查内部与外部快捷方式认证、适用的连接身份、目标权限和消费引擎的读取路径。不能假设每个读者的身份都以相同方式传递。记录架构变化约定，并测试获准与被拒绝的读者。指针可用不证明有权读取内容。[OneLake 快捷方式](https://learn.microsoft.com/en-us/fabric/onelake/onelake-shortcuts)。

## 4. 匹配编排与转换

管道协调复制、依赖、参数、计划、重试和失败路径。笔记本表达可编程转换，也能参与编排。分布式文件处理与转换可选 PySpark，关系操作可选 SQL，合适的事件分析可选 KQL。准备模型适合任务时，也可以选择 Dataflow Gen2。

我们的夜间流程先复制选课数据、验证键、转换记录，再在检查成功后发布课程总数。参数化处理窗口和目标。区分控制层完成与数据验收：绿色复制活动仍可能送来错误日期的数据。解释批处理、镜像或流为何满足新鲜度要求，并核对源支持，不能假设每个数据库都能持续复制。

## 5. 让增量加载能够重放

高水位标记标识已处理的源变化。先捕获有界上限，加载指定区间，验证并提交输出，然后才推进持久进度。发布成功前推进标记可能漏数据。单独使用时间戳可能漏掉相同时间值、迟到变化和删除；应采用稳定顺序、重叠窗口加去重，或合适的变更数据捕获。

CDC 在受支持且正确配置时能表示插入、更新和删除。普通修改日期查询无法发现已物理删除的行，除非有其他信号。幂等合并前，用稳定业务键与确定性版本顺序去重各批次。必要时保存删除和版本信息，防止较旧的迟到更新复活已删除选课。重跑已完成批次应保持同一业务状态。

## 6. 围绕时间和恢复设计流

批处理处理有界输入；流处理处理持续到达的数据，通常采用微批。事件时间是下载发生的时刻，处理时间是引擎处理它的时刻。延迟上传的移动端事件即使今天处理，也可能属于昨天的事件时间窗口。

按转换、状态、延迟和运维要求选择 eventstreams、Spark Structured Streaming 或基于 KQL 的处理。定义窗口边界、允许迟到和修正规则。流式水印限制状态保留和迟到事件处理，与批量提取高水位标记用途不同。检查点保留用于恢复的进度和状态，但不能单独证明端到端不会重复：源重放、接收端行为和幂等写入同样重要。[将 Spark 流写入湖屋](https://learn.microsoft.com/en-us/fabric/data-engineering/lakehouse-streaming-data)。

## 7. 让数据质量可观测

规定必需列、类型、空值规则、允许值和键唯一性。新增可选字段不同于把数值字段改成自由文本。架构演进需要明确兼容性决定和下游检查；自动接受一切可能把源错误变成已发布约定。

将无效记录放入受控隔离区，保留原因代码和源标识符，避免无必要地记录真实学生细节。测量接受、拒绝、重复、删除和发布记录数，并按明确核算规则对账。课程引用缺失可能需要延迟维度处理，不能默默删除。合成测试应包含重复键、错误日期、未知课程和重放变化。任务成功不能证明这些规则通过。

## 8. 检查每条访问路径

工作区角色、项权限、SQL 权限、语义模型规则，以及 OneLake 文件或表访问分别作用于不同边界。某个引擎实施规则，不证明另一条路径也受保护。为工程师、分析师和执行身份分别授予所需最小权限。

大学分析应使用预期读者身份，测试允许查看课程汇总、拒绝查看学生明细。既检查报表查询，也检查直接文件访问。行、列、对象和文件级限制必须符合所选引擎及当前功能支持。敏感度标签和认可状态传达治理背景；单独贴标签不会自动实现全部授权要求。把导出和日志也纳入检查。[Fabric 权限模型](https://learn.microsoft.com/en-us/fabric/security/permission-model)。

## 9. 根据环境部署定义

Git 集成支持对受支持的项定义进行版本管理。部署管道在阶段之间移动受支持内容。两者都不意味着每条源记录、秘密、权限、连接或运行状态会随定义复制。规划提升前检查项类型和依赖支持。

分开开发、测试和生产配置：工作区与项引用、连接绑定、执行身份、参数、计划和环境依赖。凭据不得进入源代码管理。对于应用，要检查测试管道读取合成选课，且不能发布到生产。比较版本、执行验收，再有意识地启用计划任务。规划如何回退定义并修复已写数据；回退代码不会撤销所有数据变化。[部署管道](https://learn.microsoft.com/en-us/fabric/cicd/deployment-pipelines/intro-to-deployment-pipelines)。

## 10. 根据基线诊断并离线练习

记录运行标识符、源窗口、行数、拒绝记录、耗时、新鲜度和容量使用率。重跑前检查失败活动和底层错误。权限失败、输入错误和源不可用需要不同应对。反复重试可能放大部分写入。

作业缓慢时，比较类似工作负载：Spark 阶段倾斜与 shuffle、小文件、分区裁剪、查询计划、管道并发和容量竞争。按学生标识符分区可能产生过多小分区。针对正确性和延迟阈值，测试一项有根据的修改；当测量显示容量压力能解释问题时，扩容才有帮助。
