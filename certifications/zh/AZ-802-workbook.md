# AZ-802 · 以证据为基础的 Windows Server 练习册

[指南](AZ-802.md) · [10 个推理案例](AZ-802-cases.md) · [目录](README.md)

五个对应单元结合 AZ-802 的七个学习领域。使用虚构且隔离的大学实验环境 `lab.example.test`。产出可供审查的决策与证据包，而不是从视频复制的设置清单。这些是拟议的 Windows 练习，不宣称执行过 AD、Hyper-V、Azure、还原或安全控制。如果没有兼容的 Windows 实验环境，应提交明确标注的设计与预测观察，而不是编造结果。

为每个单元保留台账：基线、假设、竞争性解释、选定的只读检查、拟议更改、预期观察、执行时的实际观察，以及停止和回退条件。记录操作系统版本类型与版本、已安装模块、所需权限和目标身份。遮盖机密与个人数据。指南的前提条件矩阵适用于其中的命令示例；任何命令都不会授予检查无关系统的权限。

<a id="az-802-unit-1"></a>

## 1. 从目录到访问追踪身份更改

**场景：** LAB-DC1 接受了研究组成员身份更改，但远端楼宇客户端仍无法访问 `\\LAB-FS1\LabNotes`。客户端选择 LAB-DC2。另一个分支方案因为教室物理保护有限，计划使用 RODC。

**调查：** 画出林与域、两台可写控制器、分支 RODC、DNS 解析器、站点和 IP 子网映射。标记接受更改的控制器和客户端使用的控制器。确定复制路径、相关 SRV 记录、时间层级、用户令牌，以及共享与 NTFS 边界。选择有顺序的检查，区分过期目录状态和有效访问问题。包含一项能够推翻最初假设的预期观察。

只有在适当的 Windows 管理上下文中，才使用指南中的 AD 清单、解析器与时间、复制查询。对于组策略，分别解释范围、客户端处理和有效设置。对于 RODC，定义有资格断网访问的普通账户、必须继续被拒绝的账户、委派的分支管理和设备丢失响应。验证有效密码复制策略，不要假定组名就能证明结果。

**证据：** 标明身份边界的拓扑；去除敏感内容的查询上下文和时间戳；对象更改时间线；预期与实际观察的控制器选择；一组允许与拒绝文件访问测试；以及不含密码的 RODC 缓存决策。

**交付物与关口：** 编写一页诊断，提出范围有限的修复。在任何获授权实验更改前，保留原解析器、站点和策略设置。如果出问题的控制器或命名空间位于可丢弃实验之外，就停止。不要为消除症状而扩大权限、强占 FSMO 角色或重置全部账户。成功意味着所需目录更改收敛，预期用户只获得预期访问权，而应拒绝的用户仍被拒绝。

## 2. 审查远程管理和 VM 恢复边界

**场景：** 操作人员能远程进入成员服务器，却无法访问第二项资源。有人提议启用可重复使用的凭据委派，并在 DC 上运行 JEA 终结点。同时，一台 VM 的生产一致性步骤失败，却创建了 Standard 检查点。实验有两台 64 GiB 主机，每台假定为主机预留 12 GiB，并分配十二台固定使用 4 GiB 的来宾。

**调查：** 画出每次身份验证的跃点、协议、有效身份和所需操作。把受支持的第二跃点设计，与 CredSSP 风险及协议特定的委派限制比较。审查 JEA 允许的命令和参数、执行组、审核及放置；解释为什么 DC 上默认虚拟账户的权限，对有限的成员服务任务而言过大。对于 Arc 管理的机器，单独识别 Azure 扩展授权和本地权限。

使用 VM、交换机、内存和检查点清单，解释来宾网络和恢复状态。按各自针对的故障，比较检查点、副本、群集和受保护备份。解释 Production 与 ProductionOnly，以及实际检查点类型为何重要。对于这组假设容量，正常分配内存为每台主机 48 + 12 = 60 GiB；把全部 24 台来宾移到一台主机，则需要 96 + 12 = 108 GiB。写明假设，展示为什么正常情况下容纳得下，并不能证明单主机故障时仍有足够容量。

**证据：** 权限与跃点图；受限制终结点审查；交换机和来宾路径；内存计算表；有条件时获取的实际检查点元数据；以及独立还原副本计划。

**交付物与关口：** 提出受支持、范围有限的管理设计，并单独设计恢复机制。如果委派将暴露真实特权身份，或 VM 受支持的一致性要求不明，就停止。记录更改前的终结点设置和恢复访问。不要删除 AVHDX 文件，不要声称副本能修复逻辑损坏，也不要将同一存储中的检查点称为独立备份。成功执行命令和服务能够安全恢复，需要不同验证。

## 3. 跨网络与存储诊断客户端到文件的路径

**场景：** 教室新客户端无法获得地址，而旧租约继续有效。完成获批网络修正后，一名研究用户能够到达共享，但被拒绝访问文件夹。服务器已注册 Azure File Sync，部分文件已分层。图中还包含混合 DNS 条件转发器，以及一台未配置的第二 DHCP 服务器。

**调查：** 追踪客户端 VLAN 与中继、获授权 DHCP 作用域、排除与保留、选项和剩余容量。说明真正的新分配测试相较于现有客户端测试增加了什么信息。区分存在第二台服务器与已配置受支持故障转移关系。追踪预期解析器、命名空间、条件转发目标、返回路径和应用端口；正确的 DNS 回答不能证明 SMB 连接可用。

随后记录实际用户、共享授权、NTFS 继承和组令牌上下文。测试获准身份和必须继续被拒绝的身份。对于 Azure Files，区分受支持的身份设置、共享级授权，以及目录与文件权限。清点 File Sync 终结点、本地缓存假设、独立保留的备份和受支持恢复流程。明确否定将还原、克隆或回退已注册服务器的操作系统或 VM 视为通用 File Sync 恢复方法。

**证据：** 地址分配工作表；解析器和路由图；移除机密的共享与 ACL 观察；允许与拒绝测试条件；云与服务器终结点图；以及选定的历史恢复点和相应依赖。

**交付物与关口：** 将网络失败和权限失败作为两项独立发现解释。在任何获授权更改前，记录现有作用域和 ACL。遇到重叠分配范围、意外权限扩张或未受保护的恢复依赖时停止。成功要求目标新客户端获得有效设置，预期用户能够访问文件夹，应拒绝用户仍被阻止，而且恢复计划确定的是受保护副本，而不只是另一个同步终结点。

## 4. 按角色设计加固，同时保留恢复访问

**场景：** 服务器群包括 Windows Server 2022 和 2025、成员服务器、DC 与文件服务器。方案将同一 OSConfig 基线部署到所有机器，未检查证书就暴露 SMB over QUIC，并在报告中共享 LAPS 密码。移除基线被描述为完整回退。

**调查：** 选择控制前，先建立角色与版本矩阵。核对过的 OSConfig 安全基线指南针对 Windows Server 2025；记录模块版本、场景、预期设置差异、重启需求，以及与现有 GPO 或其他管理的冲突。选择正确角色试行。解释为什么不能假定移除管理会重建早期状态。保留受保护的原状态记录，以及另一条获授权管理路径。

对于 LAPS，区分轮换、备份目标、允许获取、审核和恢复访问。在相关情况下记录 DSRM 恢复条件，不要获取或公开密码。对于 SMB over QUIC，核实准确的服务器与客户端支持范围：审查的指南列出 Windows Server 2022 Datacenter: Azure Edition 或 Windows Server 2025 各版本，以及 Windows 11 客户端。审查证书信任、名称、私钥使用和获准 UDP 路径，并保持共享与文件授权。不要把 QUIC 当作授权的替代品。

**证据：** 角色与版本矩阵；所选控制及支持参考；设置差异与回退关口；允许与拒绝获取的角色；移除敏感信息的证书检查清单；以及隔离环境中的允许与拒绝访问测试计划。

**交付物与关口：** 编写分阶段更改方案，明确恢复责任人。如果基线不受支持、唯一管理路径将被移除、证书要求尚未解决，或真实机密出现在证据中，就停止。已有凭据披露应通过组织的响应流程处理。合规结果、已安装功能和已证明强制执行，是不同观察。

## 5. 追踪缺失事件，并演练目录恢复

**场景：** Arc 管理的服务器报告已连接，AMA 发送 Heartbeat，但所需 System 事件仅存在于本地。另一次独立桌面推演中，AD 对象被删除，且事前未启用回收站。已有受支持目录备份。团队设定两小时还原目标，希望得到比“VM 能启动”更有力的证据。

**调查：** 沿预期的 AMA 扩展与服务、DCR、关联、源选择、目标和查询时间范围，追踪一个移除了敏感内容的本地事件。分别记录机器身份、事件时间和到达时间。定义测试，区分源事件缺失、收集配置缺失，以及查询了错误的表或工作区。解释 Arc 连接和 Heartbeat 各自证明什么，以及仍留下哪些不确定性。

对于目录恢复，识别受影响对象与依赖、可用且受支持的备份、恢复负责人、受保护 DSRM 凭据，以及适当还原范围。区分回收站对象恢复、权威或非权威目录恢复、SYSVOL 恢复和整个林恢复。为实际故障选择受支持流程；不要把单个对象误操作自动变成控制器回退或 FSMO 强占。演练依赖顺序、复制影响、验证，以及已恢复服务的安全返回。

**证据：** 从事件源到目标的追踪；带时间戳的假设日志；恢复点清单；明确标为估算的预期恢复时间；以及覆盖所需对象、身份验证、复制、策略和受影响应用的验收检查。

**交付物与关口：** 分别编写监视与恢复运行手册。更改前保留原 DCR 和关联证据。如果恢复范围或权威副本不明确，就停止。记录业务中断和可用恢复数据的时间线，避免混淆 RTO 与 RPO。只有获授权实验真正执行操作并提供所列观察后，才能记录为完成。仓库本身不宣称完成 Windows 或 AD 还原，也不宣称实测达到两小时。

最后，在不打开解释的情况下回答[十个案例](AZ-802-cases.md)。对于每个薄弱答案，确定缺失证据或混淆边界，再回到[指南](AZ-802.md)相应部分。本练习册提供选定练习，不是对全部考试目标的完整覆盖，也不是通过考试的预测。
