# AZ-140 · 共同进阶练习册

[指南](AZ-140.md) · [10 个案例](AZ-140-cases.md) · [目录](README.md)

各语言包含对应的五个单元。使用大学笔记应用和虚拟机房离线练习。将预测明确记录为预测；这些单元不部署资源、不更改租户，也不证明已具备生产就绪能力。

<a id="az-140-unit-1"></a>

## 1. 映射资源、用户和职责

画出供 48 名学生使用的池化机房，以及供一位研究人员使用的个人桌面。识别主机池、会话主机、应用组、工作区注册和用户分配。把 Microsoft 对连接代理和网关的责任，与客户对映像、虚拟机、网络、身份集成和存储的责任分开。解释受支持的多会话运行为什么不同于个人分配。

**场景：**学生可以看到 Azure 虚拟机，但桌面订阅源为空。**证据：**资源关系图、有效应用组访问授权、预期客户端账户和许可假设。**交付物：**前三项检查、一次被排除的不合适角色提升，以及每项客户管理依赖的负责人。将设计与[计算基础](../../zh/03-compute.md)联系起来。

<a id="az-140-unit-2"></a>

## 2. 分别追踪身份与传输

结合旧应用和所选配置文件存储身份验证，比较 Entra 加入、AD DS 加入和 Entra Domain Services 加入。把订阅源身份验证、访问授权、会话登录和文件访问画成不同阶段。加入出站 HTTPS 反向连接，以及某项选项对应的 UDP Shortpath 路径。解释托管网络侦听器的专用可达性，以及 ICE/STUN 或 TURN 如何改变传输要求。

**场景：**校园用户连接流畅，家庭用户则再次收到登录提示且会话较慢。**证据：**客户端版本、加入类型、SSO 和条件访问假设、协商传输、DNS 路径，以及所需延迟观察。**交付物：**两个独立假设及其确认测试，不向公网开放 TCP 3389。复习[网络基础](../../zh/05-networking.md)。

<a id="az-140-unit-3"></a>

## 3. 保护配置文件并发布可用应用

在可替换池化主机之外设计持久 FSLogix 容器。记录存储身份与 Kerberos 兼容性、共享和 NTFS 权限、容量、登录高峰假设、单连接行为，以及备份与还原目标。区分配置文件偏好与笔记的权威数据。比较在映像中安装编辑器与使用受支持的 App Attach 包，并单独解释 RemoteApp 发布。

**场景：**学生进入桌面后得到临时配置文件，并且无法启动编辑器。**证据：**容器附加错误、活动会话所有权、预期权限、主机映像版本、包访问和分配。**交付物：**有序故障树，分别列出配置文件分支与应用分支，提出安全恢复方案，并制定保护现有用户工作的标准。

<a id="az-140-unit-4"></a>

## 4. 发布映像并计算课堂容量

编写版本化黄金映像发布计划，覆盖受支持的操作系统、代理、安全策略、应用、验证用户、排空行为和回滚。在测得每台主机最多 12 个会话的前提下，计算一台主机故障时容纳 48 名学生所需的容量。区分缩放计划选定的方法与 Start VM on Connect；包括启动时间、运行状况、最大会话数和存储约束。

**场景：**课前收到补丁，而此时已有一台主机不可用。**证据：**五台主机的容量表、映像版本、验证清单、活动会话和维护排除项。**交付物：**保留足够可用容量的分阶段上线计划，包含回滚触发条件，以及缩减容量时对仍然连接的用户采取的明确策略。

<a id="az-140-unit-5"></a>

## 5. 开展登录失败与恢复桌面推演

用 UTC 时间戳、用户假名、资源、主机和关联 ID 追踪一次合成连接。指定所需诊断设置、主机性能收集、FSLogix 日志和用户体验观察。解释为什么从未到达 AVD 的尝试可能不留下连接记录。把身份、DNS、应用包、配置文件和笔记 API 依赖加入备用区域恢复计划。

**场景：**09:00 的课程在存储中断后无法恢复配置文件。**证据：**预测检查点、正常会话对照、配置文件恢复目标、可用容量，以及持续的虚拟机、磁盘、存储、网络、监测和许可成本负责人。**交付物：**事件时间线、首次故障假设、恢复及返回主区域标准，并明确区分桌面推演预测和实际观察测试。
