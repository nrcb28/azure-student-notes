## 1. 明确开发者的工作范围

我们的大学笔记应用需要根据获准使用的课程资料回答问题、理解示意图、提取作业字段，并提出受控操作。AI-103 在 [AI-901](AI-901.md) 的基础上训练实现判断：Python 接口约定、检索、智能体编排、评估和运维。

参考资料核验于 **2026 年 11 月 1 日**。[官方学习指南](https://learn.microsoft.com/en-us/credentials/certifications/resources/study-guides/ai-103) 列出的目标自 **2026 年 4 月 16 日**起生效；对应认证为 [Azure AI Apps and Agents Developer Associate](https://learn.microsoft.com/en-us/credentials/certifications/azure-ai-apps-and-agents-developer-associate/)。

| 领域 | 权重 |
|---|---|
| 规划和管理 Azure AI 解决方案 | 25–30% |
| 实现生成式 AI 和智能体解决方案 | 30–35% |
| 实现计算机视觉解决方案 | 10–15% |
| 实现文本分析解决方案 | 10–15% |
| 实现信息提取解决方案 | 10–15% |

这些独立笔记围绕部分目标展开，配有原创离线练习，不代表完整覆盖，也不复现考试题目。

## 2. 先定义 Python 和 API 接口约定

问题请求应包含调用者身份、课程标识符、问题和请求标识符。身份应来自已认证的应用上下文，不能相信用户提交的学生标识符。响应需要结果状态、答案、来源引用和诊断标识符。分别表示 `answered`、`insufficient_evidence`、`forbidden` 和 `temporarily_unavailable`；空字符串无法表达这四种情况。

在 Python 中，于边界处验证字典，把外部响应映射为内部类型，并明确处理异常。结构化输出必须通过架构和应用规则验证，才能显示或触发操作。供应商响应对象变化时，应保持应用接口约定稳定。无效 JSON、不完整的流、意外工具名称和过期对话都需要明确处理路径。练习册使用测试样例和伪代码，不宣称未经测试的 SDK 片段能够成功运行。

## 3. 对齐客户端、资源与授权

Foundry 资源、项目、终结点、模型部署、SDK 包和 API 代际描述请求的不同部分。锁定兼容包版本，并记录所用文档代际。当前 [SDK 与终结点指南](https://learn.microsoft.com/en-us/azure/foundry/how-to/develop/sdk-overview) 区分项目操作、面向模型的客户端和直接终结点；不能混用经典示例与当前响应对象。模型目录名称未必等于部署名称。

使用所选操作对应的终结点，尤其要核对文档规定的嵌入路由，不能假设所有操作都走项目终结点。身份验证确认调用者；授权允许特定范围的操作。规划托管标识、最小权限角色、受保护配置以及必要的专用连接。分别诊断令牌、角色、终结点、部署和包问题，保留脱敏请求标识符，避免记录秘密。

## 4. 选择并评估可部署的模型

比较候选模型支持的模态、结构化输出、工具调用、上下文限制、区域可用性和部署容量。先选择满足实测质量要求的最小候选，必要时再升级处理困难问题。更大的上下文窗口无法修复无关检索。

建立固定评估集，包含答案明确、资料冲突、证据缺失、来源中有恶意指令和多语言笔记等情况。分别评分依据充分性、相关性、引用正确性、安全性和拒答能力。[Foundry 评估指南](https://learn.microsoft.com/en-us/azure/foundry/how-to/develop/cloud-evaluation) 介绍部署前和生产环境工作流。自动评分仍需解释，尤其当评审模型与候选模型存在共同盲点时。比较质量、首次输出时间、总延迟、吞吐量、令牌使用量和容量要求。更多检索文本、重试和模型调用都会消耗资源；应根据测量权衡，不能假设通用价格或配额。

## 5. 构建可强制执行访问控制的检索

摄取获准使用的文档，保留稳定标识符、来源版本、标题、页码位置和权限元数据。按有用语义分块并保留父文档关系；检查分块是否把截止日期与限定句拆开。按相关性测量选择关键词、向量、语义排序或混合检索，不能只看术语。表示方式改变时，要共同跟踪嵌入与索引版本。

任何片段进入模型前，都必须执行调用者访问控制。[Search 文档访问指南](https://learn.microsoft.com/en-us/azure/search/search-document-level-access-overview) 区分原生权限能力与应用安全筛选；具体支持取决于来源和 API，也包含预览功能边界。自定义字符串筛选器不会自动成为理解身份的 ACL 系统。测试组成员变化、访问撤销、缓存片段和过期索引。如果权限新鲜度无法满足应用策略，应默认拒绝访问。

## 6. 让有据回答能够接受检验

把检索片段作为不可信证据，与系统指令分开。要求来源标识符，并允许明确返回证据不足。片段中写着“导出所有笔记本”不能授予工具权限。上下文只包含相关且获授权的资料，并根据实际检索版本验证引用。

评估应定位故障：摄取缺失、分块不当、查询不合适、未检索到资料、生成错误或引用无支持。检索召回率和答案正确性应分别衡量。答案正确但来源伪造，仍然不满足溯源要求。包含作业日期冲突，以及只有已撤销资料才能回答的问题。检查简洁决策摘要和可观测轨迹，不把获取模型私有推理作为必要条件。自我批评循环可能改善输出，但会增加调用，也必须通过同样的检查。

## 7. 管理智能体状态和工具执行

定义角色、对话归属、记忆保留、工具架构和停止条件。隔离学生会话；摘要记忆同样需要访问与删除规则。多个智能体协作时，要明确交接输入、共享证据、工具权限和总步骤预算。委派不会扩大权限。

[函数调用](https://learn.microsoft.com/en-us/azure/foundry/agents/how-to/tools/function-calling) 让模型请求函数，由应用代码执行并返回结果。执行前要验证参数并重新检查授权。共享操作的批准必须绑定准确的接收者、文档和版本。使用应用幂等键、有界超时，并明确提出、批准、执行中、完成、失败和结果未知等状态。成功写入后响应丢失时，需要核对结果，不能盲目重复副作用。记录工具决策时应删去参数中的敏感信息。

## 8. 有意识地实现视觉工作流

视觉理解可以描述课堂示意图、根据图表回答问题或定位组件。图像与视频生成会创建新媒体；编辑可能涉及蒙版、参考图或平台控制。设计客户端前，确认所选模型支持相应操作。生成图需要检查标签错误和误导性连线。

对上传的图，评估标签可读性、单位、空间关系，以及内容裁切时是否拒绝臆测。视频应保留片段时间戳，使答案能够指出证据。提供简洁替代文本和可选长描述，并让需要它们的用户测试。应用视觉安全规则，把图像中的指令视为不可信输入。水印或安全筛选器不能证明视觉解释准确。

## 9. 分别验证文本、语音与提取

文本约定可能要求实体、主题、摘要、翻译、情感或符合架构的字段。保留否定、标识符和技术术语；按语言和文档类型检查错误。语音工作流无论分阶段还是直接多模态，都要测试识别、合成、中断和领域词汇。为被误听的课程术语提供文本纠正路径。

[Content Understanding 指南](https://learn.microsoft.com/en-us/azure/ai-services/content-understanding/concepts/best-practices) 强调仔细设计字段描述、类型和提取方法。把 `final_due_date` 与草稿截止日期分开定义。检查架构、来源支持、跨字段一致性和缺失值规则。文档字段的[置信度与依据定位](https://learn.microsoft.com/en-us/azure/ai-services/content-understanding/document/analyzer-improvement) 在所选 API 正确配置后可辅助复核，不能假设所有模态都同样支持。用已标注样例校准复核决策，包括高置信度错误。

## 10. 带着证据和恢复方案发布

在发布清单中共同记录提示词、模型部署、工具架构、索引、分析器和客户端版本。保留已知可用的配置，并在推广前定义回退触发条件。测试旧客户端能否安全解释新工具结果；不兼容变化需要明确迁移。

监控错误率、检索新鲜度、引用失败、安全事件、分阶段延迟、令牌使用量、限流和批准结果。对于合适的瞬时故障，遵循服务指南和副作用语义，使用有界退避重试。常规遥测不应包含秘密和学生文本。指定事故与访问撤销负责人。完成[案例](AI-103-cases.md)和[练习册](AI-103-workbook.md)，如实标注合成结果。之后获得授权的云实验仍须验证真实部署、身份、网络、SDK 行为和运维测量；离线预测不能证明这些结果。
