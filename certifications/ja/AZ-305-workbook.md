# AZ-305 · 共通の発展ワークブック

[←](README.md) · [共通学習コア](../../ja/16-common-core.md) · [発展演習](../../ja/17-advanced-labs.md)

八言語で目標、ケース、提出物を対応させています。同等性は語数ではなく学習単位と検証する証拠で確認します。以前のガイドも補足説明として残します。

<a id="az-305-unit-1"></a>

## 1. 必要性を制約に変える

利用者、成長、所在、秘密性、性能、RTO/RPO、予算、運用能力を定義します。確認済み条件と仮定を分けます。常時利用には対象操作と測定期間が必要です。

**ケース：**五学部でネットを共有しデータは非公開。**証拠：**管理とデータ境界、担当、分離を要求する条件。規模だけで企業構成を選びません。

<a id="az-305-unit-2"></a>

## 2. データと状態

Query、取引、互換性、一貫性、復旧を比較します。JSON はエンジンを決めず、読み取り拡張は書込能力を必ず増やすわけではありません。アプリ、セッション、文書の状態を分けます。

**ケース：**高速 cache が古い権限を返す。**証拠：**無効化、期限、故障動作、古い複製を信用できない情報。

<a id="az-305-unit-3"></a>

## 3. 全体復旧を設計

データとサービス別に RTO/RPO を設定し、能力、資格情報、権限、DNS、設定を含めます。論理障害も複製され得ます。Active-active と passive を費用と複雑さで比較します。

**ケース：**Key Vault が戻っても統合がない。**証拠：**順番、認可された利用側の試験、自動復元されない依存、隔離した予行。

<a id="az-305-unit-4"></a>

## 4. 実行と通信

VM、PaaS、コンテナー、batch を制御、時間、運用で比較します。Queue は状態と重複を増やします。消費側を増やす前に timeout、制限再試行、冪等性を設計します。

**ケース：**保存応答の消失とメッセージ重複。**証拠：**安定 ID、回数制限、途中処理の扱い。Cluster か単純な基盤かを説明します。

<a id="az-305-unit-5"></a>

## 5. 移行を記録する

依存と利用量を調査し、互換性、pilot、初回転送、差分、切替、戻し方を決めます。整合性確認と元環境の退役条件を定義します。VM だけで必要ファイルがなければ未完了です。

**提出：**二つの ADR、ネットと復旧、リスク表。各決定に代案、影響、試験、見直し条件。予算や所在変更で再検討します。
