# AZ-140 · 共通の発展ワークブック

[ガイド](AZ-140.md) · [10ケース](AZ-140-cases.md) · [目次](README.md)

言語間で対応する五単元です。大学のノートアプリと仮想計算機室を使い、オフラインで取り組みます。予測は予測と記録します。何もデプロイせず、テナントを変更せず、本番準備ができた証拠にはなりません。

<a id="az-140-unit-1"></a>

## 1. リソース、利用者、責任を対応付ける

48人の学生用プール型実習環境と、研究者一人用の個人デスクトップを描きます。ホストプール、セッションホスト、アプリケーショングループ、ワークスペース登録、利用者割り当てを示します。Microsoftのブローカーとゲートウェイ責任を、顧客のイメージ、VM、ネットワーク、ID連携、ストレージと分けます。対応するマルチセッション動作と個人割り当ての違いを説明します。

**シナリオ：**学生にはAzure VMが見えてもフィードが空です。**証拠：**リソース関係図、実効アプリケーショングループ資格、意図したクライアントアカウント、ライセンスの仮定です。**成果物：**最初の三確認、却下する不適切な権限昇格、各顧客管理依存先の責任者です。[コンピューティングの基礎](../../ja/03-compute.md)と設計を結び付けます。

<a id="az-140-unit-2"></a>

## 2. IDと転送を別々に追う

古いアプリと選択したプロファイルストレージ認証に対し、Entra参加、AD DS参加、Entra Domain Services参加を比較します。フィード認証、利用資格、セッションのサインイン、ファイルアクセスを別段階として描きます。送信HTTPS reverse connectと、方式固有のUDP Shortpath経路を加えます。マネージドリスナーのプライベート到達性と、ICE/STUNまたはTURNで転送要件がどう変わるか説明します。

**シナリオ：**学内は快適でも、自宅では再度のサインイン要求と遅延があります。**証拠：**クライアント版、参加種類、SSOと条件付きアクセスの仮定、転送方式、DNS経路、必要な遅延観察です。**成果物：**独立した二仮説と確認テストです。公開TCP 3389は開けません。[ネットワークの基礎](../../ja/05-networking.md)を確認します。

<a id="az-140-unit-3"></a>

## 3. プロファイルを守り、使えるアプリを公開する

交換可能なプール型ホストの外に、永続FSLogixコンテナーを設計します。ストレージID・Kerberosの互換性、共有とNTFSの権限、容量、サインイン集中の仮定、単一接続動作、バックアップと復元目標を記録します。プロファイル設定とノート正本データを分けます。イメージへの編集アプリ導入と対応App Attachパッケージを比較し、RemoteApp公開は別に説明します。

**シナリオ：**デスクトップには入れても一時プロファイルとなり、編集アプリも起動しません。**証拠：**コンテナー接続エラー、アクティブセッション所有者、期待権限、イメージ版、パッケージアクセス、割り当てです。**成果物：**プロファイルとアプリを分枝させた順序付き障害ツリー、安全な復旧案、既存作業を守る基準です。

<a id="az-140-unit-4"></a>

## 4. イメージをリリースし、教室容量を計算する

対応OS、エージェント、セキュリティ方針、アプリ、検証者、ドレイン動作、切り戻しを含む、版管理したゴールデンイメージのリリース計画を書きます。実測上限12セッションで、一台故障時の48人分を計算します。スケーリングプランで選ぶ方法とStart VM on Connectを区別し、起動時間、健全性、最大セッション、ストレージ制約を含めます。

**シナリオ：**一台が停止中に、授業前のパッチが届きます。**証拠：**五台の容量表、イメージ版、検証一覧、アクティブセッション、保守除外です。**成果物：**十分な利用可能容量を残す段階展開で、切り戻し条件と縮小時にも接続中の利用者への明確な方針を含めます。

<a id="az-140-unit-5"></a>

## 5. ログイン失敗と復旧の机上演習を行う

UTC時刻、仮名利用者、リソース、ホスト、相関IDで合成接続を追います。診断設定、ホスト性能収集、FSLogixログ、必要な利用体験の観察を指定します。AVDまで届かない試行が接続記録を残さない理由を説明します。代替リージョンの復旧計画に、ID、DNS、アプリパッケージ、プロファイル、ノートAPIの依存を加えます。

**シナリオ：**ストレージ停止後、09:00の授業でプロファイルを復旧できません。**証拠：**予測チェックポイント、正常セッションとの比較、プロファイル復旧目標、利用可能容量、VM・ディスク・ストレージ・ネットワーク・監視・ライセンスの継続費用責任者です。**成果物：**時系列、最初の失敗仮説、復旧とプライマリ復帰の基準、机上予測と観測テストの明確な区別です。

[ガイド](AZ-140.md)の六つの技術参照で仮定を検討します。独自教材であり、全公式目標の網羅や試験結果の保証はありません。
