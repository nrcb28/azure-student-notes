# AZ-120 · 共通の上級ワークブック

[ガイド](AZ-120.md) · [10ケース](AZ-120-cases.md) · [目次](README.md)

各言語で共通の5単元です。架空の大学の購買・財務SAP環境と研究ポータル連携を、オフラインで扱います。ライセンスの提供、Azure展開、SAP実行、本番準備完了を主張しません。仮定・予測結果と観測証拠を区別します。

<a id="az-120-unit-1"></a>

## 1. 責任と対応容量を棚卸しする

本番・非本番SID、アプリサーバー、ASCS/ERSまたはSCS、HANA、共有ファイル、ID、DNS、インターフェイスを描きます。基盤、OS、Basis、DB、セキュリティ、業務検証の責任者を割り当てます。アプリ冗長化だけでは別の単一障害点が残る理由を説明します。該当SAPS、メモリ、成長、帯域、遅延、障害余力のサイジング表を作り、SKU選定は認定・互換性確認を条件とします。

**シナリオ：** 安いVMのコア数は同じですが、HANAサポート証拠がありません。**証拠：** 依存図、対応するVM/OS/DB/ストレージの組み合わせ、リージョンクォータの前提、ライセンスレビュー責任者。**成果物：** 受け入れ基準と未解決の測定を説明する設計判断。[コンピューティング基礎](../../ja/03-compute.md)を復習します。

<a id="az-120-unit-2"></a>

## 2. 配置、ネットワーク、HANAストレージを設計する

対応するアプリ対DB経路、管理、複製、バックアップ、学内接続、DNS転送を描きます。ExpressRouteのプライベート接続と選ぶ暗号化を分けます。明示した遅延前提で、ゾーン分離とPPG近接制約を比較します。`/hana/data`、`/hana/log`、`/hana/shared`、対応ファイルシステム、ディスク・VMのI/O上限、構成固有のキャッシュ・Write Accelerator判断を計画します。

**シナリオ：** セーブポイントと購買遅延が重なり、アプリとDBの間に検査機器を置く案があります。**証拠：** 通信経路、配置図、予測遅延予算、ボリューム役割表、必要なI/O観測。**成果物：** 容量と障害ドメインのトレードオフを示す対応代替案。[ネットワーク基礎](../../ja/05-networking.md)を復習します。

<a id="az-120-unit-3"></a>

## 3. 安全な切り替えと過去時点への回復を分ける

HANA System Replication、対応クラスター制御、ASCS/SCS保護、ERS、クォーラム、フェンシング、仮想名、ロードバランサープローブを説明します。ネットワーク分断後の唯一の書き込み元を描きます。業務RPO・RTO、ワークロード整合バックアップ、使えるログ、保持、復元依存関係を定めます。複製が誤りをコピーし、調整なしスナップショットではアプリ整合性を確立しない理由を示します。

**シナリオ：** 相手をフェンスできず、財務上の誤りは既に複製済みです。**証拠：** クラスターの予測判断、フェンス依存関係、正当コピー規則、バックアップ・ログ可用性、復元検証基準。**成果物：** 別々のHA・復元手順書。フェンス無効化を修復策として明確に否定し、過去回復後の業務照合を含めます。

<a id="az-120-unit-4"></a>

## 4. 移行と連携の手順書を作る

ソースのサポート、版、インターフェイス、変更率、転送時間、停止時間、移行先互換性を評価します。理由付きで対応移行方式を選びます。予行、書き込み凍結、最終同期、ソース隔離、DNS・インターフェイス変更、技術確認、業務受け入れ、再開を定めます。RISEでは、想像上のサブスクリプション権限でなく契約を使い、顧客連携とSAP管理の責任を分けます。

**シナリオ：** 切り替え後に発注が作られ、その後研究ポータルが故障します。**証拠：** 書き込み所有の時系列、キュー状態、受け渡し点、検証ゲート、判断者。**成果物：** 新規書き込み前の巻き戻しと、その後の照合・逆移行の別判断。失敗境界がRISE側ならSAPへのエスカレーションも含めます。

<a id="az-120-unit-5"></a>

## 5. 運用をレビューし、リージョン復旧を演習する

架空のIaC変更でイメージ対応、配置、ストレージ、秘密情報参照、依存関係、破壊的差分をレビューします。クラスターを考慮した順序と巻き戻し基準で更新を段階化します。Azure Monitor収集、SAP監視プロバイダー、DB・クラスター証拠、アラート責任者、保持を指定します。ID、ネットワーク、中央サービス、アプリ、データ、連携、主系への同期を含む全サービスを別リージョンで復旧します。

**シナリオ：** サイズ変更案の審査中、購買中にリージョン停止が起きます。**証拠：** 依存順序、予測RPO/RTO、障害時容量、複製状態、業務確認、計算・保存・通信・監視の継続費用責任者。**成果物：** 計画検査と実行済みテストを区別するインシデント机上演習と変更審査記録。

[ガイド](AZ-120.md)の技術資料6件で前提を問い直します。独自演習は有用な概念を選んでおり、すべての公式目標を扱うことも試験結果を保証することもありません。
