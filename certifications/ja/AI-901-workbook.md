# AI-901 · 共通の発展ワークブック

[ガイド](AI-901.md) · [10ケース](AI-901-cases.md) · [目次](README.md)

学習言語間で対応する五つの単元です。架空の大学ノート、プロンプト、文字起こし、候補回答を使ってオフラインで作業します。候補出力には**合成**、期待結果には**予測**と明記します。本物の学生の資料をアップロードしてはいけません。このワークブックでは何もデプロイせず、試験全範囲の網羅を示しません。参照確認日：**2026年11月1日**。[試験目標は2026年4月15日から有効](https://learn.microsoft.com/en-us/credentials/certifications/resources/study-guides/ai-901)です。

<a id="ai-901-unit-1"></a>

## 1. 五つのAI契約を定義する

授業の質問への回答、課題の提出期限抽出、フィードバック文の分析、音声質問の受け付け、図の説明について、一つずつ契約を書きます。入力のモダリティ、許可するデータ、出力形式、許容しない誤り、失敗時の代替を定めます。生成回答、テキスト分析、音声、画像認識、Content Understandingを、何を出力するかで比較します。画像生成の要求も一つ加え、作成と解釈を区別します。

**シナリオ：**仲間が全機能に一つの画像モデルを提案しました。**証拠：**五行の判断表で、それぞれ選んだ機能の理由と却下した代案を示します。モダリティ、デプロイ方法、言語、対応パラメーターについてモデル選定の質問を追加します。不明なサービス詳細は現在の資料で確認する項目として残し、制限値を作りません。

<a id="ai-901-unit-2"></a>

## 2. 根拠付きプロンプトとアクセス規則を書く

閲覧可能な講義ノート、非公開ノート、文書を外部送信せよという指示を含む閲覧可能ページという短い三つの抜粋を作ります。安定した出典IDを付け、アクセス一覧の異なる二人の学生を設定します。出典に支えられた回答を要求し、原資料の境界を保ち、回答を控えることを認めるシステムとユーザーのプロンプトを書きます。検索はコンテキスト構築前に呼び出し元の権限で絞る必要があり、プロンプトはそのセキュリティ境界の代わりになりません。

**シナリオ：**許可された抜粋に質問の答えがありません。**証拠：**期待する回答差し控え、禁止されたアクセスの拒否、インジェクションに耐える合成回答を示します。各出典が支える主張を注記します。引用や攻撃検出器だけでは、真実、プライバシー、権限を確立できない理由を説明します。

<a id="ai-901-unit-3"></a>

## 3. クラウド呼び出しなしで軽量クライアントを追う

Pythonクライアントから対象のFoundryエンドポイントと構成済みデプロイへの要求、続くレスポンスまたはエラーを描きます。ID、認可、宛先、デプロイ選択を区別します。保護された設定を読み、適切な資格情報を取得し、許可された入力を送り、エラーと出力を検査し、安全に結果を表示する擬似コードを考えます。実行可能なSDKコードではなく、**擬似コード**と明記します。辞書、反復、例外、非同期呼び出しが現れそうな場所を説明します。

**シナリオ：**認証は成功しても、選んだリソースが操作を拒否します。**証拠：**機密情報のない診断一覧と、拒否、タイムアウト、空の出力、不正設定での期待動作を作ります。REST、SDK、CLIが同じタスクをどう表すか比較します。後のクラウド練習で使う[現在のSDKクイックスタート](https://learn.microsoft.com/en-us/azure/foundry/quickstarts/get-started-code)を特定します。

<a id="ai-901-unit-4"></a>

## 4. マルチモーダル抽出を検証する

最終提出期限のある課題用紙、日付のない用紙、単位の読めない図、雑音を含む音声質問を作ります。フィールド型、欠損値方針、出典参照のある期限スキーマを定めます。推測の日付、誤った単位、聞き間違えた専門語という、わざと欠陥のある合成出力を作ります。失敗が抽出、視覚的解釈、認識、後続の推論のどこにあるかを示します。音声認識を使う経路と、対応する直接マルチモーダル処理の代案を説明します。

**シナリオ：**出力は妥当なJSONですが、用紙の内容に矛盾します。**証拠：**スキーマ検証と出典検証を分けた結果、曖昧さのレビュー規則、テキストによるアクセシビリティの代替を示します。[Content Understanding](https://learn.microsoft.com/en-us/azure/ai-services/content-understanding/overview)で文書、画像、音声、動画をどう扱えるか含めます。信頼度を証拠の代わりにしてはいけません。

<a id="ai-901-unit-5"></a>

## 5. ツールを制限した単一エージェントを評価する

指示、モデル選択、呼び出し元に限定した検索を持ち、変更ツールを持たないノート検索エージェントを設計します。検索ツールの要求と結果、クライアントによるエージェントの識別と会話コンテキストの維持を定義します。裏付けのある回答、証拠不足、文書拒否、インジェクション、矛盾する期限、ツールのタイムアウトという最低六行の失敗表を作ります。各行に二つの競合する合成回答を書く前に、期待結果を追加します。

**最終証拠：**契約、プロンプト、アクセス一覧、クライアント案、抽出確認、採点した表を提出します。事実の裏付け、引用、差し控えと拒否、プライバシー、スキーマ、ツール権限を別々に採点します。プロンプトの修正一つとそのトレードオフを説明します。残る実地作業として、モデルのデプロイとポータル操作、実際のSDKチャットクライアント、ポータルで試す単一エージェントとそのクライアントを列挙します。オフライン採点はその準備です。
