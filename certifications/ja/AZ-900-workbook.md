# AZ-900 · 共通の発展ワークブック

八言語で目標、ケース、提出物を対応させています。同等性は語数ではなく学習単位と検証する証拠で確認します。以前のガイドも補足説明として残します。

<a id="az-900-unit-1"></a>

## 1. 責任を分ける

同じ要求に対し VM、管理された基盤、契約済みソフトウェアを比較します。OS、依存先、データ、アクセス、復旧の担当を列挙します。責任が完全になくなる選択肢はなく、必要な制御と運用能力が判断基準です。

**ケース：**ライブラリがシステムドライバーを要求します。適合しなくなる案と理由は何でしょう。**証拠：**責任分担表と、具体的要件で却下した代案。

<a id="az-900-unit-2"></a>

## 2. 可用性と境界

プロセス、インスタンス、ゾーン、リージョン障害を分けます。複数台でも依存先は共有され得ます。要求の移動時にセッションと文書がどうなるか説明します。部品の SLA はアプリ全体の可用性ではありません。

**ケース：**四つの API が復旧未定義の単一 DB に依存。**証拠：**全経路、弱い依存先、確認試験。

<a id="az-900-unit-3"></a>

## 3. データと接続を選ぶ

オブジェクト、関係メタデータ、共有ファイルを分け、読み書き、認可、復旧を定義します。公開は匿名と同じではなく、私設 DNS は権限を与えません。

**ケース：**教員は文書を開け、別利用者は403。**証拠：**ネットワーク、ID、認可の別仮説と、それぞれを裏付ける観測。

<a id="az-900-unit-4"></a>

## 4. 統制と見積もり

RBAC は操作、Policy は条件、タグは分類です。予算は全費用を止める仕組みではありません。容量、処理、転送、ログ、コピーを明示した仮定で見積もります。

**ケース：**許可地域だけに配置し学部別に費用を集計。**証拠：**方針、最小ロール、未確認料金を使わない費用単位表。

<a id="az-900-unit-5"></a>

## 5. 説明し検証する

配置、機能、復旧を区別します。リソース作成はダウンロードの成功を、コピー作成は迅速な復元を証明しません。CPU に加え業務信号を使います。

**提出：**図、五つの判断理由、耐えられる障害、残る責任、清掃計画。要件を変えて再回答します。答えが常に同じなら判断過程を見直します。
