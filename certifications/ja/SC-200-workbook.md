# SC-200 · 判断と証拠のワークブック

[ガイド](SC-200.md) · [10ケース](SC-200-cases.md) · [目次](README.md)

架空の大学ノートアプリを題材とする独自の五単元です。架空の記録とIDでオフライン作業します。期待結果と演習で与えられた観察を分けて明記します。テナントへのアクセス、クラウドへのデプロイ、実クエリ、メッセージ送信、封じ込めは必要なく、実行したとも主張しません。

<a id="sc-200-unit-1"></a>

## 1. 収集とアクセスの境界を図示する

Microsoft 365、Azureアプリ、オンプレミスサーバー、学内ファイアウォールを描きます。適切な箇所にDefender XDRの調査、またはSentinelの収集と分析を割り当てます。ソースごとにオンボード、コネクターの前提、期待テーブルと時刻列、安定したID、遅延、保持期間、責任者を定めます。閲覧、インシデント管理、ルール作成、自動化の権限を分離します。

**シナリオ：**ファイアウォールのコネクターは接続済みに見えますが、必要なイベントがありません。**証拠：**四ソースの範囲表、収集の健全性への質問、期待スキーマの合成イベント一つを示します。**成果物：**分析者が何を結論できるか説明する図と不足一覧です。個人情報とエクスポートの扱いも定め、本物の学生情報は収集しません。

<a id="sc-200-unit-2"></a>

## 2. 説明可能なインシデント時系列を作る

メール、ID、エンドポイント、アプリ、クラウドワークロードにまたがる六つの記録を作ります。各記録にUTCのイベント時刻、取り込み時刻、ソースID、エンティティID、観察を付けます。学内IPの共有だけで関係が証明されるとせず、関連アラートを仮のインシデントにまとめます。既知の範囲、疑う範囲、利用できないテレメトリを分けます。

**シナリオ：**疑わしいメッセージの後に、非公開文書へのアクセスらしい記録があります。**証拠：**時系列、エンティティ図、競合する説明、追加で求める記録一つです。**成果物：**担当者、優先度の理由、封じ込め案、承認要件、サービス影響、復旧条件を含むトリアージメモです。提案操作はすべて未実行とし、確認の予測を観測済み対応と呼びません。

<a id="sc-200-unit-3"></a>

## 3. 件数を信じる前にクエリ結果を説明する

ガイドの固定した合成KQL集合を読みます。半開のUTC期間、Deniedフィルター、重複除去、集約の各段階で行を追います。`student-a`の期待結果が二イベントとなる理由を説明します。同アカウントに二行ある別の架空テーブルを加え、明示的なinner結合の組を描きます。既定の`innerunique`による左側の重複除去と比較します。

**シナリオ：**報告が結合行を別々の攻撃と誤認しています。**証拠：**中間件数、結合キー、IDの仮定、境界時刻の例です。**成果物：**期待出力と制約を含む修正解釈です。クエリ実行を主張しません。任意のローカル計算も、テナントでの観察とは区別します。

<a id="sc-200-unit-4"></a>

## 4. ハンティング仮説を調整レビューにつなげる

疑わしいメッセージの受信と異常な非公開ファイルアクセスを結ぶ仮説を書きます。対象集団、UTC期間、必要なソース、代替説明を定めます。良性四例と懸念あり四例の合成データにラベルを付けます。検出と狭い例外を提案し、どれが警告され、見逃され、追加文脈を要するか示します。ASIMが対応ソースを正規化する方法と、パーサーの対応確認が必要な箇所を説明します。

**シナリオ：**承認済みインポートが不正利用に似ています。**証拠：**版管理した判断表、ソースの穴、誤検出と見逃しの分析、パーサー対応の確認です。**成果物：**調整の提言です。ハンティングが空でアラートが減っても、侵害なしや全範囲の可視性は証明できません。

<a id="sc-200-unit-5"></a>

## 5. 支援付き対応ワークフローをレビューする

情報補強のプレイブックを起動し、影響のある封じ込め前に承認を求める自動化ルールを描きます。操作者、Sentinelの呼び出し許可、ワークフローID、後続操作の範囲を分けます。重複トリガーとタイムアウトを模擬し、チケット重複や不要な再制限を防ぐIDと状態確認を記録します。責任者と復旧条件も含めます。

**シナリオ：**AI要約がアプリログなしでクラウドアラートと学生のダウンロードを結び付けています。**証拠：**主張と出典の対応表、修正結論、承認境界、再試行の期待動作です。**成果物：**レビュー済みの机上手順書です。Copilotの提案を、与えられた記録とクエリの意味で検証します。通知、承認要求、実際の対応は一切送りません。
