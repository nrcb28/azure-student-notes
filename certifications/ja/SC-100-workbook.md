# SC-100 · セキュリティアーキテクチャのワークブック

[ガイド](SC-100.md) · [10ケース](SC-100-cases.md) · [目次](README.md) · [Español](../es/SC-100-workbook.md)

架空の大学ノートサービスのための、独自のオフライン5単元です。架空の資産、ID、インシデント、証拠を使い、設計案と机上演習の結果を作ります。テナント変更、攻撃実行、リソース展開、ライブテレメトリ接続はしません。クラウド実行や対策の有効性を主張しません。

<a id="sc-100-unit-1"></a>

## 1. 重要度と対策範囲を確定する

**シナリオ：** 公開ノートだけだったアプリに、大学が未公開の試験解答を追加します。重要業務、データ所有者、想定脅威、業務影響を特定します。MCRAの機能対応、MCSBの対策要件、CAFのプラットフォーム責任、Well-Architectedのワークロードレビューを区別します。完全な台帳を作り上げず、前提を明示します。

**証拠：** 仮想資産図、優先順位付きリスク3件、現在の対策境界、不足情報。Azure Policyの結果だけで評価できない要件を一つ含めます。

**成果物：** 要件、対策、範囲、所有者、証拠、欠落、受け入れ基準を含む対応表。二案を比較し、残余リスクを受け入れる権限者を示す短いADRを加えます。

<a id="sc-100-unit-2"></a>

## 2. ID、ネットワーク、特権の境界を定める

**シナリオ：** 学内利用者、客員教員、管理者、デプロイパイプライン、AIエージェントが、サービスの異なる部分へアクセスします。学内とクラウドをまたぐID、アプリ、ネットワーク、管理の境界を描きます。最小権限、特権有効化、復旧アクセス、資格情報やフェデレーションの所有者を指定します。提案するエージェント制御の機能・ライセンス前提を確認します。

**証拠：** 期待する許可・拒否6件、プライベートDNS依存関係、公開アクセスの前提、到達可能なネットワークでも認可が維持される説明。

**成果物：** 信頼境界図と、所有者、範囲、ライフサイクル、ログ、障害動作を含むアクセス表。拒否されるエージェント操作と復旧管理者経路を含めます。IDと要求はすべて架空にします。

<a id="sc-100-unit-3"></a>

## 3. 検知を認可された対応へつなぐ

**シナリオ：** 不審な学内ID活動と異常な文書ダウンロードが同時に起きます。ID、端末、アプリ、クラウド、SaaSに必要なSOC能力を定めます。優先脅威経路2件を、関連するMITRE ATT&CK技法、期待テレメトリ、相関、初動評価、封じ込めへ対応付けます。完全な可視性を仮定せず、SentinelとDefender XDRの責任を説明します。

**証拠：** イベントソース、取り込み遅延、保持の前提、欠落信号、競合する説明を示す合成タイムライン。誰がIDを無効化し、試験サーバーを停止できるかを特定します。

**成果物：** 検知範囲表と、エスカレーション、承認、巻き戻し、証拠保全を含む対応権限表。すべて提案であると明記し、運用前に必要な受け入れ証拠を示します。

<a id="sc-100-unit-4"></a>

## 4. データとソフトウェア・AIのライフサイクルを守る

**シナリオ：** 新AIアシスタントが科目文書を検索し、ビルドパイプラインがそのAPIを展開します。情報を分類し、ラベル、暗号化、DLP、保持、アプリのアクセス境界を対応付けます。未対応箇所も記します。依存関係、ビルドID、成果物昇格、文書プロンプトインジェクション、ツールアクセスを脅威モデリングします。

**証拠：** 合成した正常検索、信頼しない指示を持つ文書、架空の未承認ビルドを各一つ。攻撃手順を生成したりテストを実行したりせず、期待する検索・ツールの拒否を記録します。

**成果物：** 所有者、範囲、来歴、権限、承認、受け入れ証拠を示すデータ対策表とライフサイクルレビュー。検知、暗号化、ベンチマーク対応が、それぞれ別の評価すべきリスクを残す理由を説明します。

<a id="sc-100-unit-5"></a>

## 5. 復旧を机上演習し、計画の順序を決める

**シナリオ：** ランサムウェアが主文書ストアと特権アカウントに影響します。演習要件をアプリRTO 2時間、RPO 15分とします。ID、管理面アクセス、DNS、キー、構成、メタデータ、ファイル、デプロイの依存関係を追います。保護された復旧点とレプリケーションを比較し、破損とバックアップ管理の侵害を考慮します。

**証拠：** 机上の復元順序、仮定の復旧時刻、整合性検査、ファイルが戻っても認可された読み取りを妨げる依存関係。測定値は仮定と記します。

**成果物：** 復旧受け入れ計画と、1学期分の予算内の3段階ロードマップ。所有者、工数見積もり、前提条件、巻き戻し基準、期限付き例外、残余リスクの業務承認を含めます。実際の復元や復旧目標は検証していません。
