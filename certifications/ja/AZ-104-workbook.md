# AZ-104 · 共通の発展ワークブック

[←](README.md) · [共通学習コア](../../ja/16-common-core.md) · [発展演習](../../ja/17-advanced-labs.md)

八言語で目標、ケース、提出物を対応させています。同等性は語数ではなく学習単位と検証する証拠で確認します。以前のガイドも補足説明として残します。

<a id="az-104-unit-1"></a>

## 1. 有効なアクセスを追う

ID、テナント、サブスクリプション、リソース、操作、範囲を記録します。グループ、直接と継承、条件、反映を調べます。管理面とデータ面を分け、ロール割り当て自体の権限も確認します。

**ケース：**Storage は作れるが Blob 一覧は不可。**証拠：**必要権限と同じ ID による最小検査。Owner の一括付与や仮説のないネット変更はしません。

<a id="az-104-unit-2"></a>

## 2. データ保護と復元

対象、コンテナー、アカウントごとの保護を選び、事故前の設定を記録します。Versioning では特定版の選択や昇格が必要な場合があり、全構成共通の手順とはしません。

**ケース：**演習ファイルを同一内容で復元。**証拠：**事前設定、前後の hash、権限、清掃後も保持されるデータ。

<a id="az-104-unit-3"></a>

## 3. 変更前に構成を読む

パラメーター、リソース、依存、出力、差分を読みます。コンパイル、検証、what-if、適用を分けます。Export は修正が必要な場合があり、クォータ、地域、方針でも失敗します。

**ケース：**what-if でモジュール未解析。**証拠：**診断、未確認範囲、適用前の解決判断。VM 変更ではディスク、ネット、設定も調べます。

<a id="az-104-unit-4"></a>

## 4. 全経路を診断する

DNS、IP、経路、NSG、ゲスト firewall、待受、認可を追います。複数の状態付きフィルターが働き得ます。Frontend、backend、規則、probe を確認し、App Service の受信と送信統合を分けます。

**ケース：**probe 正常で実要求失敗。**証拠：**各ポート、応答、規則、検証可能な仮説。Probe は機能の正しさを証明しません。

<a id="az-104-unit-5"></a>

## 5. 証拠で運用する

指標、ログ、警告、対処、担当を定義します。Query の前に収集元、関連、出力先を確認します。ID、DNS、依存先を含むアプリ復旧を測ります。

**提出：**Storage とロール検査、期待と観測、復旧 runbook。ローカル検査と Azure 試験を分け、削除または残存保持を確認します。
