# AI-103 · 上級開発者ワークブック

[ガイド](AI-103.md) · [10ケース](AI-103-cases.md) · [目次](README.md)

共通の5単元で、架空の大学ノートとオフラインの要求・応答フィクスチャを使います。候補出力は**合成**、期待動作は**予測**と記します。クラウドリソース、資格情報、実在学生記録、サービス実測は不要です。選択した実装スキルを学ぶ演習であり、全範囲を主張しません。確認日は**2026年11月1日**、[目標の有効開始は2026年4月16日](https://learn.microsoft.com/en-us/credentials/certifications/resources/study-guides/ai-103)です。

<a id="ai-103-unit-1"></a>

## 1. クライアント契約とデプロイ判断を固定する

**シナリオ：** 試験期のピーク時に、Pythonバックエンドから根拠付き回答を返します。ID文脈、要求ID、科目、結果、回答、引用、エラー種別を持つ要求・応答例を定義します。不正JSON、アクセス拒否、タイムアウト、部分出力を含めます。現行の[SDK指針](https://learn.microsoft.com/en-us/azure/foundry/how-to/develop/sdk-overview)で、リソース・プロジェクト、接続先型、デプロイ名、API世代、パッケージ版、資格情報方式の互換性マニフェストを作ります。

**証拠：** 仮想候補二つを品質、対応機能、容量、遅延、資源量で比較し、不明点は後の確認対象と記します。**成果物：** 型付き契約案、失敗フィクスチャ4件、架空の上限・価格を使わない根拠ある展開判断。

<a id="ai-103-unit-2"></a>

## 2. 権限失効まで含む検索を設計する

**シナリオ：** 二人がノートを共有し、その後一人の権限が失効します。提案するチャンク境界で条件文が分断される課題も含め、6抜粋を作ります。文書・チャンクID、版、出典位置、ACLメタデータ、インデックス・埋め込み版を定義します。キーワード、ベクトル、ハイブリッドの検索予測を比べます。認証、権限フィルター、検索、キャッシュ参照、モデル文脈を実際の順序で描きます。

**証拠：** インデックス伝播、キャッシュ、会話メモリを含む失効前後のアクセス表、裏付けのない引用一つ、証拠不足回答一つ。**成果物：** 権限鮮度方針、無効化規則、回帰例4件を持つ検索設計。[Searchアクセス方式](https://learn.microsoft.com/en-us/azure/search/search-document-level-access-overview)が実装選択へ与える影響を説明します。

<a id="ai-103-unit-3"></a>

## 3. 結果が不確かな承認済みツールを追跡する

**シナリオ：** エージェントが許可文書一つを学習グループと共有する提案をします。ツールスキーマ、呼び出し元範囲、正確な承認内容、操作キー、状態ストア、時間予算、会話所有者を定義します。検証→認可→承認→実行→照合→報告の**擬似コード**を描きます。アプリ設計であり、実行可能SDKコードではありません。同じ権限を保つ計画・検索エージェント間の引き継ぎも加えます。

**証拠：** 拒否、成功、重複配信、承認期限切れ、バックエンド成功後の応答消失のトレース。**成果物：** 状態遷移表と機密を除いたトレースで、再試行が共有を重複しない理由を示します。現行の[関数呼び出し境界](https://learn.microsoft.com/en-us/azure/foundry/agents/how-to/tools/function-calling)と結び付けます。

<a id="ai-103-unit-4"></a>

## 4. マルチモーダルなフィールドと意味を検証する

**シナリオ：** 課題用紙に下書きと最終期限があり、グラフの軸は読めず、音声質問は「mutex」を含みます。テキスト、音声、視覚理解、媒体生成、抽出に別の契約を定義します。詳細説明、型、null処理、出典参照を持つContent Understandingフィールドスキーマを書きます。期限逆転、架空単位、専門語の聞き誤りという合成誤出力を作ります。

**証拠：** スキーマ、出典、意味、アクセシビリティの個別検査。高信頼度の誤フィールドとテキスト訂正を含めます。**成果物：** 注釈付きフィクスチャ5件とラベル付き例で調整したレビュー方針。[アナライザー設計](https://learn.microsoft.com/en-us/azure/ai-services/content-understanding/concepts/best-practices)と[文書グラウンディングの対応](https://learn.microsoft.com/en-us/azure/ai-services/content-understanding/document/analyzer-improvement)を確認し、モダリティ・APIの制限を明示します。

<a id="ai-103-unit-5"></a>

## 5. 評価してロールバックを予行する

**シナリオ：** 候補リリースでプロンプト、ツールスキーマ、埋め込みモデルを変えます。根拠付き回答、出典欠落、権限失効、インジェクション、誤引用、曖昧な期限、ツールタイムアウト、重複操作の固定8例を採点します。検索品質、主張の裏付け、安全性、権限遵守、遅延予測を分けます。限定した段階展開と回復を起動する指標を述べます。

**証拠：** 比較表、互換性のあるリリースマニフェスト、機密を除くテレメトリスキーマ、クライアント・インデックス・プロンプト・ツールを一緒に戻す手順。**成果物：** レビュー可能なリリース一式と、認可済みラボでなお必要な測定一覧。[評価指針](https://learn.microsoft.com/en-us/azure/foundry/how-to/develop/cloud-evaluation)に沿い、オフライン予測と観測した展開証拠を区別し、合成スコアをAzure結果として報告しません。
