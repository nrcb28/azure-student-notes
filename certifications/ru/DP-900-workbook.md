# DP-900 · Общая практическая тетрадь

[Руководство](DP-900.md) · [Десять случаев](DP-900-cases.md) · [Содержание](README.md)

Пять соответствующих модулей на восьми языках. Используй синтетические данные, отдельно записывай предположения и наблюдения. Упражнения не развёртывают Azure и не доказывают полного покрытия экзамена.

<a id="dp-900-unit-1"></a>

## 1. Описать данные до выбора хранилища

Перечисли PDF, строку записи на курс, JSON с необязательными метаданными и событие скачивания. Для каждого опиши структуру, ID, производителя, потребителя, хранение и чувствительные поля. Затем назови важную операцию: получить файл, записать студента или агрегировать события. Различай выбор формата и требование нагрузки.

**Ситуация:** предлагают одну базу, потому что все четыре набора принадлежат одному приложению. **Доказательства:** матрица из четырёх строк, отклонённый вариант для каждой и новое требование, при котором выбор изменится. Не выдумывай ограничения служб и не считай, что любому JSON нужен Cosmos DB.

<a id="dp-900-unit-2"></a>

## 2. Сделать реляционную целостность видимой

Нарисуй Students, Courses и Enrolments со стабильными ID. Создай шесть учебных строк, объясни первичные ключи, ссылки и правило против повторной записи на курс. Предскажи результат соединения. Переименуй курс и сравни действия с моделью, где название скопировано во все записи. Цель — показать конкретную аномалию обновления, а не повторить лозунг нормализации.

**Ситуация:** студент записан на несуществующий курс. **Доказательства:** правило отклонения или обнаружения, пример неверной строки и ожидаемый результат. При локальном SQL-примере назови движок: поведение SQLite не является проверкой Azure SQL.

<a id="dp-900-unit-3"></a>

## 3. Выбрать ответственного за эксплуатацию базы

Сравни Azure SQL Database, Managed Instance и SQL Server на VM для новой системы и миграции. Перечисли совместимость, сеть, идентичности, обслуживание и ожидания восстановления. Добавь вариант с открытым движком, если его требует приложение. Отличай обоснованный выбор от утверждения, что один продукт всегда лучше.

**Ситуация:** среди миграционных зависимостей есть компонент с доступом к гостевой ОС. **Доказательства:** вопросы совместимости, таблица обязанностей и план проверки концепции с критериями успеха. Развёртывание не нужно; отметь предположения, которые ещё надо проверить до принятия цели.

<a id="dp-900-unit-4"></a>

## 4. Сверить небольшой конвейер

Создай шесть событий скачивания, включая повторный ID и запись без курса. Определи допустимый ввод, уникальное событие и условие завершения. Нарисуй ETL и ELT с точками проверки и хранения ошибок. Объясни, когда пакет укладывается в задержку, а когда оправдан поток.

**Ситуация:** итог панели отличается от числа строк источника. **Доказательства:** исходное число, дубликаты, отклонённые и принятые записи с воспроизводимым объяснением. Назначь владельца и действия при сбое. Успешный статус конвейера не доказывает правильности бизнес-итогов.

<a id="dp-900-unit-5"></a>

## 5. Определить заслуживающий доверия показатель

Выбери детализацию, например одно завершённое скачивание, и факт с контекстом курса и даты. Укажи часовой пояс, обработку опозданий и свежесть. Объясни, что хранит, преобразует, создаёт семантическую модель и показывает отчёт. Сравни озеро, хранилище и lakehouse по необходимой работе, а не названию.

**Итог:** сдай матрицу хранения, реляционную схему, сверку конвейера и макет месячного отчёта с определением показателя. Объясни роли Fabric, Synapse и Power BI. Назови открытый вопрос для официального руководства: хороший макет не доказывает работу облака или готовность к экзамену.
