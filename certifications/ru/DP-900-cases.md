# DP-900 · 10 случаев с разбором

[Руководство](DP-900.md) · [Тетрадь](DP-900-workbook.md) · [Содержание](README.md)

Авторские учебные ситуации, не реальные экзаменационные вопросы. Сначала назови требование, отклони альтернативу и укажи нужные доказательства. Выполнение в облаке не заявляется.

## 1. Приложение хранит PDF и доступные для поиска сведения о владельцах. Обязательно помещать всё в одну SQL-таблицу?

<details>
<summary>Разбор</summary>

Нет. Один вариант хранит PDF-объекты в Blob Storage, а владельцев и связи с курсами — в базе. Важно объяснить границу доступа и согласованности: файл мог загрузиться, а обновление метаданных — завершиться ошибкой. Нужен восстанавливаемый процесс и поиск файлов без соответствующих записей. Хранить всё в базе тоже можно при обоснованных требованиях, но предположение «любые данные должны быть SQL-строкой» мало помогает при выборе.

</details>

## 2. JSON-файл содержит необязательные вложенные атрибуты. Отсутствие полей делает его неструктурированным?

<details>
<summary>Разбор</summary>

JSON может представлять полуструктурированные данные: ключи и вложенность сохраняют организацию, даже когда записи различаются. Пропуски не отменяют структуру. Отдели представление от качества и выбора хранилища. Уточни, допустимо ли отсутствие поля, означает ли неизвестное значение или ошибку загрузки; опиши реакцию потребителя. Документная база может подойти способу доступа, но наличие JSON само по себе не решает архитектурный вопрос.

</details>

## 3. В каждой записи на курс повторяются название курса и преподаватель. Какую ошибку предотвратит нормализация?

<details>
<summary>Разбор</summary>

При переименовании курса одни строки могут обновиться, а другие сохранить старое название. Запись Courses со стабильным ключом и ссылки из Enrolments уменьшают такую аномалию. Объясни ограничения и соединения для получения результата. Дублирование не запрещено повсюду: аналитический снимок может намеренно сохранять историческое описание. Нужно понимать, обсуждается актуальная транзакционная информация или историческая модель отчётности.

</details>

## 4. Отчётный запрос замедляет запись студентов. Перенос диаграммы в Power BI автоматически уберёт нагрузку на базу?

<details>
<summary>Разбор</summary>

Нет. Всё зависит от получения и обновления данных модели. Отчёт всё ещё может обращаться к операционной базе или дорого её читать при обновлении. Уточни свежесть, запросы и ёмкость источника. Подготовленная аналитическая копия способна отделить часть работы, но добавляет задержку и обязанности конвейера. Измерь нагрузку источника и определи «актуальность», не предполагая, что смена визуализации меняет способ доступа.

</details>

## 5. Существующему приложению SQL Server нужны компоненты ОС. Azure SQL Database всегда будет прямой заменой?

<details>
<summary>Разбор</summary>

Нет. Сначала составь список компонентов и зависимостей. У Azure SQL Database, Managed Instance и SQL Server на VM разные границы управления и совместимости. VM даёт доступ к ОС, но требует больше обслуживания. Managed Instance может покрыть часть требований экземпляра, не удовлетворяя всем внешним зависимостям. Нужны список совместимости и план миграционного теста: знакомый движок ещё не доказывает, что всё приложение запустится без изменений.

</details>

## 6. Студент считает, что Azure Table Storage обеспечивает внешние ключи, потому что в названии есть Table. Что исправить в проекте?

<details>
<summary>Разбор</summary>

Table Storage — нереляционное хранилище сущностей, а не управляемая реляционная SQL-служба. Из названия нельзя выводить поддержку соединений и внешних ключей. Определи реальные чтения, изменения, связи и требования согласованности, затем сравни модель сущностей с реляционной. Полезное доказательство — пример получения курса по записи студента и предотвращения или обнаружения неверных ссылок. Название продукта подсказывает, что проверить, но не заменяет список возможностей.

</details>

## 7. Ночная обработка успевает к утреннему отчёту. Стоит заменить её потоковой ради современного названия?

<details>
<summary>Разбор</summary>

Начни с допустимой бизнес-задержки. Если надёжный ночной пакет вовремя даёт нужный результат, потоковая обработка может добавить эксплуатационную работу без пользы для решений пользователей. Если сотрудники должны реагировать на перегрузку за минуты, оцени путь с меньшей задержкой именно для этого требования. В обоих случаях нужны дубликаты, неполный ввод и повторы. Сравнивай свежесть всего пути и восстановление после сбоя, а не частоту работы одного компонента.

</details>

## 8. Сырые данные загружаются в хранилище и очищаются там. Это ETL? Проверки больше не нужны?

<details>
<summary>Разбор</summary>

Такой порядок — ELT: сначала загрузка, затем преобразование средствами цели. В ETL преобразование предшествует загрузке в нужное назначение. Ни один подход не отменяет контрактов и проверок. Определи место для ошибочных записей, повторяемость преобразований и сверку принятых итогов с источником. Контролируй доступ к ограниченным сырым данным, даже если аналитик видит только чистую модель. Удобный интерфейс запросов не доказывает безопасность или правильность записей.

</details>

## 9. Панель считает события скачивания, но повторы создают одинаковые ID. COUNT(*) обязательно равен числу завершённых скачиваний?

<details>
<summary>Разбор</summary>

Только если по определению каждая учитываемая строка — одно завершённое скачивание. Повторные доставки завышают COUNT(*). Задай бизнес-событие, стабильный идентификатор, условие завершения и интервал отчёта, затем убери дубли или агрегируй по этому определению. Сохрани счётчик отклонённых и повторных событий, чтобы объяснить изменение. Проверь небольшой набор с повторным ID и незавершённым скачиванием. Правдоподобная диаграмма ещё не доказывает соответствие нужному вопросу.

</details>

## 10. Шесть записей курсов помещаются в документную модель. Значит, Cosmos DB — единственное разумное хранилище?

<details>
<summary>Разбор</summary>

Нет. Шесть записей сохранят многие службы; пример доказывает только возможность представления. Сравни будущие запросы, связи, обновления, согласованность, эксплуатацию и навыки команды. Реляционная база может быть проще при важных ограничениях и связанных сущностях; документная — при других обращениях. Назови основание своего выбора и условие его пересмотра. Подготовка по основам должна учить рассуждению, а не привязывать продукт к любому JSON-подобному примеру.

</details>
