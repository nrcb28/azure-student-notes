# DP-300 · Общая операционная тетрадь

[Руководство](DP-300.md) · [Десять случаев](DP-300-cases.md) · [Содержание](README.md)

Пять модулей с соответствующими целями и доказательствами на восьми языках. При необходимости проектируй без Azure. Отделяй ожидаемое от реально наблюдаемого. Выполнение Azure и полное покрытие экзамена не заявляются.

<a id="dp-300-unit-1"></a>

## 1. Обосновать платформу и миграцию

Запиши требования приложения: функции базы, ОС, зависимости экземпляра, перерыв записи, ответственного за обслуживание и цели восстановления. Сравни SQL Database, Managed Instance и SQL Server на VM по этим условиям, не по знакомым названиям.

**Случай:** существующему заданию нужен инструмент ОС. **Доказательства:** необходимость зависимости, поддерживаемая цель или переработка и проверка совместимости. **Результат:** последовательность исходного переноса, заморозки записи, проверки, переключения, ответственного за откат и обработки новых записей после перехода. Завершённая копия — не приёмочный тест.

<a id="dp-300-unit-2"></a>

## 2. Разделить границы доступа и конфиденциальности

Нарисуй путь от идентичности приложения к разрешённой операции таблицы. Отметь DNS, сеть, аутентификацию, субъекта базы и объектные разрешения. Раздели приложение, развёртывание и аварийное администрирование. Укажи допустимые данные в запросах, логах, экспорте и копиях.

**Случай:** частное соединение работает, таблица недоступна. **Доказательства:** реальная идентичность, база, объект и отказ; расширение публичной сети не заменяет диагностики. **Результат:** минимальные разрешения и сравнение транспортного шифрования, TDE, Always Encrypted и masking для конкретного требования. Учти восстановление ключей и владельца.

<a id="dp-300-unit-3"></a>

## 3. Диагностировать измеренную регрессию

Придумай два сопоставимых периода запроса разрешений с длительностью, чтениями, CPU, параллельностью и ID плана. Свяжи изменение с доказательствами гипотезой и назови опровергающее наблюдение. Учти блокировки, длительность транзакции и историю Query Store. Ни нормальная метрика платформы, ни дорогой оператор плана отдельно не устанавливают причину.

**Случай:** индекс улучшил чтение и замедлил импорт. **Доказательства:** оба результата до и после при представительной нагрузке. **Результат:** один обратимый эксперимент, пороги приёмки, откат и ограничения выводов. Не предлагай shrinking или завершение всех сессий как регулярное обслуживание.

<a id="dp-300-unit-4"></a>

## 4. Сделать автоматизацию наблюдаемой и повторяемой

Классифицируй ночное задание по работе и платформе. Сравни SQL Agent для поддерживаемых SQL Server или Managed Instance с Elastic Jobs для T-SQL SQL Database. Укажи идентичность, цели, расписание, timeout, бюджет повторов и уведомление. Внешним зависимостям может понадобиться более общий оркестратор.

**Случай:** работа фиксирует результат и теряет ответ успеха. **Доказательства:** отсутствие дублей при повторе и способ оператора подтвердить завершение. **Результат:** таблица ожидающей, выполняемой, завершённой и неопределённой работы, план проверки синтетическими данными. Успешный вызов планировщика не равен проверенному бизнес-результату.

<a id="dp-300-unit-5"></a>

## 5. Восстановить данные и всю службу

Отдельно опиши случайное удаление и региональный отказ. Выбери сохранённые состояния и механизмы доступности по их задачам. Определи RPO и RTO приложения, нужные разрешения, ёмкость цели, endpoint, DNS, аутентификацию и зависимости. Репликация может перенести нежелательное подтверждённое изменение.

**Случай:** новый primary здоров, студенты не скачивают конспекты. **Доказательства:** функциональная проверка и хронометраж с переподключением. **Результат:** изолированная проверка восстановления, решение об авторитетной копии до failback и ответственный за очистку сохранённых данных. Предлагаемое время помечай ОЖИДАЕТСЯ до наблюдения в подходящей среде; обсуждение за столом не измеряет Azure recovery.
