## 2. Darstellung und Workload getrennt entscheiden

Strukturierte Daten folgen einer festgelegten Anordnung, etwa einer Einschreibungstabelle mit typisierten Spalten. Semistrukturierte Daten besitzen eine erkennbare Organisation, ohne überall identische Felder zu verlangen: Ein JSON-Dokument kann optionale Metadaten enthalten. Ein eingescanntes Arbeitsblatt gilt für die Inhaltssuche als unstrukturiert, auch wenn sein Dateiname einem Schema folgt.

CSV eignet sich für kleine tabellarische Austauschdateien, benötigt aber Vereinbarungen zu Zeichencodierung, Trennzeichen und fehlenden Werten. JSON bildet verschachtelte Strukturen ab. Parquet ist spaltenorientiert und häufig für analytische Scans geeignet. Ein Dateiformat liefert allein weder Berechtigungen noch Geschäftsregeln oder Datenqualität.

Transaktionale Arbeit umfasst oft viele kleine Operationen: einen Platz reservieren und die verbleibende Kapazität konsistent ändern. Analytische Arbeit fasst Vergangenheit zusammen, etwa Einschreibungen nach Kurs und Semester. Eine Datenbank kann an beidem beteiligt sein, doch aufwendige Berichte konkurrieren möglicherweise mit der laufenden Anwendung. Definiere die zulässige Aktualität, statt ohne Grund „Echtzeit“ zu verlangen.

## 3. Relationaler Entwurf macht Beziehungen sichtbar

Stell dir Students, Courses und Enrolments vor. Ein Primärschlüssel identifiziert eine Zeile. Ein Fremdschlüssel beschreibt eine Beziehung, sofern die Datenbank diese Bedingung durchsetzt. Enrolments verbindet Studierende mit Kursen, ohne den Kurstitel in jeden Studierendendatensatz zu kopieren. Normalisierung reduziert bestimmte Redundanzen und Änderungsanomalien. Daraus folgt nicht, dass jeder brauchbare Bericht ein möglichst stark zerlegtes Schema benötigt.

Eine Tabelle speichert Zeilen. Eine Sicht stellt eine gespeicherte Abfrage bereit und ist nicht zwingend eine getrennt gespeicherte Kopie. Ein Index unterstützt Zugriffspfade, kostet aber Speicher und zusätzlichen Aufwand beim Schreiben. Eine gespeicherte Prozedur bündelt Operationen auf Datenbankseite. Transaktionen helfen, zusammengehörige Änderungen unter den jeweiligen Nebenläufigkeits- und Isolationsregeln konsistent zu halten. Sie reparieren keine nie implementierte Geschäftsregel.

Lerne den Zweck von SELECT, INSERT, UPDATE, DELETE, CREATE und GRANT. Vor UPDATE oder DELETE würde ich die betroffenen Zeilen vorhersagen und die Bedingung an Beispieldaten prüfen. Eine technisch erfolgreiche Anweisung kann die falschen Datensätze verändern.

## 4. Das Betriebsmodell für Azure SQL wählen

Azure SQL Database ist ein verwalteter Datenbankdienst. Azure SQL Managed Instance bietet instanzbezogene Kompatibilität für viele bestehende SQL-Server-Anwendungen. SQL Server auf einer Azure-VM gewährt Betriebssystemzugriff und lässt mehr Verwaltungsarbeit beim Team. Ähnliche Abfragesyntax bedeutet keine identischen Bereitstellungs-, Kompatibilitäts- oder Wartungsgrenzen.

Für eine neue Mitschriften-App würde ich Funktionen, Verbindungen, Wiederherstellung, Betriebsaufwand und Lastprofil vergleichen. Bei einer Migration kommen zuerst die Abhängigkeiten ins Inventar: Instanzfunktionen und externe Komponenten können die Zielwahl verändern. „Verwaltet“ nimmt uns weder Zugriffskontrolle noch Schema, Anwendungsabfragen oder Wiederherstellungsanforderungen ab. Auch PostgreSQL und MySQL besitzen verwaltete Azure-Angebote. Zum vorhandenen Datenbankmotor zu passen kann wichtiger sein, als SQL-Server-Begriffe zu übernehmen. Prüfe das konkrete Produkt und die unterstützte Version; die Engines sind nicht beliebig austauschbar.

[Quelle: Azure-SQL-Auswahl](https://learn.microsoft.com/en-us/azure/azure-sql/azure-sql-iaas-vs-paas-what-is-overview).

## 5. Objekte, Freigaben und Entitäten haben unterschiedliche Aufgaben

Blob Storage speichert Objekte wie PDFs und Bilder. Azure Files stellt verwaltete Dateifreigaben für passende Dateizugriffe bereit. Table Storage speichert Entitäten in einem nichtrelationalen Modell und ist kein relationaler SQL-Tabellendienst. Ein verwalteter Datenträger ist wiederum eine andere Speicherabstraktion.

Für die App wäre ein plausibler Entwurf: Dateiinhalte in Blob, Eigentümermetadaten in einer Datenbank. Halte fest, wie beide Teile bei einem halb fehlgeschlagenen Upload konsistent bleiben. Getrennte Speicherung koordiniert keine Transaktion automatisch. Das Recht, ein Speicherkonto anzulegen, unterscheidet sich außerdem vom Recht, seine Blobs zu lesen. Ein Downloadtoken ist ein Zugangsmittel und gehört nicht in geteilte Notizen.

[Quelle: Speicherdienste](https://learn.microsoft.com/en-us/azure/storage/common/storage-introduction).

## 6. Verstehen, wann eine Dokumentdatenbank passt

Azure Cosmos DB unterstützt nichtrelationale Anwendungsszenarien über die jeweils unterstützten APIs und Datenmodelle. Ein Dokument kann flexible Kursmetadaten aufnehmen, ohne jedes optionale Attribut als eigene relationale Spalte zu führen. Das beweist nicht, dass jeder Workload dorthin gehört.

Beginne mit Lesezugriffen, Aktualisierungen, Beziehungen, Konsistenzanforderungen und betrieblichen Grenzen der Anwendung. Eine SQL-ähnliche Abfragesprache bedeutet allein weder relationales Verhalten noch beliebige relationale Joins. Für die Grundlagen solltest du Dokument, Schlüssel-Wert-Entität, Objekt und relationale Zeile vergleichen können. Detaillierte Anwendungsimplementierung und Leistungsoptimierung liegen außerhalb dieser Einheit.

[Quelle: Cosmos-DB-Überblick](https://learn.microsoft.com/en-us/azure/cosmos-db/overview).

## 7. Daten durch die Pipeline verfolgen

Stapelverarbeitung bearbeitet eine abgegrenzte Menge, etwa die Downloads von gestern. Streaming verarbeitet eintreffende Ereignisse mit begrenzter Verzögerung, muss aber weiterhin Duplikate, verspätete Ereignisse und Fehler behandeln. Ein sekündlich aktualisiertes Dashboard beweist nicht, dass jedes Quellereignis bereits eingetroffen ist.

ETL transformiert Daten vor dem Laden in das vorgesehene Ziel. ELT lädt zuerst und transformiert mit den Verarbeitungsmöglichkeiten des Ziels. Keines der Kürzel garantiert saubere Daten. Definiere Kennungen, Typen, den Umgang mit abgewiesenen Datensätzen und Abstimmungsprüfungen. Zähle Quellereignisse, angenommene und abgelehnte Ereignisse und erkläre Abweichungen. Orchestrierung koordiniert Schritte, Abhängigkeiten und den Wiederanlauf nach Fehlern; sie ist etwas anderes als die Transformation selbst.

[Quelle: ETL und ELT](https://learn.microsoft.com/en-us/azure/architecture/data-guide/relational-data/etl).

## 8. Gespeicherte Daten für Analysen nutzbar machen

Ein Data Lake kann unterschiedliche Daten zur späteren Verarbeitung aufnehmen. Ein Warehouse organisiert analytische Daten für konsistente Abfragen und Berichte; ein Lakehouse verbindet Ansätze. Ein Dateihaufen wird erst mit klaren Zuständigkeiten, Formaten, Qualitätsregeln und Auffindbarkeit nützlich. Im Sternschema hält eine Faktentabelle messbare Ereignisse fest; Dimensionstabellen liefern beschreibenden Kontext. Bestimme die Körnung vor der Summenbildung.

Azure Synapse Analytics bietet Analysefunktionen und Integrationsmöglichkeiten. Microsoft Fabric vereint mehrere Daten- und Analyseworkloads in einer SaaS-Plattform. Power BI unterstützt semantische Modelle, Berichte und Dashboards. Diese Aufgaben hängen zusammen, sind aber nicht austauschbar. Definiere eine Kennzahl wie abgeschlossene Downloads, ihre Zeitzone und Aktualisierungsgrenze, bevor du ein Diagramm baust. Sonst können zwei plausibel aussehende Berichte Verschiedenes zählen.

[Quelle: Fabric-Überblick](https://learn.microsoft.com/en-us/fabric/fundamentals/microsoft-fabric-overview).

## 9. Entwurfsübung und Nachweise

Zeichne ohne Cloudressourcen einen Entwurf für PDFs, Einschreibungen und monatliche Downloadberichte. Erstelle sechs synthetische Datensätze mit einem doppelten Ereignis und einer fehlenden Kurskennung. Wähle pro Datenmenge einen Speicher, lege die zulässige Berichtsverzögerung fest und beschreibe die Behandlung des Duplikats und des ungültigen Datensatzes. Schreibe eine Beispielabfrage oder erläutere ihr erwartetes Ergebnis auf Papier. Trenne Entwurfsannahmen von tatsächlich beobachteten Ausführungsergebnissen.

Eine DBA-Rolle konzentriert sich auf den Datenbankbetrieb, Data Engineering auf das Bewegen und Aufbereiten von Daten und Analyse auf Fragen, Modelle und Berichte.
